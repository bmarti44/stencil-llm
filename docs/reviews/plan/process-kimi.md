## Findings

1. **High — Review acceptance accepts unbounded scores and never checks the Verdict line.** Section 2b's gate checklist says acceptance is "verified by `tools/check_review_scores.py`" (PLAN.md:101), and "Finding identity and closure" says the checker "treats any unmarked high/critical finding as open and fails regardless of score" (PLAN.md:98). The checker's score regex is `^\*\*Score:\*\*\s*(\d{1,3})\s*/\s*100` (`tools/check_review_scores.py:18`) — `999 / 100` parses and passes any threshold — and nothing in either validator reads `**Verdict:**`, so a file bearing `**Verdict:** FAIL (<75)` with a high Score line is mechanically accepted. `review_round_tracking.py`'s score patterns are likewise unbounded (`-\s*Score:\s*\d+\s*/\s*100`). Separately, the closure regex accepts any first-line `(resolved ...)` string (`tools/check_review_scores.py:21-22`); sol#1 frames that as "forged closure," which I reframe: closure *substance* is deliberately delegated to reviewer concurrence ("only a subsequent reviewer round may mark a finding `(resolved ...)`", PLAN.md:98) and to orchestrator verification, so the checker cannot and need not adjudicate it — but the score range and Verdict consistency are purely mechanical and must be enforced at the sole mechanical gate. (Concur sol process#1, reframed.)

Because the audit trail's "amendment log discipline" and the retros' finding-count evidence (`tools/agent_metrics.py` parses these files) both read this history, a compliant-but-dishonest rewrite corrupts the metrics and the record while passing every mechanical gate. ## Recommendations

1. Harden `tools/check_review_scores.py` (lines 18–44): bound the score to 0–100; parse `**Verdict:**` and require consistency with `--min` (a FAIL verdict with a passing score rejects); require closure markers to match `(resolved|refuted) YYYY-MM-DD: ...` and, where feasible, require the closing action to reference the verifying round. Keep closure-substance verification in the concurrence protocol, per finding 1.
2. Make history truly append-only at `tools/review_round_tracking.py`: byte-compare prior round blocks (hash or verbatim containment), forbid severity/title/body rewrites except appended `(resolved/refuted ...)` markers, enforce unique strictly descending round numbers — or else amend PLAN.md:97 to say honestly what is enforced.
3. Author the missing governance artifacts before Phase 0's exit depends on them (PLAN.md:100, 109): `tools/codex-prompts/review-tradeoff.md`, `review-report.md`, a kimi retro rubric fragment, named topics (with fragments) for Phases 0–4 and 6, and a default threshold policy per topic.
4. Add checklist item (f) to PLAN.md:101: the phase's kimi cross-review is complete and every confirmed kimi high/critical is resolved or adjudicated before the gate commit; correct rule 9 (PLAN.md:81) to "all reviews *of record* are sol adversarial reviews."
5. Repair the state machine (PLAN.md:77, 391–395, 417, 487–501; README.md:47–58): either register `green-with-efficiency-miss` in rule 5, README, and Phase 6's precondition or delete it; make a persistent red G3.6 sanity result actually red or define one named non-red state; give D.4's wide-variant continuation a named entry state; add combined-failure rows.
6. Register a matrix resume contract: `scripts/run_matrix.py` skips cells whose `results/<run_id>/` carries a completion marker, refuses to `--force` over completed gate-feeding runs, and writes a per-cell status manifest the ledger write-ahead references (PLAN.md:333, 375–380).
7. Upgrade the ledger (PLAN.md:115–127): structured fields per finding 7 (work-unit id, lifecycle state, phase/gate, branch/HEAD, brief path+hash and allowed paths, model/effort, session/pid, run_id, cell status, retry count, blocked-by, open-finding inventory, exact next command); add triggers for per-cell completion and wrapper hard failures (exit 4/5/6) and tie-break events; move wrapper logs (including a real kimi log file) out of `/tmp` into a repo-local `logs/` (gitignored) directory; fix write-ahead placement to true newest-first.
8. Unify attempt budgets across rule 4 and Appendix D (PLAN.md:76, 487–499): one registered attempt count per branch (or per gate) with an explicit escalation/kill consequence, and reconcile item 1's "do not proceed until ... at their nulls" with the one-pass kill rule.
9. Contain coder runs like reviewer runs (`tools/run_codex_agent.sh`): pre-run baseline snapshot, brief-scoped diff allowlist, hard failure on excess scope, sandbox by default with the bypass opt-in and ledgered; and make the reviewer wrapper write-atomic for the canonical file (temp write + rename, retain a backup of the prior file on failure paths).
10. Make the tie-break executable (PLAN.md:106): a `review-tiebreak` prompt fragment, a canonical verdict artifact under `docs/reviews/`, an orchestrator verification step before execution, an operational definition of "round trip," and edit human touchpoint (1)'s text (PLAN.md:111) to match the override.
11. Enforce kimi anti-churn (PLAN.md:107; `tools/run_kimi_review.py`): include the anti-churn clause in the prompt for rounds ≥ 2, consider a fixed low temperature/nondiscovery wording, and register an orchestrator dedup rule for re-raised kimi claims.
12. Register plan-phase acceptance (ledger/PLAN.md): Phase 0 begins only when all plan topics are ≥ 90 with zero open high/critical findings and confirmed kimi findings are adjudicated, recorded as a ledger decision.
13. Extend the amendment-log schema (PLAN.md:7–15, 111): accepting review file/round/score, affected phase, pre-launch evidence, old/new values, activation commit; fix Appendix C's "last amended v1.4" to v1.6 (PLAN.md:471); state the `amendment` review threshold.
14. Couple README mechanically (PLAN.md:77; README.md:47–58): define `in progress`/`red`/`killed` transition triggers and Phase 5/7 row events; add evidence columns (gate commit SHA, review round/score, date); add a `make` check or pre-commit that cross-verifies the table against `git log` and review state.
15. Extend the Phase 6 freeze list (PLAN.md:419–429): aggregate GPU-hour budget, pilot, per-run timeout, checkpoint/resume policy, partial-matrix recovery, a pre-registered descope option if projections exceed 2x (the current rule's only outcome is "pause for the human"), and the explicit determinism scoping (named scale-repeatability contract versus toy bitwise).
16. Define rule 3's freeze moment for Phases 0–2 (PLAN.md:75): e.g., "the first `make gate-N` invocation," and either move G0/G1/G2 tolerances into Appendix C or state that prose pass-bars are covered by the same rule.

18. Quarantine rejected kimi candidates to `/tmp` and exclude them from `build_context` globs and `agent_metrics.py` inputs (`tools/run_kimi_review.py:171-176`; `tools/agent_metrics.py:126`).
