## Findings

1. **Critical — Task A's claimed chance rate is impossible for the registered `k=8` cells.** Task A says, "Rules are k fixed random permutations" ([PLAN.md:256](/home/bmarti44/stencil-llm/PLAN.md:256)), registers `k in {2, 8, 32}` ([PLAN.md:258](/home/bmarti44/stencil-llm/PLAN.md:258)), and then declares, "Chance = 1/16 = 6.25 percent" ([PLAN.md:259](/home/bmarti44/stencil-llm/PLAN.md:259)). A cue-blind model still observes operand `x`. Conditional on that operand and `k=8` equiprobable fixed rules, the answer has at most eight possible values, so its Bayes accuracy is at least `1/8 = 12.5%`; collisions among permutation outputs only raise it. Randomly sampled `k=32` rules are also not guaranteed to be exactly balanced over the 16 answers. Consequently the G3.1 demand `<= 8.25` ([PLAN.md:419](/home/bmarti44/stencil-llm/PLAN.md:419)) will reject a perfectly isolated baseline, and the statements that B0-local/B1 are "pinned at chance by construction" ([PLAN.md:46](/home/bmarti44/stencil-llm/PLAN.md:46)) and that "the normal model then fails by construction" ([PLAN.md:24](/home/bmarti44/stencil-llm/PLAN.md:24)) do not follow.

2. **Critical — The numerical method contradicts both the conservation claim and the Phase 2 tests.** H2 says, "M1 conserves exactly (IMEX)" ([PLAN.md:47](/home/bmarti44/stencil-llm/PLAN.md:47)), while the registered update is symplectic Euler ([PLAN.md:193](/home/bmarti44/stencil-llm/PLAN.md:193), [PLAN.md:196](/home/bmarti44/stencil-llm/PLAN.md:196), [PLAN.md:197](/home/bmarti44/stencil-llm/PLAN.md:197)). With `G=u=0`, this method preserves a modified quadratic, not the specified `H = z^2 + A y^2`. At `dt=1`, `y=1`, `z=0`, one step gives `H_1/H_0 = 1 - A + A^2`; for the registered minimum period 8, `A=(2π/8)^2≈0.617`, so the one-step relative change is about 23.6%, not below `1e-4`. The demand that this discrete trajectory match the continuous analytic solution over 1000 steps within `1e-4`, followed by physical-energy drift below `1e-4` over 10,000 steps and monotone damped energy ([PLAN.md:318](/home/bmarti44/stencil-llm/PLAN.md:318), [PLAN.md:319](/home/bmarti44/stencil-llm/PLAN.md:319)), is therefore not a valid gate for the registered first-order discretization. G2 cannot reliably become green, and the "exact conservation pole" label ([PLAN.md:235](/home/bmarti44/stencil-llm/PLAN.md:235)) is scientifically inaccurate as written.

3. **Critical — H4's bottleneck argument is information-theoretically false, leaving a false mechanistic positive that can pass every mandatory gate.** The plan claims, "Thirty-two arbitrary bindings cannot plausibly be routed through 16 scalar gates per position" ([PLAN.md:279](/home/bmarti44/stencil-llm/PLAN.md:279)). These are real-valued fp32 gates, not 16 bits, they exist at every position and layer, and the controller has 128-dimensional state while reading every token embedding ([PLAN.md:184](/home/bmarti44/stencil-llm/PLAN.md:184), [PLAN.md:186](/home/bmarti44/stencil-llm/PLAN.md:186), [PLAN.md:218](/home/bmarti44/stencil-llm/PLAN.md:218), [PLAN.md:225](/home/bmarti44/stencil-llm/PLAN.md:225)). At an answer prediction, even one scalar can encode the queried 4-bit value, while the state can encode all 32 bindings. Low MQAR accuracy therefore shows only failure to learn/use that code, not channel purity; nevertheless `<=11.25` is labeled a "clean control channel" ([PLAN.md:426](/home/bmarti44/stencil-llm/PLAN.md:426)). The conditional follow-up is only a linear probe at one position ([PLAN.md:357](/home/bmarti44/stencil-llm/PLAN.md:357)), which can miss a nonlinear or distributed code. A recurrent controller can compute `rule(cue, x)` directly, transmit the answer through gates, fail the harder MQAR cell, and still pass G3 and G4. Because H4 is record-only, even an observed side-channel does not block promotion. That defeats the claimed strict control/content separation.

4. **High — M1/M1b/B2 do not "differ only in energy handling," so H2 is structurally confounded.** The registered claim is, "Three matched controllers differ only in energy handling" ([PLAN.md:47](/home/bmarti44/stencil-llm/PLAN.md:47)). M1/M1b instead use two stacked second-order oscillator cells with a GLU between them ([PLAN.md:204](/home/bmarti44/stencil-llm/PLAN.md:204), [PLAN.md:205](/home/bmarti44/stencil-llm/PLAN.md:205)), whereas B2 is a first-order diagonal decay state with a different transition family ([PLAN.md:234](/home/bmarti44/stencil-llm/PLAN.md:234)). Global parameter matching then widens each variant's transformer `d_ff` ([PLAN.md:242](/home/bmarti44/stencil-llm/PLAN.md:242)), redistributing capacity between controller and trunk rather than matching controller capacity. Any M1/M1b/B2 ranking can reflect recurrence order, spectral basis, stacking, GLU, trainable-parameter allocation, or trunk width rather than dissipation.

5. **High — H2 is registered as an observation exercise, not a falsifiable hypothesis.** The hypothesis says, "The deliverable is the ordering and the tradeoff curves, pre-registered as a valid result in any direction" ([PLAN.md:47](/home/bmarti44/stencil-llm/PLAN.md:47)); G3.5 is explicitly "record-only, no kill" ([PLAN.md:345](/home/bmarti44/stencil-llm/PLAN.md:345)); and Phase 5 has "No pass/fail gate" ([PLAN.md:364](/home/bmarti44/stencil-llm/PLAN.md:364)). The stated prior `M1b >= M1 >= B2` is not paired with a defined aggregate metric, uncertainty rule, minimum effect, or confirm/refute criterion, and the sole G3 ordering cell does not operationalize the claimed aggregate or switching tradeoff. Any outcome can be narrated after the fact without a registered decision about H2.

6. **High — Autoregressive target alignment is unspecified, so the answer token can leak directly into its own prediction.** Task A's token sequence explicitly includes `[answer = rule_i(x)]` ([PLAN.md:253](/home/bmarti44/stencil-llm/PLAN.md:253)), while loss is merely described as "Cross-entropy at masked answer positions only" ([PLAN.md:283](/home/bmarti44/stencil-llm/PLAN.md:283)) and the proof differentiates an "answer-position logit" ([PLAN.md:324](/home/bmarti44/stencil-llm/PLAN.md:324)). The plan never specifies the one-token causal shift between input positions, logits, targets, and `loss_mask`. If implemented literally at the same index, a causal decoder sees the answer embedding and can copy it. This ambiguity also changes which position's control state/gates are tested and the exact cue-to-prediction distance in the `L*w` proof.

7. **High — The `L*w` graph argument is sound only under assumptions that the registered proof test does not fully verify.** The plan says the ceiling "is verified by an exact-zero-gradient test" ([PLAN.md:55](/home/bmarti44/stencil-llm/PLAN.md:55)) but specifies only one Task A sample and one answer logit ([PLAN.md:324](/home/bmarti44/stencil-llm/PLAN.md:324)). Standard featurewise pre-LN/final-LN, pointwise RoPE/readout, and B1's same-position gate do not expand reach; a true boolean or `-inf` mask makes excluded softmax weights exactly zero. But that conclusion depends on explicit mask semantics, window convention, target shift, tokenwise normalization/readout, and absence of any sequence-coupled operation. A single scalar derivative at initialization can be zero because the selected output/path is inactive, cancelled, detached, or hooked incorrectly even when another logit has a leak. The close-cue guard tests only B0-local ([PLAN.md:325](/home/bmarti44/stencil-llm/PLAN.md:325)). Targeting the position activation rather than the shared embedding-table row is correct, but it does not cure the test's output and configuration coverage gaps. The current test is evidence for one derivative, not the claimed architecture-wide proof.

8. **High — Appendix C is not evaluable as a clean preregistration because the sampling and aggregation protocol is incomplete.** The entire evaluation definition is "exact-match accuracy at answer positions, reported per grid cell as JSON" ([PLAN.md:281](/home/bmarti44/stencil-llm/PLAN.md:281), [PLAN.md:283](/home/bmarti44/stencil-llm/PLAN.md:283)). It does not freeze evaluation sample count, evaluation seeds, whether rules are shared between train/eval, final-versus-best checkpoint selection, or confidence intervals. G4 similarly names "the trained ... checkpoints" ([PLAN.md:352](/home/bmarti44/stencil-llm/PLAN.md:352)) but does not say whether each threshold is per seed, a mean, or pooled. Thus the `+2` and `+5` point bands have unknown false-decision rates, and checkpoint/seed aggregation remains researcher discretion. Appendix C also labels G6 "ppl regression" ([PLAN.md:428](/home/bmarti44/stencil-llm/PLAN.md:428)) while the gate itself uses validation LM loss ([PLAN.md:378](/home/bmarti44/stencil-llm/PLAN.md:378)); these are not the same relative metric.

9. **High — The kill/root-cause logic can rescue a dead hypothesis or kill a live one.** Appendix D pre-decides that if all recurrent variants are at chance, this is a "Pathway plumbing or optimization defect, not a mechanism result" ([PLAN.md:435](/home/bmarti44/stencil-llm/PLAN.md:435)) without a discriminator between an implementation defect and a genuine optimization/expressivity failure. Item 3 triggers if "M1b or B2 solves it" but then directs the project to designate M1b primary ([PLAN.md:436](/home/bmarti44/stencil-llm/PLAN.md:436)); that is incoherent when only B2 passes. There is no branch for M1 passing while required G3.2b fails. Item 4 authorizes a post-failure capacity selection up to 256 pairs ([PLAN.md:437](/home/bmarti44/stencil-llm/PLAN.md:437)) even though the registered mechanism uses 64 pairs ([PLAN.md:204](/home/bmarti44/stencil-llm/PLAN.md:204)), without saying that success belongs to a new hypothesis/model rather than rescuing the original. Finally, an H4 content-side-channel result is merely recorded ([PLAN.md:346](/home/bmarti44/stencil-llm/PLAN.md:346), [PLAN.md:348](/home/bmarti44/stencil-llm/PLAN.md:348)) although it falsifies a central claimed contribution. These gaps defeat the promise to stop after one objective pass through the tree ([PLAN.md:62](/home/bmarti44/stencil-llm/PLAN.md:62)).

10. **Medium — The H3 patch metric can count no-change cases as causal flips and does not isolate a rule state from answer content.** The test uses pairs "differing only in cue" and passes when the recipient "outputs the donor's rule >= 90 percent" after overwriting `c` at every position ([PLAN.md:355](/home/bmarti44/stencil-llm/PLAN.md:355)). Random permutations can give the same answer for donor and recipient rules on a given operand; those cases are not identifiable flips but can count as successes unless explicitly excluded. Patching the entire control trajectory after it has also read the operand permits transplantation of a directly computed answer, which is exactly the H4 alternative. The test lacks an unpatched-recipient control, a same-rule sham patch, and a boundary-state intervention that patches rule context before exposing the controller to a different recipient operand.

11. **Medium — G3.6 treats a materially altered MQAR cell as an implementation oracle.** The plan acknowledges a "documented deviation from Zoology's fixed datasets" and adapts the task to a 64-token vocabulary and infinite-data regime ([PLAN.md:270](/home/bmarti44/stencil-llm/PLAN.md:270)), yet says B0-full `>=95` "validates our MQAR implementation against known results" ([PLAN.md:278](/home/bmarti44/stencil-llm/PLAN.md:278)) and that any failure "must be fixed before proceeding" ([PLAN.md:346](/home/bmarti44/stencil-llm/PLAN.md:346)). With different data regime, model size, optimizer budget, and configuration, a red cell can be an optimization/capacity result rather than an implementation defect. The current rule invites unregistered changes under the label of a fix and can also kill a correctly implemented experiment.

12. **Medium — The threshold amendment rules conflict at the exact point preregistration matters.** Operating rule 3 says thresholds change only "before the phase's runs begin" ([PLAN.md:70](/home/bmarti44/stencil-llm/PLAN.md:70)), while Appendix C says, "Editing them after Phase 3 begins requires a human commit ... with a rationale line" ([PLAN.md:415](/home/bmarti44/stencil-llm/PLAN.md:415)). ## Recommendations

1. Replace Task A's independently random rules with a jointly balanced rule family, or compute and preregister the exact cue-blind Bayes accuracy `mean_x max_y p(y|x)` for each realized rule set and compare B0/B1 against that value. `k=8` cannot have a 1/16 null; update the claims and G3.1 together ([PLAN.md:256](/home/bmarti44/stencil-llm/PLAN.md:256), [PLAN.md:419](/home/bmarti44/stencil-llm/PLAN.md:419)).
2. Decide whether M1 means zero explicit damping, exact preservation of a modified discrete energy, or exact preservation of physical oscillator energy. Then choose a compatible integrator and test: compare a discrete implementation with its discrete closed form, or run a registered convergence study against the continuous solution; do not require symplectic Euler to conserve `z^2+A y^2` to `1e-4` ([PLAN.md:193](/home/bmarti44/stencil-llm/PLAN.md:193), [PLAN.md:318](/home/bmarti44/stencil-llm/PLAN.md:318)).
3. Remove the gate-count capacity claim. For a genuinely pure control path, architecturally restrict controller inputs to cue events (or impose and measure a real bandwidth constraint). At minimum, make H4 claim-limiting: content-side-channel evidence must retract the strict separation claim, and low task accuracy must not be called proof of purity ([PLAN.md:184](/home/bmarti44/stencil-llm/PLAN.md:184), [PLAN.md:426](/home/bmarti44/stencil-llm/PLAN.md:426)).
4. Test dissipation with one matched second-order controller topology: identical state dimension, stack, GLU, forcing/readout, trunk width, and optimizer, varying only registered `G` conditions (for example zero, fixed grid, and learned). Keep B2 as a separate architectural baseline, not a point on an otherwise controlled dissipation spectrum ([PLAN.md:47](/home/bmarti44/stencil-llm/PLAN.md:47), [PLAN.md:234](/home/bmarti44/stencil-llm/PLAN.md:234)).
5. Give H2 a primary scalar estimand and a decision rule before runs: named cells/curve summary, seed aggregation, uncertainty, minimum effect, and explicit supported/refuted/inconclusive outcomes. Preserve full curves as secondary descriptive results ([PLAN.md:345](/home/bmarti44/stencil-llm/PLAN.md:345), [PLAN.md:364](/home/bmarti44/stencil-llm/PLAN.md:364)).
6. Specify causal LM alignment with an explicit miniature example: which token positions enter the model, which logits predict which next tokens, how `loss_mask` is shifted, and whether cue distance is measured to the input position producing the answer logit ([PLAN.md:253](/home/bmarti44/stencil-llm/PLAN.md:253), [PLAN.md:283](/home/bmarti44/stencil-llm/PLAN.md:283)).
7. Turn the reachability claim into a structural proof obligation: define the window mask exactly, assert its adjacency matrix and L-fold reachability, state that all non-attention operations are tokenwise, and test the full vocabulary-logit Jacobian across boundary distances, variants, seeds, and trained checkpoints. Assert disconnected/zero gradients without converting `None` or a missing hook into an unquestioned pass ([PLAN.md:53](/home/bmarti44/stencil-llm/PLAN.md:53), [PLAN.md:324](/home/bmarti44/stencil-llm/PLAN.md:324)).
8. Freeze evaluation dataset sizes and seeds, rule sharing/splitting, checkpoint selection, per-cell estimator, seed aggregation, confidence intervals or exact binomial error bounds, and all G4/G6 aggregation rules. Choose either loss or perplexity for G6 and use it consistently ([PLAN.md:283](/home/bmarti44/stencil-llm/PLAN.md:283), [PLAN.md:417](/home/bmarti44/stencil-llm/PLAN.md:417)).
9. Rewrite Appendix D as an exhaustive outcome table. Bound every diagnostic and permissible fix; separate implementation failures from hypothesis failures with independent evidence; add the M1-pass/M1b-fail and B2-only-pass cases; label any 128/256-pair rescue as a new variant; and state which headline claims are withdrawn when H4 fails ([PLAN.md:430](/home/bmarti44/stencil-llm/PLAN.md:430), [PLAN.md:437](/home/bmarti44/stencil-llm/PLAN.md:437)).
