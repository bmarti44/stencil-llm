## Findings

1. **Critical — Task A does not make the unreachable baselines a 16-way-chance predictor.** H1 says the base and B1 are “pinned at chance by construction” (`PLAN.md:46`), Section 1 calls the ceiling chance (`PLAN.md:53-58`), and G3.1 requires at most 8.25% (`PLAN.md:339-346`, `PLAN.md:419-426`). But Task A samples `k` fixed permutations once per dataset seed and gives the model the operand `x` (`PLAN.md:252-259`). When the cue is unreachable, the Bayes predictor can learn the marginal of `rule_i(x)` across the fixed rules. For `k=8`, even eight distinct outputs give at least 1/8 = 12.5% conditional accuracy, already above 8.25%; collisions only raise it. Exact-zero cue gradient proves cue unreachability, not a uniform answer distribution. The README compounds the false claim with “The normal model fails every time, guaranteed” and “coin-flip level” (`README.md:17`, `README.md:33`). This invalidates the load-bearing G3.1 interpretation and can force a correct baseline to fail the gate.

2. **Critical — Answer-token alignment is unspecified and permits target leakage.** Generators return `tokens` plus a mask selecting “answer positions” (`PLAN.md:248`), sequences explicitly contain `[answer = ...]` tokens (`PLAN.md:252-254`, `PLAN.md:272-274`), and loss is “Cross-entropy at masked answer positions” (`PLAN.md:281-283`). The plan never states that logits at position `p-1` predict the answer token at `p`, nor how `loss_mask` is shifted. A literal same-position implementation lets the causal model read the answer embedding and copy the target. The load-bearing gradient test’s phrase “answer-position logit” is therefore ambiguous too (`PLAN.md:323-325`). Task A, Task B, Task M, all accuracy gates, and the reachability proof need one explicit next-token indexing convention.

3. **Critical — The stated discretization cannot pass three mandatory numerical tests.** The update is symplectic Euler when `G=0` (`PLAN.md:193-198`), so the “symplectic” label is defensible, but it does not exactly conserve the declared continuous energy. With `dt=1`, `y_0=0`, `z_0=1`, and any `A>0`, the update gives `z_1=1`, `y_1=1`, hence `H_1=1+A` rather than `H_0=1`. At the minimum period 8, `A=(2π/8)^2≈0.617`, so the first-step drift is about 61.7%, not below `1e-4`. With small positive `G`, `H_1=(1+A)/(1+G)^2` can still increase, contradicting monotonicity. The discrete trajectory also cannot match the continuous closed form to `1e-4` for 1,000 steps; for the same period-8 initial state, discrete `y_1=1` while continuous `y(1)=sin(π/4)/(π/4)≈0.9003`. Thus `test_oscillator_matches_closed_form`, `test_imex_energy_conservation`, and `test_damped_energy_monotone` are impossible as written (`PLAN.md:318-320`), and the claim that M1 “conserves exactly (IMEX)” is false for the specified `H` (`PLAN.md:47`, `PLAN.md:235`).

4. **High — The controller tensor dimensions and two-cell dataflow are not defined.** Each cell has `y,z ∈ R^64`, with 128 state values per cell (`PLAN.md:202-205`), yet Section 5.3 says `c_t` is dimension 128 “from final cell's y” (`PLAN.md:216-223`). A dense readout is mentioned but neither its 64→128 shape nor its placement is stated (`PLAN.md:212`). The spec also does not say whether the second cell consumes the first cell’s `y`, a GLU projection, the original 256-dimensional embedding, or a residual combination, and it supplies no GLU input/output dimensions or initial-state convention (`PLAN.md:184-186`, `PLAN.md:202-212`). Consequently the total state, parameter count, JAX fixture, and patched object called `c` are not uniquely implementable.

5. **High — H2 is not the controlled comparison the hypothesis claims.** H2 says “Three matched controllers differ only in energy handling” (`PLAN.md:47`), but B2 is one first-order 128-dimensional decay recurrence (`PLAN.md:234`) while M1/M1b are two 128-state oscillator cells plus a GLU (`PLAN.md:204-205`, `PLAN.md:235-236`). They differ in recurrence order, depth, nonlinearity, total latent state, and likely parameter count, not only dissipation. The fairness note also says “every recurrent variant starts ... with dissipation learnable” (`PLAN.md:238`) while M1’s `G` is explicitly a frozen zero buffer (`PLAN.md:208-211`). Total-model parameter matching cannot remove these mechanism confounds.

6. **High — The parameter-matching claim is numerically unsupported and cannot be instantiated from the plan.** Section 5.5 says control pathways add “roughly 70 to 130k params” and that configs widen `d_ff` to match all six variants (`PLAN.md:240-242`). B2 as written adds only about 34,960–35,088 parameters: `B` is 128×256, `λ` has 128 values, and the 16 gates contribute `16×(128+1)` (depending on whether `B` has a bias). B1’s displayed vectors add only `4×4×256=4,096` weights (`PLAN.md:221-225`, `PLAN.md:233-234`). The oscillator count cannot be computed because Finding 4 leaves the stack and readout shapes open. No six concrete `d_ff` values or a matching target are specified in Section 5.5 or Appendix A (`PLAN.md:390-401`), so `test_param_match_within_1pct` has no fixtures (`PLAN.md:326`).

7. **High — Appendix A is not a complete or internally safe configuration schema.** The “single flat dataclass” lists only a small field set (`PLAN.md:390-401`). It omits Task M’s `P` and query count even though the production task uses P=32 and its named miniature test requires P=4 (`PLAN.md:276`, `PLAN.md:309`); Task B’s rule count and delay bounds; context length; RoPE settings; controller/readout/GLU dimensions; initialization choices; AdamW weight decay/betas/epsilon; evaluation size and cadence; checkpoint selection; Phase 4 probe/patch/permutation seeds and fit settings; Phase 5 evaluation settings; and Phase 6 corpus, tokenizer, mixture, sequence length, token budget, and validation split (`PLAN.md:263-266`, `PLAN.md:332-337`, `PLAN.md:352-358`, `PLAN.md:364`, `PLAN.md:372-380`). `damping_learnable` can also contradict `variant=m1` or `variant=m1b` (`PLAN.md:394-400`). A coder must add fields, hard-code hidden defaults, or accept contradictory configs.

8. **High — Task B and Task M sampling semantics are incomplete.** Task B specifies only `R`, a delay distribution, and “most recent cue”; it omits `k`, the cue schedule (including whether adjacent cues may repeat), operand sampling, rule-table lifetime, and how stale-rule errors handle multiple prior rules producing the same answer or zero wrong answers (`PLAN.md:261-266`). Task M does have consistent range arithmetic—P=32 exhausts the 32 keys, and the value alphabet has 16 tokens—but it never says whether values or the eight queried keys are sampled with replacement, how query order is chosen, or the exact gap length formula (`PLAN.md:268-279`, `PLAN.md:403-411`). Those choices change difficulty, fixtures, and metrics, so `test_task_b_active_rule_tracking`, `test_task_m_bindings`, and `test_task_m_gap_exceeds_receptive_field` do not determine one generator (`PLAN.md:308-310`).

9. **High — Phase 0 and Phase 1 tests lack independent, reproducible oracles.** `test_determinism_two_runs_bitwise` does not fix the “tiny model,” dummy-copy data, device, optimizer details, or exact loss sequence (`PLAN.md:291-298`). `test_config_hash_stable` does not define canonical JSON encoding, treatment of defaults/enums/floats, or hash bytes, while `test_seed_isolation` does not state which tensors/sequences are compared (`PLAN.md:292-295`). Phase 1 asks for “hand-computed fixtures” without providing them or specifying the permutation/RNG algorithm, metadata schema, or label shift (`PLAN.md:302-310`). The distractor-independence test demands “every rule with correct frequency” but gives neither a deterministic balanced construction nor a sample count/tolerance (`PLAN.md:256-257`, `PLAN.md:306`). The implementer would author both behavior and expected values.

10. **High — The remaining Phase 2 tests still require guesses after the impossible integrator tests are removed.** Exact zero from `softplus(g_raw)` requires a specified `-inf` assignment or a special branch, but `test_damping_zero_matches_m1_bitwise` states neither (`PLAN.md:208-211`, `PLAN.md:320`). The JAX oracle has no pinned repository commit, package version, fixture shapes, seeds, dtype, or named cases, and the instruction “If they differ materially, implement the papers' forms” allows external code to override the governing equations without an amendment (`PLAN.md:200`, `PLAN.md:321`, `PLAN.md:458-464`). The scan test is optional while Gate G2 says tests 1–9 must be green (`PLAN.md:322`, `PLAN.md:328`). Gate-identity does not define how B1’s sigmoid output is clamped to exactly 1 or how shared initialization avoids RNG-consumption differences (`PLAN.md:323`). The nonzero-gradient tests do not fix the sample, selected logit, initialization, norm/threshold, or boundary `N`, so a zero caused by a particular random network can fail a structurally valid path (`PLAN.md:324-325`).

11. **Medium — Receptive-field arithmetic is only conditionally correct because `window` and `N` use incompatible conventions.** The products 4×64=256 and 12×256=3072 are arithmetically correct (`PLAN.md:170-180`, `PLAN.md:372`), and B1’s layerwise bound is valid if `w` means maximum backward edge length (`PLAN.md:53-55`). But a “window 64” often means 64 attended positions including self, whose maximum lag is 63; the explicit mask convention is never given (`PLAN.md:159`, `PLAN.md:175`). Also Task A’s `N` is a count of distractor tokens, so the cue-to-QRY distance is N+1 and the cue-to-next-token answer decision is N+2, not N (`PLAN.md:252-258`). The large registered cells remain safely separated, but `test_cue_reachable_when_close` can select `N < receptive_field()` while the actual decision remains outside it (`PLAN.md:324-325`). Exact-zero boundary tests and `model.receptive_field()` therefore lack one shared definition.

12. **High — Phase 3 thresholds are not reproducible measurements.** The fixed training block omits AdamW weight decay/betas/epsilon and evaluation protocol (`PLAN.md:330-337`); Section 6 says only that accuracy is reported as JSON (`PLAN.md:281-283`). There is no evaluation sample count, confidence requirement, held-out seed policy, checkpoint choice (last versus best), or metrics JSON schema. The 8.25% chance band and 95/90/85% gates therefore have uncontrolled sampling error (`PLAN.md:339-348`, `PLAN.md:417-428`). G3.2’s “min seed >= 85” also does not explicitly say whether the minimum is enforced separately at both registered cells (`PLAN.md:341`, `PLAN.md:420`). The run-count statement itself is correct: Task A contributes 6×3×3 + 2×3 = 60 runs and Task M contributes 5×3×2 = 30, exactly 90 (`PLAN.md:334-337`).

13. **High — None of the three Phase 4 gate tests has a complete protocol.** The logistic probe lacks solver, regularization, optimizer/steps, seed, balancing, preprocessing, and checkpoint-selection rules (`PLAN.md:352-355`). Patching lacks a precise donor/recipient sampling schedule, required `i≠j` condition, output position, and definition of whether “overwrite `c`” means the ambiguous readout or the full `(y,z)` state (`PLAN.md:355`; see also `PLAN.md:204`, `PLAN.md:218`). Gate shuffling does not define one fixed permutation versus per-example permutations, seed, whether layer/head axes may mix, evaluation set size, or the reference accuracy from which the 30-point drop is measured (`PLAN.md:356`). These degrees of freedom can change pass/fail outcomes materially.

14. **Medium — H4’s stated channel-capacity inference is not justified by its dimensions.** H4 calls 16 real scalars per position a bottleneck that should carry rule identity but not arbitrary content (`PLAN.md:49`, `PLAN.md:276-279`), and the README calls 32 bindings “far too many facts to smuggle through the wire” (`README.md:38`). Yet 32 values from a 16-symbol alphabet contain at most 128 bits, while the recurrent stack has at least 128 real-valued output coordinates and exposes 16 unquantized real gates at every position (`PLAN.md:204-225`). Without quantization, noise, an information estimator, or a proved capacity bound, low beyond-window accuracy is empirical failure to use the channel, not proof of channel purity; high accuracy shows use, but the asymmetric “clean control channel” label in Appendix C overclaims (`PLAN.md:426`).

15. **High — Phase 6 is neither dimensionally complete nor compatible with earlier fixed claims.** A 12-layer, d_model=768 model is not determined to be ~125M without `d_ff`, vocabulary/tokenizer size, embedding tying, and controller scaling, all omitted (`PLAN.md:372-375`, `PLAN.md:395-400`). “B0-local-widened” has no widening rule. If Phase 6 includes Task B with R=32, its worst-case token count also exceeds context 8192, but no scaled R grid is selected (`PLAN.md:263`, `PLAN.md:372-374`). G6 cannot be configured or reproduced from Appendix A.
