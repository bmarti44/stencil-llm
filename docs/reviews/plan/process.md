3. Replace the free-form ledger with a validated schema for work ID/state, phase/gate, branch/HEAD/dirty paths, brief hash/scope, actor/session/PID/model/effort, commands/logs/tests, finding inventory, matrix cells/checkpoints/retries, blockers, and exact next command. Add the missing Round 4 write-ahead and correct false closure/deferment claims (`PLAN.md:116-129`).
4. Add slug validation, persistent logs, safe sandbox/narrow environment, baseline capture, and brief-derived allowed-path enforcement to `run_codex_agent.sh`; on every review failure, restore/flag drift and atomically preserve the prior canonical file before exiting (`PLAN.md:103`; `tools/run_codex_agent.sh:20-61`; `tools/run_codex_review.sh:282-405`).
5. Define and validate the coder-brief schema before the first Phase 0 coder launch, and require explicit ledger authorization for actor-model/effort overrides (`PLAN.md:91-100`, `PLAN.md:120`).
6. Make Appendix D a total outcome table with one attempt budget. Remove the post-failure wide rescue or register it as a non-passing exploratory result, and admit every qualified-green state consistently in later-phase prerequisites (`PLAN.md:68`, `PLAN.md:394-421`, `PLAN.md:491-505`).
7. Add a gate-acceptance manifest/command that binds exact gate evidence, the registered sol topic/threshold, completed kimi artifact coverage and adjudication, open-finding inventory, ledger state, README row, and proposed commit (`PLAN.md:101-106`; `README.md:45-58`).
8. Define status triggers for `in progress`, `red`, `killed`, and Phase 5/7 completion; add evidence path, accepted review round/score, date, and commit SHA to README (`PLAN.md:78`, `PLAN.md:413-439`; `README.md:45-58`).

12. Store rejected kimi output outside `docs/reviews`, exclude it from both context and metrics, and include root result documents/figures plus an explicit required-artifact manifest before applying the context cap (`tools/run_kimi_review.py:40-75`, `tools/run_kimi_review.py:171-182`; `tools/agent_metrics.py:86-94`).
13. Specify a runnable tie-break command, prompt, evidence bundle, canonical verdict artifact, and verification step; reconcile the two-round human trigger with the post-tie-break trigger (`PLAN.md:106`, `PLAN.md:112`).
14. Register plan-phase acceptance (required sol topics/scores, kimi adjudication, commit/ledger event) and define first-test freeze triggers for Phases 0-2 before Phase 0 begins (`PLAN.md:76`, `PLAN.md:101`, `PLAN.md:124`).
