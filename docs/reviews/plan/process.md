## Findings

1. **High — A review can still pass while a prior high or critical finding remains open.** Section 2b, “Finding identity and closure,” now promises that “`tools/check_review_scores.py` treats any unmarked high/critical finding as open and fails regardless of score” (`PLAN.md:97`). The checker, however, searches only the current `## Findings` section and returns no open findings when that section is missing (`tools/check_review_scores.py:25-31`); it has no prior-file or finding-ID input (`tools/check_review_scores.py:45-83`). A replay with score 95 and no Findings section returned `open_high_critical=[]`, and a score-95 file containing only a Low finding did the same. The wrapper then invokes only that score checker (`tools/run_codex_review.sh:354`). It also never validates the frontmatter verdict or the score's 0-100 range (`tools/check_review_scores.py:18`, `tools/check_review_scores.py:34-42`), while the prompt hard-codes “PASS (≥90)” despite the wrapper accepting any threshold (`tools/codex-prompts/_common-header.md:13`, `tools/run_codex_review.sh:32-44`). An omitted open finding, a score of 999, or a contradictory FAIL verdict can therefore be accepted.

2. **High — The claimed append-only review history remains mutable.** Section 2b says, “Round logs are append-only” (`PLAN.md:96`). The validator checks only that each old round number remains in the candidate (`tools/review_round_tracking.py:92-100`); it does not compare block text, order, uniqueness, finding identity, or closure transitions, and its own module header still calls this a “softer contract” (`tools/review_round_tracking.py:1-21`). The wrapper expressly says, “We no longer enforce strict byte-identity on prior rounds” (`tools/run_codex_review.sh:280-286`). A replay that replaced the entire Round 1 body with `### Round 1 — altered` and deleted its open High finding returned `{'passed': True}`. Together with Finding 1, this is still a complete silent-drop path.

3. **High (resolved 2026-08-22: stable IDs and reviewer-concurrence closure are now explicit) — Refutation was unilateral and had no durable finding identity.** Section 2b now states, “a finding's identity is `<topic>#<number>`,” “only a subsequent reviewer round may mark a finding `(resolved ...)` or `(refuted ...)`,” and “the orchestrator never edits reviewer-authored review files” (`PLAN.md:97`). The current reviewer protocol repeats that closure may be marked only after the reviewer verifies the fix or evidence (`tools/codex-prompts/_common-header.md:28`). This resolves the specification-level refutation gap; Findings 1-2 separately cover the fact that the tooling does not preserve those transitions.

There is no Round 2 write-ahead entry, despite the trigger “BEFORE launching any codex agent, review, or training run” (`PLAN.md:112`). ## Recommendations

1. Make review acceptance stateful: require a `## Findings` section, score 0-100, verdict/threshold consistency, unique stable finding IDs, and an explicit status for every prior High/Critical ID. Pass the prior snapshot into the checker and fail if an open ID disappears (`PLAN.md:97`; `tools/check_review_scores.py:18-83`).
2. Enforce true append-only history: compare every prior Round block byte-for-byte except a separately structured correction record, require strict descending unique round numbers, and preserve append-only finding-state transitions (`PLAN.md:96`; `tools/review_round_tracking.py:76-105`; `tools/run_codex_review.sh:280-299`).
3. Replace prose ledger entries with a required schema covering work-unit/phase/gate/state, branch/HEAD/dirty paths, brief hash and scope, actor/session/PID, command/log/model/effort, test/evidence IDs, matrix manifest/cell/checkpoint/retry state, finding inventory, blockers, and exact next command. Write before every wrapper/matrix launch and after every cell/checkpoint; update the currently stale Round 2 state (`PLAN.md:108-118`).
4. Add the same `.review.lock`, safe sandbox default, slug validation, narrowed environment, baseline snapshot, and brief-derived allowed-path diff enforcement to `run_codex_agent.sh`; do not restore concurrent edits—use serialization or isolated worktrees and fail without copying over other sessions (`PLAN.md:101`; `tools/run_codex_agent.sh:20-48`; `tools/run_codex_review.sh:49-56`, `tools/run_codex_review.sh:308-352`).
5. Define and validate a coder-brief schema before Phase 0, pin model/effort or require recorded authorization for overrides, and require the wrapper to emit provenance into the ledger (`PLAN.md:90`, `PLAN.md:101`, `PLAN.md:116`).
6. Repair Appendix D by adding M1b/B2 sanity cells to the registered matrix or removing that prerequisite; add explicit G3.3/G3.4/G3.6 branches; and reconcile D.3b with one unambiguous definition of whether G3.2b blocks green (`PLAN.md:359`, `PLAN.md:363-372`, `PLAN.md:462-473`).
7. Give Phase 5 a fixed training/eval config, numeric GPU-hour budget, pilot, per-run timeout, checkpoint/resume policy, and matrix-cell ledger triggers. Require the Phase 6 amendment to freeze an aggregate budget and the same operational fields for both paired variants (`PLAN.md:102`, `PLAN.md:386-401`).
8. Split determinism into named toy/proof and scale contracts. Keep bitwise fp32 proof gates and define a repeatability tolerance and command for bf16 scale training (`PLAN.md:77`, `PLAN.md:122-132`, `PLAN.md:400-406`).
9. Add one gate-acceptance command or manifest that verifies scientific evidence, every required topic review, zero open High/Critical IDs, ledger state, README row, and proposed commit message before allowing a milestone commit (`PLAN.md:76`, `PLAN.md:99-100`; `README.md:45-58`).
10. Add `tools/codex-prompts/review-amendment.md` with an amendment-specific checklist and make the wrapper validate its presence in a preflight test (`PLAN.md:104`; `tools/run_codex_review.sh:115-126`).
11. Define status-transition triggers for `in progress`, `red`, `killed`, and completion of Phase 5/7; add evidence path, accepted review round/score, date, and commit SHA to the governed README table (`PLAN.md:76`, `PLAN.md:386-412`; `README.md:45-58`).
