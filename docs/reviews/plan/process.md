## Findings

1. **High — Review acceptance still permits malformed scores, contradictory verdicts, and forged closure.** Section 2b, “Finding identity and closure,” says “`tools/check_review_scores.py` treats any unmarked high/critical finding as open and fails regardless of score” (`PLAN.md:98`). The missing-`## Findings` defect is fixed (`tools/check_review_scores.py:25-33`), but the checker accepts one to three score digits without bounding them, never parses `**Verdict:**`, and treats any first-line `(resolved ...)` or `(refuted ...)` string as closure (`tools/check_review_scores.py:18-22`, `tools/check_review_scores.py:36-44`, `tools/check_review_scores.py:66-85`). A direct parser replay of a file containing `**Score:** 999 / 100`, `**Verdict:** FAIL (<75)`, and an unsupported “trust me” resolution returned `score=999` and `open_high_critical=[]`; the wrapper's final authority is still only `check_review_scores.py --file ... --min ...` (`tools/run_codex_review.sh:378`). A malformed or dishonest review can therefore be mechanically accepted.

2. **High — The claimed append-only review history remains mutable.** Section 2b, “Review protocol,” says “Round logs are append-only” (`PLAN.md:97`). The wrapper instead says “We no longer enforce strict byte-identity on prior rounds” (`tools/run_codex_review.sh:304-310`), and the validator freezes only each prior score line plus the set of High/Critical numbers (`tools/review_round_tracking.py:92-126`). It does not preserve prior block text, heading/date/model, order, uniqueness, finding severity/title/body, or an open-to-closed transition. A replay that rewrote the entire Round 1 body and replaced finding 1 with an unrelated, self-declared resolved finding under the same number returned `OK`. This is still a complete silent-drop path even though outright deletion of the number now fails.

3. **High (resolved 2026-08-22: stable IDs and reviewer-concurrence closure are explicit in the governing prose) — Refutation was unilateral and had no durable finding identity.** Section 2b now says “a finding's identity is `<topic>#<number>`” and “only a subsequent reviewer round may mark a finding `(resolved ...)` or `(refuted ...)`” (`PLAN.md:98`); the reviewer protocol says “Never mark a finding resolved on the orchestrator's claim alone” (`tools/codex-prompts/_common-header.md:28`). ## Recommendations

1. Make review acceptance stateful: bound scores to 0-100, validate verdict against the active threshold, require unique finding IDs and valid closure syntax, and compare each prior High/Critical finding's severity/title/body/status transition against the prior snapshot (`PLAN.md:98`; `tools/check_review_scores.py:18-85`; `tools/review_round_tracking.py:92-126`).
2. Enforce genuinely append-only history: preserve every prior Round block byte-for-byte, put corrections in a separate append-only correction record, and require strictly descending unique round numbers (`PLAN.md:97`; `tools/run_codex_review.sh:304-323`).
3. Replace free-form ledger entries with a validated schema covering work-unit/phase/gate/state, branch/HEAD/dirty paths, brief hash and allowed paths, actor/session/PID/model/effort, command/log, tests/evidence, finding inventory, matrix manifest/cell/checkpoint/retry state, blockers, and exact next command. Update it at every matrix-cell/checkpoint transition, not just launch/end (`PLAN.md:115-127`).
4. Give `run_codex_agent.sh` slug validation, a safe sandbox/narrow environment, a baseline snapshot, and a brief-derived allowed-path validator that fails on excess scope; make both wrappers run containment checks and preserve recovery state on timeout/nonzero exit (`PLAN.md:102`; `tools/run_codex_agent.sh:20-61`; `tools/run_codex_review.sh:278-378`).
5. Define and validate the coder-brief schema before Phase 0, pin the actor model/effort or ledger explicit override authorization, and have the wrapper emit a machine-readable handoff/provenance record (`PLAN.md:90-92`, `PLAN.md:119`).
6. Replace Appendix D with a total outcome table over simultaneous failures. Register `green-with-efficiency-miss` everywhere or remove it; never continue from a red G3.6 calibration result; and reconcile the wider-variant amendment path with the absolute G3 kill rule (`PLAN.md:67`, `PLAN.md:391-395`, `PLAN.md:487-501`; `README.md:47-58`).
7. Require the Phase 6 freeze amendment to set an aggregate GPU-hour budget, pilot cell, per-run timeout, paired checkpoint/resume policy, and partial-matrix recovery rule; separate the toy bitwise contract from a named, testable scale-repeatability contract (`PLAN.md:103`, `PLAN.md:419-429`).
8. Add one gate-acceptance manifest/command that jointly checks gate evidence, every required sol review, completed kimi cadence, zero open confirmed blockers, ledger state, README row, and commit-message state (`PLAN.md:100-105`; `README.md:45-58`).
9. Define status-transition triggers for `in progress`, `red`, `killed`, and completion of Phases 5/7; include evidence path, accepted review round/score, date, and gate commit SHA in README (`PLAN.md:77`, `PLAN.md:409-435`; `README.md:45-58`).
10. Add and preflight review prompt fragments and topic mappings for every phase, including the explicitly required `tradeoff` and `report` topics (`PLAN.md:100`; `tools/run_codex_review.sh:115-126`).
11. Make amendments two-stage: commit or store a non-operative draft, run `topic=amendment`, then activate it only with an amendment record containing old/new values, affected phase, first-run/freeze evidence, review ID/score, and activation commit. Correct Appendix C's stale “last amended v1.4” claim (`PLAN.md:7-15`, `PLAN.md:111`, `PLAN.md:469-485`).
12. Require kimi completion before a gate decision, or explicitly defer it to the next phase and prohibit consumption until confirmed findings are adjudicated; make rejected output a `/tmp` artifact rather than a repository sibling (`PLAN.md:101`, `PLAN.md:105`; `tools/run_kimi_review.py:168-179`).
13. Implement the documented fresh-session retry, record fallback in the new round, and move `SID` discovery before resume-note construction (`PLAN.md:107`; `tools/run_codex_review.sh:167-170`, `tools/run_codex_review.sh:242-288`).
14. Require a sol process review of every retro-generated tool, prompt, or AGENTS change before the next phase begins (`PLAN.md:99`, `PLAN.md:109`).
