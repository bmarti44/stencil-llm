# Composition pilot 4 — one-round diagnosis (fable, independent reviewer)

2026-09-06. CPU only. Sources: results/quick-checks/composition-pilot-4/{README.md,
summary.json, records.jsonl, continuation/records/*.jsonl} (479 same-run records),
Amendment 3 (composition-pilot-3/README.md:192-236), src/stencil/focus/{slab.py,
loop.py, renderer.py} at HEAD. No data/bench and no evaluation episodes were read;
all episode content quoted below is the authored DEV bank regenerated by
`generate_episode("dev", i)`.

## Verdict in one paragraph

Pilot 4's instrument is, for the first time, internally consistent: the checker
matches the prompt, the reference envelope passes `check()` with `success=True`
(dry_run assert, validation log), and the retirement events render exactly as the
checker expects. The 100% format relapse in every arm — including T — is therefore
not a scoring bug; it is the literal model output: in 348/348 parsed responses
across R/N/T the report has exactly the keys `status,task,delivery`, and the model
never once produced the compact form `{"status":"ok"}` or omitted `delivery`, even
when T said `format=compact` in the same request. That makes the two *omission*
witnesses (drop `task`, drop `delivery`) floor-level in the comparator arm, hence
uninformative, and since `success` requires all of them, final success is 0 in
every lane by construction of the model's behaviour, not of the harness. The
substitution witnesses (a literal replacement value in the rule) do show a
gradient: delivery -> ready after the completes event R 20/33, T 15/44, N 0/37;
indent following a supersedes event T 11/17, N 7/20, R 2/13. Caps are one
mechanism: nine lanes re-emit every prior function inside one `edit` from round 1
(despite Amendment 3's "append only the new function"), the file duplicates,
output exceeds 512 tokens by round 2-6, and in 7 of the 9 lanes every later round
caps — 131/131 caps are unparseable "Unterminated string" envelopes. Cost is
decode-dominated (prefill <5%) and the 38.5 h floor is set by the spiral lanes
(max-token lanes are all capped-every-round lanes). My recommendation under the
do-not-over-engineer rule is to SIMPLIFY (Section 5): the SLAB envelope's
append-edit semantics has now caused a cap spiral in three consecutive pilots and
the whole-file mental model the model keeps exhibiting is exactly the plainer
harness Brian proposes; but note that whole-file output costs *more* decode per
call than the envelope, so the plainer harness only fits a budget if episodes are
shortened or the decode rate is fixed (numbers in Section 4).

## 1. Format relapse 100% in all arms: genuine output, but a floor-level witness

**Checker (slab.py `check`, lines ~984-1000).** With `stale["format"]=="verbose"`
and `rules["format"]=="compact"` on every round after the format event
(`generate_episode` keeps `retired["format"]="verbose"` for the rest of the
episode, so the denominator is 1 on every later round):

```
expected_report = {"status": "ok"}          # task only when rules["format"]=="verbose"
violations["format"] = (... ) or {k:v for k,v in report.items() if k!="delivery"} != {...expected...}
relapse["format"] = stale.get("format") is not None and isinstance(report, dict) and report.get("task") == t.task
```
and `relapse = relapse and prior["format"]`, where `prior["format"]` is true once any
earlier executed body's report contained `task` (always true after round 0). So
relapse fires iff the report still carries the correct workshop letter after the
format obligation is gone. That is the intended witness and it is satisfiable:
`reference()` omits `task` when format is compact and `dry_run` asserts
`outcome["success"]` on every DEV round.

**Rule and retirement as rendered (R, slab-dev-00, round 12, verbatim from
`rendered_messages`).** Active row after the event:
```
{"default":true,"key":"format","kind":"format","provenance":{"message_id":"m-1","role":"user","span":null},"scope":{"request_kinds":[],"task_handle":null},"text":"Workshop obligation: format must be compact.","value":"compact","version":0}
```
Retired block:
```
Retired: format v1; no longer binding in {"request_kinds":[],"task_handle":null}; replaced by default "compact"; reason completes.
```
Request changes line (all arms): `completes format -> verbose.` T arm rule text
(slab-dev-00 round 12): `Effective obligations: delivery=ready; format=compact;
indent=2 ...; language=Python; test_record=test-after-edit. Not binding:
delivery=staged; format=verbose; indent=3`. The system prompt says "report status
is ok, verbose includes task, compact omits task" and gives the literal compact
example `{"calls":[{"op":"test"}],"report":{"status":"ok"}}`. Rendering and
checker agree; the model is told the value (compact) in R and T, and told what
compact means once, in the system prompt.

**Three scored outputs (verbatim report tails; full outputs in the records).**
- R slab-dev-00 round 13 (format retired at 12; rule row says compact):
  `...{"op":"test","path":"core.py"}],"report":{"status":"ok","task":"A","delivery":"staged"}}`
  -> relapse format True, violation format True (task present), process True
  (delivery "staged" while the live value is default "ready").
- T slab-dev-00 round 12 (request text literally says `format=compact` and
  `delivery=ready`): `...],"report":{"status":"ok","task":"A","delivery":"staged"}}`
  -> same three flags.
- N slab-dev-03 round 12 (format completed at 11, delivery completed at 10):
  `...],"report":{"status":"ok","task":"B","delivery":"staged"}}` -> same.

**Census over every parsed output (348 of 479; the other 131 are caps):** report
keys are exactly `delivery,status,task` in 108/108 R, 109/109 N, 131/131 T.
`task` tracks the request letter correctly every round (the model does read the
request); `delivery` is emitted on every round including non-scoped tasks; the
`task` key is never dropped. The report object is copied from the model's own
previous turn with the letter updated — a shape-copy behaviour. So: not an
instrument defect in scoring or rendering. It *is* an instrument defect in witness
selection: nothing in four pilots established that the comparator T can satisfy
"omit a key" at a non-zero rate; pilot 4 shows it cannot (0/131), so the trait
carries no arm signal and its 100% relapse says nothing about retirement.
Minor rendering nit, not causal (T is also 100%): the changes line renders the
completion as `completes format -> verbose.`, which in N is the only cue and reads
like an assertion of verbose.

## 2. Final success 0 everywhere despite integration passing

wrong_family/breakage/semantic. Final-round clauses per lane (from the records):

| Lane | final violations |
|---|---|
| R 00 | style, process, format |
| R 01, 03, 04 | style, format |
| R 07 | format |
| R 02, 05, 06 | breakage (capped), format |
| N 01 | process, semantic, format |
| N 02 | process, breakage, format |
| N 03, 05 | style, process, format |
| N 06 | semantic, process, breakage, format |
| N 00, 04, 07 | breakage (capped), format |

| T 00, 03, 04 | process, format |

| T 05 | style, process, format |

Format (the `task` key still present after the format event, which every episode
has fired by its final round) fails in 24/24. Process is the second killer, and in
integration-true rounds it is never the receipt clause: in every integration-true
round the last op is `test` with a valid receipt (R 99/99, T 112/112, N 41/41);
the process flag comes from the delivery clause (`delivery` emitted on a
non-scoped task, or the stale value instead of `ready`). Style is third (4-space
prior: R round-0 emits width 4 in 8/8 lanes against rules 3,3,3,2,2,3,4,4; T 4/8
correct). Integration passes in 6/8 R lanes because the code is right and the
cumulative public tests pass; success is unreachable because it also requires two
omission traits the model never performs and an indent trait it performs ~25%.
There is no hidden live obligation: the failing clauses are all surfaced in the
prompt (R rows, T text) — the model does not apply them.

## 3. Why 32% of calls still cap at 512

All 131 caps are 512-token outputs whose envelope is an unterminated JSON string
(`"error":"envelope","reason":"invalid JSON: Unterminated string ..."`). Content
census: every capped output is one `edit` call whose `code` contains three or more
`def step_` definitions (N 30 with 3, N 21 / R 51 / T 29 with 4+), i.e. the model
re-emits every prior function plus the new one. Verbatim head of R slab-dev-06
round 3 (input 3510 tokens): `{"calls":[{"op":"edit","path":"core.py","code":"def
step_0(x):\n    \"\"\"Process an event ... def step_1(x): ...` and the tail is cut
mid-`report`. The spiral is deterministic per lane: 9/24 lanes re-emit from round 1
(N 00, 04, 07; R 02, 05, 06; T 06, plus N 01/02 which re-emit only at round 0-1
and recover), the append-semantics `edit` then duplicates definitions (feedback
shows `"functions":["identity","step_0","step_0","step_1"]`), output grows ~120
tokens per round (280 -> 400 -> cap), and in 7 of those 9 lanes every round after
the first cap is also capped — the lane is dead for the rest of the episode. This
is the same mechanism I flagged in pilot 3 (13/24 lanes); Amendment 3's prompt
sentence "Append only the new function; never re-emit earlier functions" reduced
it from 13 to 9 lanes but did not remove it. The model's operating prior is
"emit the file"; append semantics fight that prior and lose.

The other 27 caps are the same re-emission before the lane died (N 04 recovered
once). No cap is caused by long docstrings alone: uncapped outputs are tightly
banded at 160-196 tokens (median 174), i.e. one ~135-token function plus a ~40-token
envelope.

## 4. Cost

Measured (records): 479 calls, 130,313 output tokens, 3.86 M input tokens,
11,718 wall-seconds of request time (335/479 calls overlap other lanes; GPU-held
6831 s). Decode 10.7 tok/s per stream uncapped, 12.5 capped, 24.7 aggregate.
TTFT is 0.6-1.0 s up to 20k input and ~5.5 s above 24k, so prefill is under 5% of
request time; the cost is decode tokens / aggregate rate. Split: uncapped 348
calls, mean 182 tokens, 17.9 s/call, 6228 s total; capped 131 calls, 512 tokens,
41.9 s/call, 5490 s total — 27% of calls take 47% of request time and 51% of
tokens.

The registered projection floor 38.55 h = 5.0 h prior spend + 1.9 h this run +
0.12 h reload + 1.25 x [64 x (15,179 + 15,952) + 16 x (0 + 15,697)] / 24.73 tok/s
= 31.5 h future. The three max-token lanes (R 06, N 07, T 06) are precisely the
spiral lanes (31-32 capped rounds x 512). An uncapped 32-round lane is 5.2-5.6k
tokens and a 16-round lane 2.6-3.2k; with the spiral removed the same formula
gives 1.25 x [64 x (5,590 + 5,206) + 16 x 5,174] / 24.73 = 10.9 h future, 17.9 h
with prior spend. Note the registered gate "<=12 GPU-h including prior spend and
reserve" is already arithmetically dead: 7 h are spent, so the future run would
have to be under 4 h before the 1.25 reserve.

**Fenced whole-file harness, same model style.** The model writes ~135 tokens per
function (its docstring style) and the two files each hold about half the
functions. Whole-file output at round i is ~30 + 135 x ceil((i+1)/2) tokens:

| Design | tokens / 16-round lane | tokens / 32-round lane | 64 episodes x R/N/T |
|---|---:|---:|---:|
| Envelope, spiral fixed (append accepted as whole-file when it re-emits) | ~2.9k | ~5.5k | 0.77 M tok -> 8.7 h, x1.25 = 10.9 h |
| Fenced whole file, 16 rounds everywhere | ~10.6k | (n/a) | 2.0 M tok -> 23 h, x1.25 = 29 h |
| Fenced whole file, 16 rounds, 32-round lanes kept | ~10.6k | ~37k (and history overflows 32k context by ~round 20) | 3.2 M tok -> 36 h; infeasible at 32 rounds |
| Fenced whole file, 8-round episodes | ~3.0k | — | 0.58 M tok -> 6.5 h, x1.25 = 8.2 h |
| Fenced whole file, 16 rounds, compact = one-line docstring halving bodies | ~5.5k | — | 1.06 M tok -> 12 h, x1.25 = 15 h |

All at the measured 24.7 tok/s aggregate. So the plainer harness is not cheaper per
se — whole-file output grows linearly with the file — it is cheaper only because it
kills the spiral (which is what inflated 38.5 h) and only fits a ~12 h budget with
8-round episodes or shorter bodies. Rework (Section 5) applies either way. The
single largest cost lever, unmeasured here, is the 11 tok/s per-stream decode of a
3B-active MoE on GB10 under `VLLM_BATCH_INVARIANT=1`; if the batch-invariant path is
what costs the 3-4x, dropping it (and re-establishing determinism by D=0 replay)
would cut every number above proportionally. That is a measurement to make, not a
claim.

## 5. Verdict for Brian

**Is the SLAB envelope salvageable in one more CPU pass?** Mechanically yes, in
four fixes, but two of them change the registered science, not the code:

1. Executor: when an `edit` payload defines a function name that already exists in
   the target file, treat the call as `replace` (whole-file), and score with the
   existing `changed_code` (new top-level definitions only). ~20 lines; kills the
   duplicate spiral without changing the model's behaviour.
2. Cap: 512 -> 2048 so an accepted whole-file re-emission of 8 functions (~1.2k
   tokens) is not truncated; drop or shorten the 32-round DEV/eval lanes (a
   re-emitting 32-round lane overflows the 32k context around round 20).
3. Witness set (science change): remove the two omission traits (`task` key
   omitted for compact; `delivery` omitted for the non-scoped task) from the
   `success` clause and keep them descriptive; keep the three substitution traits
   (indent value, delivery value, and a format trait with a literal value — e.g.
   verbose = multi-section docstring, compact = one-line docstring, measured on
   `changed_code` by AST). Register a T-arm floor check: a trait enters the success
   clause only if T satisfies it at >=50% on the DEV bank.
4. Gates (science change): "R final >= 5/8" and "<=12 GPU-h including 7 h prior
   spend" must be re-registered; with the 4-space prior the model's ceiling on
   indent is ~25% under R and ~65% under T (Section 1 numbers), so any final-success
   gate above ~3/8 fails on style alone.

That is a day of coder work plus a review round, and it keeps a JSON-string
envelope in which every cap is a total loss and every parser tolerance so far
(trailing `]`, trailing `}`, `lift_report`, `test_path`, Python literals) was a
model-versus-schema fight. Fix 1 is, in substance, "accept whole-file output" —
the plainer harness by another name.

**Recommendation: SIMPLIFY.** Move the larger test to the plainer harness: the
model answers with one fenced Python block that is the whole target file plus a
one-line trailer for the report values (e.g. `report: task=A delivery=staged`);
the harness writes the file, runs the frozen public tests itself, and shows the
result plus the current file in the next request. Same rule kinds (style value,
format value on the docstring shape, process value on the trailer), same
retirement events and renderings, same R/N/T arms, `changed_code`-based scoring so
re-emission is free. Rework: slab.py prompt (~30 lines), `parse_envelope` ->
fence/trailer extractor (~30), `Executor.run` -> write-file + run tests (~40,
simpler than now), `check` format/process clauses on the trailer and docstring
(~20), `reference`/`mutants`/`should_pass` regenerated (~40), DEV tests (~100);
run.py/loop.py/renderer.py unchanged. One coder day, one review, one 20-call CPU
smoke; two days including the T-floor pre-check. GPU for 64 episodes x R/N/T at
the measured rate: 8-round episodes ~8 h; 16-round ~29 h (15 h if compact means a
one-line docstring). Choose by measurement: run the 8 DEV episodes at 16 rounds
first (~1 h), read the T floor per trait and the actual tokens/lane, then fix the
episode length. The scientific signal worth carrying forward from pilot 4 is the
delivery gradient (R 20/33 vs T 15/44 vs N 0/37) and the inverted indent gradient
(T 11/17 vs R 2/13): the register helps when the rule row carries the literal
replacement value and hurts when the model must map a value to a key omission or
compete with its 4-space prior. Design the next witnesses so every trait has a
literal value in the rule text, and the test can discriminate arms at all.
