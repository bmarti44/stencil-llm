## 2. The authority boundary must survive automatic proposals

The desired output is a grounded **delta**, not a freshly rewritten rule database. Separate four decisions: whether text is an adopted obligation; its span/value and scope; which existing key/version it affects; and whether this principal is authorized to make that change. Model confidence answers none of the transport-authentication questions.

Proposed contract, before training: the host supplies principal, message role/origin, immutable source identifier, explicitly adopted source ranges when available, declared task handles, register version and target versions. A model may propose evidence offsets, scope, value and operation; it cannot mint authority, a task handle, an adoption receipt or a completion receipt. Tool text, assistant echoes, retrieved memory and quoted payload do not acquire user authority when copied into another model's answer. Genuine user adoption of quoted content needs both the source and the adopting user evidence; blanket quote rejection would lose valid positives. Uncertain inferred adoption remains an abstention/proposal unless the supported policy explicitly admits it.

The semantic verifier sees the **whole authenticated message plus candidate and register context**, including negation and adoption, rather than just the candidate string or the proposer's explanation. For a full updater it must also verify target/version, replacement value and scope; a binary span verifier is only the first experiment. No keyword, regex, request-template or “done” phrase may authorize a write. Typed enum checks, offset bounds/source-byte integrity, authenticated capabilities and exact target IDs are validation, not linguistic string matching. If the intended prohibition also excludes substring lookup, emit source offsets and validate indexed bytes; never substitute a permissive semantic matcher for provenance.

Keep retirement append-only with masks. The current register already derives live state from retirement records (`src/stencil/focus/register.py:298–301`) and applies a transaction to a new register (`:307–316`). Its target operation requires exact scope and sufficient authority (`:331–341`). Therefore task-over-global should compile to a narrower scoped add with explicit shadowing semantics, preserving the global rule elsewhere; it must **not** globally retire the target. Verify actual effective state inside/outside the task through the real renderer before calling this supported. A relation benchmark's “supersedes on intersection” and the executable operation need separate scores. Same-scope replacement appends a new version and masks the old; cancellation/completion/reinstatement use authenticated legal targets. Never silently reinterpret old scores under a new label convention.

Version-check and stage the complete delta before commit; reject stale or conflicting transactions atomically. Completion requires external evidence, not “the updater thinks we finished.” Journal failure must roll back or poison the session before further work. The audit found that current session state advances before journal append; this is a prerequisite successor repair, not something this report fixes (`results/full-program-review-astra.md:112,122`; `results/HANDOFF-astra.md:107–114`). Persistent source lineage must be carried through every derived memory, including summaries, and replay must preserve it. Untrusted content can still inform ordinary answers without becoming a privileged rule.

### 1 — Frozen trunk proposes; a small fitted model verifies

**What:** keep46's broad clause-capable proposal machinery, improve its proposal coverage separately, and fit an existing clean BGE encoder plus candidate-conditioned head for bindingness. Verify before compiling and applying deltas. Later extend the verifier to complete-operation/target correctness. Do not start with a sentence filter before the trunk. Candidates may eventually come from the improved trunk plus a learned boundary head, but candidate-union recall must be measured;44c+B is evidence against assuming complementary errors automatically produce useful union coverage.

**Why ranked first:**46 already handles cue-less and multi-rule cases substantially better than the small BIO recipe, while44b demonstrates that contextual small-model admission can have high precision on a different bank. Those are complementary clues, not a measured hybrid. Ask-and-Verify provides a direct generator/verifier precedent. The verifier is small enough for CPU and shares one HF snapshot with a byte-identical trunk. Typed guards retain authority and mask-only retirement; no string vetoes are needed. Known risks are candidate-conditioned distribution shift, correlated errors, false rejection of adopted quotes and continued6s mean/15s p95 trunk latency.

**Effort:**6–10 person-hours for original candidate-pair authoring/audit, CPU fit, calibration and saved-record evaluation; another4–8 for complete-operation verification and fresh-bank integration. These are planning estimates, not measured throughput. CPU fit is capped at90 wall-minutes with bounded threads; if a fixed epoch cannot finish, report cost-ineligible rather than choosing a partial checkpoint.

**Quick test1: verifier preservation test, 0.00 GPU-hours.** Fit exactly1,024 original candidate/message pairs plus256 scenario-disjoint DEV pairs, using the existing base `BAAI/bge-small-en-v1.5` (identity: `data/classifier/model/admission-v2/manifest.json:4`) rather than an evaluation-influenced relations checkpoint.
