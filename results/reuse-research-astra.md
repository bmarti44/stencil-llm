# Reuse research for Stencil — 2026-09-06

**Recommendation:** reuse boundary extraction, explicit state transitions, request-time rendering, and evaluation infrastructure. Keep the current router/mask implementation as an experimental actuator. No inspected package already implements Stencil's complete frozen-Qwen SET–HOLD–SWITCH–CLEAR contract, and no inspected pretrained model is a validated automatic standing-rule admission replacement.

The strongest new findings are **GLiNER2.5's small boundary extractor**, **NLSI's explicit distinction between stored and applicable standing instructions**, **Aider's actual reminder and old-output handling code**, **SlopCodeBench's evolving-specification harness**, and **Hugging Face's supported single-repository custom-generation mechanism**. Two apparent shortcuts fail inspection: the original GLiNER2 checkpoint has a short span-width limit, and SteerMoE's code is not permissively licensed for general product reuse.

**Verdicts describe the named reusable unit, not the whole scientific problem:**

- **drop-in:** an existing interface or primitive directly serves that narrow purpose.
- **adapt (<= 1 day):** a bounded prototype or code/schema adaptation is reasonably feasible within one engineer-day; this does **not** promise training, qualification, serving parity, or a passing gate.
- **idea only:** relevant evidence, but substantial work, a scientific mismatch, or unresolved rights/lineage prevents easy reuse.
- **nothing reusable:** no suitable component for the particular requirement was established in this search. This is a search result, not a universal nonexistence claim.

**Local constraints that change the ranking.** [44b](quick-checks/check44b/RESULTS.md) remains NO-GO: span recall 151/207 = 72.95%. Its [review](check44b-review-fable.md) attributes 31 of 56 misses to the sentence candidate boundary; the maximum one-to-one recall available to that splitter was 176/207 = 85.02%. Thus changing the representation of candidate spans is necessary, while semantic admission remains unsolved. [40g](quick-checks/check40g/README.md) is INVALID after JS 3/8, not evidence for SQL/Go. Prompt wording and operands both changed; a stronger Python prior is an interpretation, not an isolated causal finding. The [composition review](composition-design-review-fable.md) requires an oracle-register actuator contrast and realistic token caps. Check42's 151 versus 131 out of 192 is the descriptive coverage view; the frozen common sample was 99 versus 88 out of 124, and the masking result remains NOT CLOSED. Nothing found below licenses reopening stopped dose/neuron searches.

**Data lineage for every prospective reuse:** fit/profile/prompt-development-on = only an independently audited development source, disjoint from evaluation; evaluation-on = fresh author/scenario-disjoint Stencil work or a separately frozen external benchmark. No IFEval, Multi-IF, MultiChallenge, LongMemEval, derivative prompt, recorded response, expert profile derived from an evaluation benchmark, or seen Stencil decision-bank example enters fitting, threshold selection, demonstrations or actuator discovery. Public availability and a permissive license do not establish clean lineage. Under AGENTS.md's broad benchmark prohibition, NLSI/SGD are schema/evaluation references here, not newly authorized training sources.

**Important GLiNER trap:** the [original gliner2-base-v1 config](https://huggingface.co/fastino/gliner2-base-v1/raw/main/config.json) sets max_width = 8. It is not safe to recommend that checkpoint for long instruction clauses merely because it supports NER. GLiNER2.5 avoids that fixed grid, but its candidate caps, encoded-window limit, overlap policy and word-boundary mapping still need representability checks. Changing a pretrained splitter or silently chunking away an adoption phrase could recreate 44b's failure in another form.

**Proposed annotation contract, not borrowed gold:** keep separate fields for (1) exact rule span, (2) exact adoption evidence, (3) lifetime/scope, and (4) relationship to an existing key/version. A quoted rule and the user's endorsement may require separate spans. Whole-message context supplies interpretation; span output supplies multiple distinct rules. Avoid collapsing persistence, source authority and command type into a single sentence label.

**Fit-data answer:** I found plausible auxiliary corpora, but **no externally sourced corpus ready to fit Stencil's complete admission contract immediately with both appropriate labels and verified clean lineage**. The cleanest immediate material remains independently authored development messages with audited offsets. This is a stronger reason to reuse extraction code than to import a memory framework's training mix.

**Unsolved:** none of these packages supplies validated cross-key binding, arbitrary scope intersection, authenticated quote adoption, or exact cancellation/reinstatement recall on Stencil's distribution. Do not replace the existing classifier with an LLM conflict resolver on the strength of a downstream memory QA score. NLSI helps formulate applicability; it does not supply a version-history classifier.

**Concrete Stencil recipe:** at each user request **and tool continuation**, resolve the live register, render applicable exact values near the current task, and preserve the static prefix. I found no primary evidence making “every N turns” universally superior. Stencil's own every-request result is more directly relevant than generic vendor advice. Aider's model-dependent placement is also a reason to preserve the measured Qwen template rather than copy another model's final-system-message syntax.

**What can actually be reused together now:** Transformers retained KV + Stencil's persistent keep-mask + explicit positions + per-session register/provenance state. This is a local inference path, not a claim of cross-request serving prefix-cache support.

A later mask equivalence fixture should compare the real attention consumer to a tiny dense reference at prefill and one-token decode: forbidden-key probability is zero, allowed logits agree within a declared numerical tolerance, and monotonically increasing logical positions survive multiple switches. Never equate zeroing V with masking K/V participation; its key still consumes softmax mass. Nor does masking delete information already mixed into surviving downstream KV.

**Cache-history consequence:** identical token strings and today's bias are insufficient cache keys. A prefix computed under yesterday's bias/mask schedule carries that computation. Reuse only an identical historical computation, or a neutral shared prefix before interventions. Branch/copy state independently. Conservative session salting reduces accidental cross-session reuse but does not implement historical replay. Treat simultaneous router/mask changes and replay reconstruction as scientific interventions, not transparent performance optimizations.

## TOP-3 — Things Brian may not be thinking of

1. **“Select which instruction governs” is already a separate task in NLSI, and often should stay symbolic.** Admission, applicability and actuation need distinct errors and state. An explicit artifact/task binding can choose the applicable rule without any learned task head; a router tensor need not encode arbitrary user constraints. Measure whether it adds anything once symbolic selection has already succeeded.
2. **Some persistent rules can be enforced where actions execute.** A rule such as allowed file scope or a required test receipt can become a small versioned predicate. This prevents a stale action even when the model's next-token behavior drifts. Keep verbal advice in the renderer, but do not spend GPU research budget trying to solve every mechanically checkable obligation through attention. Record attempted and executed violations separately.
3. **Cache state is part of the mechanism's experimental identity, not just infrastructure.** Aider's old-output imitation comment and aLoRA's pre/post-intervention cache distinction point to the same issue: changing a controller does not undo the computation already stored in history. Couple cache provenance to immutable control events and retain durable facts outside maskable bodies. Otherwise a fast cached implementation can silently test a different mechanism from the one that earned the result.
