## 2. The cost model and the constraint that matters

Let H_t be non-render history tokens at request t, and B_i the inserted rule block at request i. Current logical prompt length is approximately `H_t + sum(B_i, i=1..t)`. With constant B and T requests, the rule-block contribution summed over requests is `B*T*(T+1)/2`: **136B at T=16**. A request-local view containing only the current block would contribute **16B**, an **88.235% reduction in the rule component across those requests**, before placeholders and metadata. This is algebra, not a measured runtime saving. At t16 it removes 15/16 of that component. Shortening every block to b reduces growth's coefficient, but does not change its linear growth per prompt or quadratic cumulative token accounting.

Measure five separate things: serialized tokens; logical/maximum RoPE position; visible attention keys; allocated KV bytes; and uncached prefill/latency. They are not interchangeable. Dense masking changes visible keys, normally **not** token count, positions, KV allocation, or dense-kernel work. KV quantization changes bytes, not the instruction count. Prefix caching avoids repeated prefill but leaves history occupying the model's context and decode attention.

The cache premise also needs qualification. A changing block at the **front** invalidates reuse after it. The current renderer already appends its current-user block after unchanged history, so a rule change there does **not** inherently invalidate the preceding history. Re-composing historical blocks moves the first changed token backward and can destroy that advantage. vLLM hashes each block with its parent-prefix hash and only caches full blocks; identical rule text at a different prefix is not automatically reusable as the same KV. [vLLM prefix-cache design](https://docs.vllm.ai/en/stable/design/prefix_caching/).

A semantic retirement mask, a prompt-view mask, an attention mask and physical KV eviction must have different names in an implementation. Keep immutable source events, original transcript, versions and retirement links. Select renderer-owned intervals by recorded offsets/IDs from construction, never by searching for “Active rules,” instruction words, or copied substrings. Tokenizing components separately is not necessarily equivalent to tokenizing the final concatenation; verify boundaries through the actual tokenizer consumer. Current obligations remain complete and recent on **every user request and tool continuation**, including HOLD, defaults after CLEAR, and turns with no state change.

A delta such as “unchanged,” a checksum, or `r7=v2` without accessible meaning does not satisfy that semantic requirement. A complete compact digest can; the delta is then optional emphasis. An immutable prefix dictionary plus current bindings is possible for closed typed enums, but requires testing whether prefix definitions plus recent pointers preserve behavior. It cannot encode arbitrary new natural-language obligations using unexplained IDs. Moving full definitions to a dictionary is not lossless *for the model* merely because host code can invert it.

### 2 — Mask obsolete renderer-owned intervals; skip them only with a verified sparse backend

**What:** At the next request, turn off attention to prior **generated rule-block intervals**, leaving the current block fully visible at its existing position. Record interval ownership when constructing the prompt. Do not mask user instructions, tool facts, assistant answers, headers or EOS. Preserve original token IDs/absolute positions and the append-only register/journal. The first stage is the40i-style dense causal-AND-keep mask; the second is a block-sparse attention implementation that skips wholly masked blocks without deleting retained tokens or KV. Its goal is reduced attention work with the same mask semantics, not an invented logical-context reduction.

**Evidence/fit:**16 copies/34.7% in pilot7 is an exact target;40i supplies a position-preserving mask precedent, but **on different intervals**. HF supports custom attention/mask interfaces; no integrated sparse Qwen result was verified. Frozen trunk and one-snapshot packaging remain possible because this is code/kernel policy, not training. Recomposition by replacing all historical blocks with today's rules is inferior as a first experiment: it adds anachronistic instructions, rewrites a large prefix, and contradicts the retained decoder contract.

**Effort:** **8–12hours** for interval ownership and dense-mask behavioral prototype; **24–40 additional hours** to integrate/audit sparse skipping and cache semantics; independent bank2–4hours. Risks: downstream KV already contains old-rule traces; masks cannot promise complete forgetting. Partial blocks may give little speedup, and sparse kernels can lose more efficiency than they save. Mask/position policy must be part of cache identity; token-only shared caching is insufficient if representations were computed under different masks. Keep prefix KV computed under its original causal history and apply the new visibility policy prospectively; do not call that a re-composed-history recomputation. Stock retained decoding is a starting point, not an implementation of this policy.

## Verdict for Brian

We can probably make rendering substantially cheaper with what we have, without giving up a fresh rule reminder on every request. The strongest evidence is that we were retaining repeated verbose representations, and the first trim already halved the rule-block component—not the whole context. The single cheapest next experiment is a **CPU-only,35-fixture comparison of today's renderer against one complete compact representation**, with a fixed40% block-saving threshold and exact state-preservation checks. If it clears that bar, spend at most0.75GPU-hour on a fresh independent lifecycle bank after the protected run. Masking old copies is a plausible second step, but ordinary masks do not free context space, and quantized KV only saves memory. We do not yet have a demonstrated way to keep an arbitrarily long, position-preserved transcript inside a fixed logical context window; no gist-token paper or caching feature changes that fact for free.
