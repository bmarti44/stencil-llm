## Fixed experiment

Four complete original Python projects, each with two task handles, an untouched finished helper, three target functions, and six dependent edits. Each submitted function takes one JSON value and returns a JSON value, using ordinary computational builtins. This permits reuse of the existing isolated CPython/seccomp executor. Narrow runtime scope is a feasibility limit; it does not redefine the full goal around Python functions.

Three arms: H receives ordinary retained natural history and its own current code; C receives the same information plus the current instruction to recap the applicable obligations before coding; M receives the same information plus an independently correct manual prose reminder for this request. H/C/M are content-controlled comparators, not three differently constrained submission protocols. All arms may have prose before the single code fence; any incidental H/M prose is recorded. M's reminder is ephemeral, and no M oracle text enters H or C.

Exactly72single-attempt calls. Fixed order: episode order, then chronological round0–5, then H/C/M. Each `(episode,arm)` has its own cumulative actual module and canonical native-role transcript. Append the same natural source messages and request to all three transcripts. Each outgoing message view adds only that arm's current ephemeral instruction/reminder and actual workspace content. After a valid submission, canonical assistant history receives only the exact extracted code fence, without regenerating formatting. Comments within submitted code remain part of that actual artifact; the discarded field is the prose prefix outside the fence, not every possible rule-related string inside code. A failed response remains in raw receipts; no fabricated assistant code is appended. There is no test feedback, retry, syntax repair, gold state reset or cross-arm sharing. Valid code is retained even if tests fail, so later edits operate on actual accumulated work.

The native HTTP request uses genuine message roles. Only user sources establish standing rules; non-user statements require explicit user adoption. Source IDs/roles/content and current task/target are authenticated fixture inputs, not model-generated authority. Oracle metadata, reference patches, expected checks, mutants, retired-rule labels and reviewer notes never enter worker prompts. M alone receives the author-prepared current manual recap. Future messages are inaccessible. This first screen covers user/assistant sources and quotation/adoption; it does not claim coverage of arbitrary tool/API traces.

## Submission and executable checks

One complete column-zero Python definition of the requested target function inside exactly one Python code fence. Accept the same surrounding prose structure in all arms. Require a single undecorated synchronous function, the exact target symbol/path and one argument. Preserve indentation and code bytes; never dedent, anchor an indented def, synthesize a fence/trailer, or repair syntax. Replace only that function using AST source extents. Parse/shape/syntax/cap/transport failure leaves the previous module unchanged and counts as failure or incomplete evidence as specified below. A shape-valid patch is applied once even when subsequent checks fail.

For each round, run all initial helper checks and cumulative stable functional checks through that round, plus only the CURRENT round's obligation checks. This avoids imposing retired conventions retroactively. Every check runs in a fresh isolated Python process. Expected values are complete JSON alternatives with type-sensitive equality; a permission can allow more than one valid result. Scores come from executed behavior, not string matching the model's recap.

Before worker inference, every Kimi reference patch and mutant must pass through the SAME fenced-response parser, shape checks, AST splice, and sandbox consumer as the eventual model output. All cumulative reference states must pass all active checks. Each mutant must fail every named discriminating check; obligation mutants must retain all active original/functional behavior. Record every failure by episode/round/check ID. Correct or clarify flawed data only through separately preserved Kimi patches, followed by independent re-review before freeze. Do not change data after seeing worker responses.

CPU guards must exercise failures through the actual consumer: malformed/indented/extra-function output, unchanged state on failure, persistence of a valid-but-wrong patch, source/oracle separation, no recap persistence, independent arm histories, timeout/length/surrogate/raw-byte preservation, and partial72call accounting. No full repository test suite is required.
