# Research reset after the coding self-cue failure

2026-09-08. Parent synthesis of two native **Astra xhigh** research lanes and
primary-source checks. The decision is to **qualify a competent coding worker
with a small edit/execute loop before spending on another automatic selector**.
A separately trained, source-grounded interpreter is the conditional next
mechanism. Its feasibility and training cost are not established. This report
selects preparation work; it is not an inference or training launch registration.

The [completed screen](../../quick-checks/coding-self-cue-01/RESULTS.md), archived
at `27dc06b8`, gave automatic recaps 2/24 passing coding steps, correct manual
reminders 12/24, and ordinary history 10/24. Every arm failed to complete all
steps of any project. Four output caps make technical evidence incomplete;
other completed responses contain definite failures. The manual control was
not competent enough to support a useful parity comparison. Recurrent updater,
disposable source reader and same-response recap recipes remain parked.

Brian's target remains automatic maintenance that can match competent manual
prose at an acceptable quality/cost tradeoff. Representation superiority is
unnecessary. A competent manual control is a prerequisite, not a substitute for
automation or for fresh, adequately sized executable validation.

The bounded research covered two gaps: learned or compiled handling of changing
instructions, and coding-agent competence with execution feedback. The table is
the claim/source ledger. Results are author-reported, not local replications;
confidence is high in the stated methods and narrower than their transfer here.
All links were accessed 2026-09-08. No benchmark task banks were acquired for use.

A source-check correction matters: an initial research note said VerIH lacked
multi-turn evaluation. Version 5 explicitly contains that experiment. The
reviewer confirmed the correction above. The remaining transfer gap is our
specific lifecycle and proposed training method, not multi-turn work in general.

**The next prerequisite is a small, fresh M-only competence screen.** Prepare
four independently Kimi-authored projects, each with three connected work
requests operating on actual accumulated code. Begin with a working helper;
subsequent features must use real dependencies and preserve earlier behavior.
Keep meaningful type, scope, ordering and integration requirements. This shorter
prerequisite is not a replacement for long-trajectory focus validation.

Use one transactional edit action with a compile guard, sandboxed execution
of fixed public functional checks, and concise factual tool observations.
Allow at most three candidate edits per request, including the initial one:
12 work items, at most 36 model calls. Every attempted correction consumes this
budget. Preserve each actual artifact and response; no oracle reset. M receives
only independently correct current prose reminders, with no automatic recap
stage. All final scoring is independent and private. A native tool protocol or
other exact action interface must be selected and frozen before worker output;
this is a new environment, not retroactive acceptance of old Markdown output.

Public checks are development aids. Private expected values, rule annotations,
scorer results and heldout obligation cases never reach the worker, including
through repair observations or stopping decisions. Separate public and private
authoring/review; do not make self-generated tests the acceptance oracle.
End each request by the frozen public-only policy or the action limit, then
score the final actual artifact once privately. Include direct-source review
and verify dependency use where required. A parser or compile rejection may
be repaired within the fixed action budget; it must remain counted and visible.

Prospective competence eligibility: all 12 final work items and all four
projects satisfy their private functional/obligation checks and independent
source review, with complete resource accounting and zero human correction.
Final parse, capacity or transport failure does not count as success. This
strict nonstatistical prerequisite can reject an operating point; four perfect
projects still cannot establish general reliability. Failure parks this
worker/environment point. It does not earn more calls, an easier bank or another
prompt on these cases. Success admits preparation of the distinct interpreter;
it establishes no automatic-focus benefit by itself.

An illustrative resource calculation, not a measured new-loop guarantee:
36 calls × 1,024 output tokens / 22.83897 observed whole-HTTP completion
tokens/second + 600 startup + 120 execution + 60 cleanup = **2,394.08 seconds**.
The observed rate is 26,922 / 1,178.774697 from the prior code workload. A
2,700-second ceiling would leave only 305.92 seconds of this extrapolated
margin. New tool parsing, prefill and execution costs must be sized before
freezing. The output limit is provisional: independently correct native actions
must have adequate measured headroom. Do not simplify tasks to force a cap.
The standing 3,600-second maximum is not permission to assume capacity or launch
without accepted data, implementation and resource checks.

**Conditional focus mechanism: learn the interpretation, retain its sources.**
A small supervised interpreter trained on wholly new Kimi conversations is
materially different from asking the unchanged worker to summarize again.
The initial output should remain small: complete current applicable prose with
per-obligation source-message references, rather than a new general policy language. Retain
raw authentic source events; current generated notes must not silently become
authoritative facts. Deterministic validation can verify shape and that source
references exist, but cannot prove the interpretation is correct or complete.
Separately measure semantic omissions, wrong scope, modality, adoption and
retired-rule influence. Incorrect citations do not become evidence merely
because their IDs parse.

Training is conditional, not yet scheduled. A clean data-lineage statement,
whole-conversation split, independent semantic label review, one fixed training
recipe, an unchanged-base comparison and a costed local pilot are needed first.
Use no existing evaluation-derived training rows, spent coding cases or old
adapters as an assumed clean starting point. Do not assume that a few examples
or cheap SFT reproduce verifier-reward training. If local sizing or data quality
fails, reject this proposal before the costly run. A many-agent critic tree or
Rego compiler adds unsupported machinery at this stage.

After competence and interpreter feasibility, compare automatic selection,
manual prose and ordinary history with the same worker, tool access, public
feedback, action budget and code visibility. The automatic arm receives no
manual label or private scorer feedback. A fresh larger registration must set
whole-project outcomes, absolute usefulness, an acceptable loss margin versus
manual prose, episode-level sample size/statistical tests, and measured total
cost. Nonsignificance is not parity. Preauthored manual reminders do not measure
a real person's time saved. No success claim is earned until that evidence exists.
