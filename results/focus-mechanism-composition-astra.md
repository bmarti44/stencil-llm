# Full generalized focus mechanism: composition design, 2026-09-06

**Decision:** build an extensible obligation register with a separately certified skill actuator. The register decides what applies; the router selects an available output family; masking reduces imitation of outputs from retired skill epochs. This is a complete proposed control loop, not a demonstrated universal skill mechanism. Its decisive unanswered question is whether routing plus masking improves executable work when the same live obligations are already rendered correctly.

Evidence boundaries matter. [40c](quick-checks/check40c/README.md) reached JS 32/32 with zero parser breakage at exploratory alpha3; [40i and its review](check40i-review-fable.md) support the Z schedule on arithmetic syntax: BACK 23/24, SWITCH/CLEAR 24/24, zero breakage, matching 40h-Z's second seed. HOLD retains biased KV and visible answers; maintenance by bias alone is not isolated. [43b](quick-checks/check43b/README.md) **closed the concept-routing avenue after PRODUCT 0/8**, and [41/41b](quick-checks/check41b/README.md) did not establish reliable dense-neuron control. “Closed” there means stopped, not solved.

The latest [FOCUS-3 diagnostic review](focus3-diag-review-fable.md) reports O 63/64, C 57/64, N 29/64, T 31/64; use these instead of the brief's O 61/64. It remains an ineligible diagnostic: C register-exact 38/64, with supersede misses as well as admission errors. [Check42's review](check42-review-fable.md) supports every-request rendering 151/192 versus recap 131/192 and documents masking's fact/constraint damage. No composition result exists.

Research-only work: CPU arithmetic and source/document reads; no model, signal, benchmark input or sealed file. Root PLAN/PROTOCOL are archived; only this requested report is written. During research, [44b's saved summary](quick-checks/check44b/summary.json) became available: **NO-GO**, overlap precision 151/152=99.34%, recall 151/207=72.95% against the 85% bar; setup false-admission turns 2/96 and request-template errors 0/96. This is the run's reported result, not an independent review. Explicit entry remains the shipping path. **1. The composed loop, including failure behavior.**

State per sequence: `FocusCache = {KV, absolute_positions, register_versions, task_table, active_task, skill_epoch, output_provenance, persistent_key_mask, artifact_refs, execution_fingerprint}`. A rule stores exact source role/message/span, authority, stable key, scope, request kind, value/text, version, status and transition evidence. A task has a family field and lifecycle; obligations such as tags or “no dependencies” are separate keys. Artifact references identify actual files/tool results, not invented summaries. Defaults are typed configuration, never classifier admissions.

The public custom `generate(new_messages, focus_cache, ...)` performs steps A–H once, calling the trunk decoder once. Each tool continuation is another request and repeats rendering. Classifiers are small CPU heads, not extra trunk generations. External tools execute through the caller's normal executor; the HF package does not silently add an autonomous shell loop.

Ship one HF repository: frozen trunk shards, custom model/generation/cache/renderer code, separate classifier `.safetensors` files, profile tensors and a versioned configuration/lineage manifest. Pin tokenizer, dependency/backend versions, thresholds and supported cache operations; validate model/profile compatibility on load. The semantic register survives independently of KV storage. Plain weights without the custom generation path do not implement focus.

- **A — Admission.** Authenticate roles and exact source spans. Only direct/adopted user instructions or authorized structured entries can create user rules; quoted text, code, payloads and tool/assistant content cannot acquire authority by being copied. Automatic mode uses the frozen, eligible message/candidate head with its actual tokenizer, threshold and overflow policy; deployment starts with explicit `{action,key,scope,kind,value,target_version?}` entry until admission qualifies. Structured entries still undergo scope, precedence and target validation. Invalid/ambiguous entries make no state change and return an abstention reason.
- Admission controls **new persistent rules**, not all transitions: “cancel that rule” need not itself be a standing rule. Forward authenticated user change candidates, including admission-negative cancellation/completion/reinstatement sentences, to B. A current one-shot request remains visible to the trunk and can establish a request-local task/family overlay without becoming a standing rule.
- **B — Relations.** Score each candidate against eligible existing versions using the frozen supersedes/cancels/completes/reinstates/none classifier and its DEV-calibrated thresholds. Bind to an exact key, target version and overlapping scope. Supersedes atomically retires/shadows the targeted portion and admits its replacement; cancels retires; completes retires the named obligation/task scope; reinstates creates a new version carrying the identified prior content. Explicit structured actions determine their operation, rather than being vetoed by a contradictory classifier guess. Tool success alone never completes a standing instruction unless an explicit rule registered that completion condition.
- `none`, low confidence, ambiguous target, unsupported scope/key, conflicting proposals, truncation or malformed evidence means **no speculative mutation**. A rejected transition cannot fall through into admission beside its target. Stage changes, validate, then commit atomically and idempotently by message/event ID; successful admission is not evidence of successful relation resolution. An unresolved conflict also disables actuation for the affected scope on this request.
- **C — Precedence.** First authority; then applicable request/task/global scope, with narrower exceptions shadowing only their intersection; then explicitly validated replacement/version order for the same key. Preserve independent keys together. Do not use “latest sentence wins” across unrelated rules. Two equally authoritative incompatible proposals with no resolved replacement abort the conflicting transaction. Cancellation reveals a surviving applicable broader rule, otherwise the configured default; completion does not globally erase preferences. Switching suspends task applicability; returning restores live rules, never automatically uncancels retired ones. This generalized scope policy extends the current sort-specific consumer and needs its own fixtures.
- **D — TASK TYPE.** Resolve the current artifact/task from the direct request, explicit task handle or unambiguous tool-call continuation; then read **that task's effective family field after precedence**. Example: JS for task A + SQL for task B + global JSON output + “no dependencies”: an edit to B selects SQL; JSON and dependency rules remain rendered obligations, never votes for another router. A clear one-response family exception applies only to this request; a standing change updates the task field only through A–C.
- The task-type head takes `(current request, candidate task/artifact bindings, applicable rule values, requested action kind)` and predicts `(task_id, family_id, confidence, unknown/mixed)`. Task IDs are pointers over the current task table, not a fixed vocabulary; create NEW only with an explicit new-task binding. Explicit validated bindings win; otherwise accept only a DEV-calibrated prediction consistent with live rules. Never infer the desired family from the model's previous answer, from gold events, or by majority of live rules. Unresolved scope, simultaneous incompatible families, OOD, low margin or missing profile means bias **OFF**. Mixed-language output gets rendering only until a composite family is separately certified; no vector addition or hidden second generation.
- Keep **desired family**, **bias state**, and **epoch** distinct. Default means natural OFF behavior for the registered request class, not “Python everywhere”; only the arithmetic default was measured. Neutral/non-code/tool-control requests keep the task's desired family but use OFF. A confident semantic family change or explicit CLEAR opens a new skill epoch, even when both old/new families use OFF. A classifier abstention merely turns the actuator off for this request; it does not fabricate CLEAR or authorize new masks.
- **E — Render.** Put all applicable live obligations, including family and explicit defaults, inside the current request on **every** generation, including tool continuations. Match schema/format rules to the request kind; never demand a task's JSON result schema on an unrelated prose/tool turn. Include verbatim values and provenance-linked task/fact references; exclude retired rules. The live register, not an appended history of all rules, supplies this block. Family cues are rendered in the composed arm too; withholding them to manufacture a bias advantage is forbidden.
- **F — Actuate and mask, before prefill.** Look up the frozen profile and certified transition edge for the resolved task family. Enter/re-enter a supported non-default family with its sustained bias plus the epoch mask; return to a certified default with bias OFF plus mask. HOLD preserves the mask and applies the same profile on relevant generation requests. Unsupported edges use rendering only; do not silently perform a two-generation detour through default. No negated-JS “Python profile.”
- Apply `z' = z + b_family[layer]` to raw router logits, then recompute the actual float32 softmax/top-k/normalization and expert-consumer weights/indices. Touch every newly processed prefill and decode position, including closure processing, as the tested hook does; never recompute old KV under the new bias. OFF returns the unmodified router result. Pin the interpreter/model/backend and assert the tuple contract: [40b's review](check40b-review-fable.md) found incompatible installed router APIs. A metadata-only logit edit is not an actuator.
- On a confirmed epoch change, add all earlier **maskable assistant skill-output bodies** to the persistent key mask, including failed code/fences; preserve headers, closures and absolute positions. Masks accumulate: BACK restores the rule/profile, not old output visibility. Never mask user instructions, tool observations, current requests or durable facts merely because their timestamps fall in an old epoch. Only typed code/tool-output spans qualify; free prose stays visible. Durable artifacts and exact tool-confirmed facts live outside those spans; future relevance is never predicted by a salience head. If a body contains an unresolved needed fact, keep it and disable that transition's bias/mask pair; use rendering only and record the fallback.
- This fact-preserving policy is a **new extension** of 40i's whole-code-body mask, requiring validation. Store tool-confirmed work in the workspace/artifact store; carry exact durable facts separately with their sources. A requested old file can be read again through a tool, tagged as task data, not an active instruction. Old tool outputs can still imitate a prior language, and surviving downstream KV can still carry masked information. Masking is neither forgetting nor undoing an already executed stale action.
- **G — Generate once.** Install the resolved mask/bias before the first forward, invoke one bounded decoder run, then restore hooks in `finally`. Return the actual reply/tool call and updated cache. No answer selection, self-grading, retry-until-correct or silent bias-off regeneration. EOS, truncation and errors are recorded literally; invalid/truncated tool calls are not executed by the normal tool validator. Runtime nonfinite values or cache invariants terminate the call as failed, never trigger an unreported rescue.
- **H — Tag and persist.** Tag every emitted body/span with task, desired family, actual bias/profile hash, skill epoch, rendered rule-version IDs, role, absolute token interval and completion status. Tag tool results with their call/artifact provenance and non-instruction authority. Final-token/EOS forwarding must agree with cache length; unforwarded output tokens still have logical positions and are forwarded once on resume. Serialize register, provenance and masks with the cache, and deep-fork all state when branching sequences; never leave mutable bias/register state shared across requests.

Mask implementation: start with the actual 40i path, a persistent 2D keep mask on every forward with explicit monotonically increasing RoPE positions; masked columns remain allocated. A serving 4D additive mask must use `0` for allowed attention and `-inf` for forbidden past keys, combined with causality. Zeroing V is not eviction: its key still consumes softmax mass. HF documents combined past/current mask lengths and backend mask conventions ([cache](https://huggingface.co/docs/transformers/main/en/cache_explanation), [attention](https://huggingface.co/docs/transformers/main/en/attention_interface)); equivalence with this modified serving path is a test obligation, not an existing result.

Prefix caching: append the new rendered block; do not rewrite an already cached prefix. Reuse KV only for identical tokens, positions, model/backend and the **historical bias/mask schedule that produced it**, with independent per-session state. A text hash or current-family hash alone is insufficient. Initially disable cross-session prefix sharing after the neutral common prefix. Cache loss/reload must replay logged historical render/bias/mask events; rebuilding the whole transcript under today's bias is a different intervention. Unsupported cache implementations fail to ordinary fresh rendering before generation; no arbitrary sliding eviction or implicit rule deletion on overflow.

Fail-safe contract: admission/relation abstain preserves previously validated state; task/actuator abstain preserves text and uses OFF with no newly authorized mask; rendering overflow or irrecoverable state corruption returns an explicit unsupported/error result rather than silently dropping obligations. “Today's behavior” means ordinary generation with known applicable instructions, **not** a guarantee that uncertain instructions are followed. No new mask, retirement, profile learning or automatic tool execution is justified by abstention.

**2. Profile library: automatic extraction with bounded certification.**

Each entry is `{family definition, trunk/tokenizer/router hashes, donor lineage, position rule, statistic, layer band, bias tensor, dose, cue template, DEV thresholds, competence/transition certificates, supported request kinds}`. Profiles are checkpoint-specific measurements, not universal expert IDs. Preserve the validated JS tensor unchanged; new extraction is a registered successor recipe. An explicit user family name can nominate a candidate, never enable an unvalidated tensor.

Data lineage, before any fitting/brief: **profile-on** = 16 independently authored paired development problems cued as family f and a fixed reference; **select-on** = eight separate development problems; **certify-on** = fresh 24-problem transfer/transition bank; **larger-test-on** = fresh repositories/episodes, disjoint authors/templates/problems from all three and all classifier fitting. No evaluation benchmark or recorded response to it may enter any stage. A handful of examples can estimate a candidate direction; it cannot certify a family.

Use the same underlying problem under both cues when semantically possible. For families without a valid paired reference, author matched task distributions and mark the weaker identification; do not pretend unlike problems differ only in family. Generate all donor replies once, save all, and require cued executable competence >=14/16 in both families; never retain only successful donors. Collect raw per-layer router logits at each generated non-EOS token's **own** teacher-forced position, including the last token, excluding prompt/EOS. This measures routing conditioned on the emitted token, not causality at the position that chose it. Keep the final-prompt/first-eight-prediction signatures as diagnostics, not another selectable actuator.

Proposed statistic: `mu_f[l] = mean_i(mean_t C(z_f,i,t[l]))`, `d_f[l] = (mu_f[l] - mu_ref[l])/2`, where `C` subtracts the across-expert mean. Weight examples equally to prevent verbose donors dominating. Separately save `a_f[l,e] = mean_i mean_t 1{e in top-k}` and routing-weight means; use `a_f-a_ref` to diagnose whether the logit contrast changes expert selection. Do not replace the proven raw-logit actuator with hard expert forcing in this first composition.

Why this statistic: [SteerMoE, Fayyaz et al., 2025/ICLR2026](https://arxiv.org/html/2509.09660v2) detects behavior-associated experts through paired activation-frequency differences. [Bandarkar et al., 2025/ICLR2026](https://arxiv.org/html/2510.04694v2) averages per-sequence top-k activation proportions against a baseline and finds layer-sensitive steering. These support contrastive, length-balanced measurement and dispatch audits; they do not validate our logit-mean recipe or provide permission to profile on evaluation responses.

Norm matching: start with all 48 layers, preserving the language recipe. For band S, `b_f[S] = s * ||b_JS,alpha3[S]||_F * d_f[S]/||d_f[S]||_F`, zero elsewhere; DEV doses only `s in {2/3,1}`. Full-band reference norm is 15.659565; on layers 7–34 it is 10.208735, with alpha2 reference 6.805823 ([43b magnitude audit](quick-checks/check43b/README.md)). Never compare a middle-band norm with a full-model norm. Quantize once to runtime dtype and save actual norms/maxima.

Reject zero/nonfinite directions, fixed split-half cosine<0.5, or a dose exceeding 1.5× the JS-alpha3 per-layer norm or maximum-coordinate envelope; do not amplify noise indefinitely or repair by screen-dependent clipping. These are proposed conservative DEV gates, not proven safety bounds. Choose the lowest dose with >=7/8 executable target replies and zero breakage on DEV, then freeze it; if neither qualifies, disable the family. Norm equality controls magnitude, not behavioral sensitivity; 43b changed dispatch strongly without selecting PRODUCT.

Certification per family: fresh uncued executable tasks, correct bias / OFF / stable within-layer expert permutation / text cue; require correct target+execution>=20/24, breakage<=2/24, shuffled target<=4/24, plus exact paired correct-vs-shuffled superiority with Holm familywise alpha=.05 across the nominated families. Keep one permutation fixed across the entire episode with the identical ON/OFF schedule and per-layer norms. Require shuffled-vs-OFF target increase<=2/24 and breakage increase<=1/24, reporting paired counts/intervals. “Control does nothing” means no meaningful target induction under these bars, not identical strings or proof of zero effect. Do not search for a benign shuffle.

Then certify Z SET/HOLD/switch/BACK/CLEAR and real paired releases against OFF+mask and shuffled+mask at BACK, on fresh transitions; use 40i's 20/2/4 bars and executable checks. A family profile and a source→target transition certificate are different objects. JS→Go cannot inherit Go↔default certification. Uncertified transitions use rendering only. This prevents a growing library from silently claiming every pairwise composition; certify only edges the application needs.

Discovery: begin with a small **user-declared taxonomy** (code language/output family), not unsupervised names for arbitrary clusters. Offline, cluster per-example baseline-subtracted routing signatures using cosine distance, retaining early/middle/late blocks separately and equal task weights; assess fixed split stability and separation across paraphrases, identifiers and problem types. Clusters may suggest merging aliases or testing a new subfamily. They become library entries only after an operational definition, cue, executable checker and intervention certificate exist.

[Chen et al., 2026](https://arxiv.org/html/2601.14050v1) find natural-language family structure and shared middle-layer routing: motivation for multiscale signature clustering, not evidence that programming skills form the same clusters. [Wang et al., ACL2026](https://arxiv.org/abs/2601.03425) find domain-invariant expert coalitions, so high routing similarity can reflect shared computation. Baseline subtraction and causal certification are essential; cluster purity alone never establishes a skill address.

The task-type classifier is a small encoder/head over request plus effective task/rule fields, trained only on independent labeled development messages with tool/quote negatives, multiple live tasks, one-shot exceptions and unknown families. Freeze whole-domain DEV splits, thresholds and a top1–top2 margin before evaluation; target <=2% false family assignments on DEV while reporting coverage. Require both semantic classification and an available certified profile/edge. Unknown/mixed/overflow => OFF, normal rendering; no nearest-profile substitution, interpolation, online clustering or fitting from the current episode. Its task binding/key generalization remains an open component beyond admission 44b.

**4. Adequate proof on a larger implementation — proposed registration, not a launched run.**

Use the actual frozen Qwen3-30B-A3B HF package/cache/renderer/hook stack. Author **64 fresh independent small repositories/episodes**, 48 with 16 and 16 with 32 **generation rounds** (a request plus one assistant generation; tool observations do not inflate the count). Each has 2–3 task switches, 1–2 instruction overrides, a return to an earlier task, delayed unrefreshed continuations and actual read/edit/test tool outputs. Four coding domains × 16 episodes; balance language transitions, cancellation/completion/reinstatement and unknown-family/neutral interruptions. Domains might be data transforms, validators, small state machines and query/report utilities; avoid another arithmetic template bank.

Eligibility comes first: 44b's current NO-GO does not license unattended admission or a confirmatory PASS run. The design below is ready for an independently qualified, frozen automatic candidate; without one, stop before the larger bank or explicitly register a diagnostic with no PASS label. An explicit-entry demonstration can proceed separately but cannot satisfy the classifier-driven claim. Do not turn 44b's high precision into a recall waiver.

Use real multi-file artifacts and dependencies between rounds: later edits must use a tool-discovered fact, a preserved user requirement and a prior artifact's interface. Include mixed-language repositories, misleading quoted/tool instructions, temporary format exceptions and incomplete work after a switch. Requests name artifacts naturally; no hidden gold task binding enters C/R. The agent chooses its tool/actions and repair edits; a frozen environment supplies milestones/change messages at fixed rounds and returns actual tool results. Histories and workspaces diverge by arm, with no forced successful prefixes, shared generated answers or replay of another arm's tool results.

Keep actions small enough for a single GPU: ordinary compact read/replace/test calls, pre-existing file scaffolds, at most 64 generated tokens/call, total 512 tokens per 16-round episode or 768 per 32-round episode, all arms equal. This tests sustained coding control over many small edits, not unrestricted software engineering. Capped/invalid generations stay failures and in history; reaching an episode token cap fails that episode, records remaining rounds as unexecuted failures, and never removes its denominator. Tool observations use a fixed bounded schema/excerpt policy, identical across arms, with artifact refs for omitted data; no gold-aware context pruning.

| Arm | What actually differs |
|---|---|
| C: composed, classifier-driven | Frozen admission, relations and task-type decisions; register/render + certified router/mask policy, including every abstention. No structured/gold substitution after a classifier miss. |
| O: oracle-driven | Gold admission/relations/task-family events replace those decisions; otherwise identical renderer, profiles, masks, caps and tools. No gold solutions, code, test answers or successful tool outcomes. |
| R: rendering-only | Same frozen classifiers/register/renderer as C, but bias OFF and no skill masks. Decisions operate on its own divergent history; do not replay C's trace. |
| N: nothing | Normal complete conversation and the same tool/workspace interface, no extra register recap, bias or mask. |
| T: text-restate | Correct current obligations/family/default explicitly restated on every applicable request from an evaluator-authored schedule; no persistent register, bias or masks. This strong oracle-text comparator gets no solutions. It is deliberately stronger than FOCUS-3's append-all-ever-stated T. |

Executable endpoints, with episode as statistical unit: **final success** = final hidden integration tests plus all still-live obligations; **stale execution** = any actual edit/tool action implementing a retired obligation on prewritten discriminating witnesses, even if later repaired; **wrong skill** = any generated code in the wrong requested family, checked by parser/compiler plus task context, never fence label alone; **breakage** = any malformed tool call, invalid program where a complete program is required, empty/repetitive/capped generation or unintended workspace damage. Preserve separate syntax, semantic-test, tool-protocol, fact-loss and resource-failure counts. Count failed attempted stale calls separately from executed ones.

Cost: all generated/prefill tokens, classifier latency, cold load, p50/p95 round latency, CPU tool time, peak memory, masked columns, GPU-held wall time, and cost per successful episode. Record register/event accuracy, false admits/retirements, task-binding/family errors, fallback coverage and masked-fact probes diagnostically; they cannot substitute for working artifacts. Failed tests do not reveal hidden checker internals to the agent.

Statistics: two primary one-sided exact McNemar tests on paired final success, **C>R and C>N, alpha=.025 each** (Bonferroni family .05); report paired differences and confidence intervals for every arm. Other endpoint contrasts and O/T gaps are descriptive, not extra uncorrected discoveries. Randomize execution order within each episode block, pin greedy decoding and all seeds, and never count rounds as independent samples.

Power recomputed here by exact enumeration: for N=64, candidate-only/reference-only success probabilities (.25,.05), delta 20 points and discordance 30%, power **82.69%** per primary comparison; (.30,.05), delta 25 points =>**93.56%**; (.20,.05), delta 15 points =>**61.80%**; (.15,.05), delta 10 points =>**33.40%**. Formula: sum over `M~Bin(N,p10+p01)` of `P[Bin(M,p10/(p10+p01)) >= k(M)]`, where `P[Bin(M,.5)>=k(M)]<=.025`. Joint power depends on arm correlation; if both marginal powers are 82.69%, its lower bound is 65.38%, not 83%. Repeated templates would invalidate the independent-episode calculation. This is powered for a large benefit, not a subtle one.

Prewritten **PASS**, all required: completed planned episode accounting; O final>=48/64; C final>=48/64; both primary tests pass and each observed gain>=8/64; C final no more than 4/64 below O or T; C stale and wrong-skill counts each<=4/64 and no higher than R; C breakage<=2/64 and no more than one episode above R; zero silent state/cache/provenance failures; total GPU allocation<=6h. These O/T/error margins are practical acceptance bars, not equivalence or noninferiority proofs. Even 0/64 breakage gives a one-sided 95% upper bound 4.57%, not zero population risk.

Reading in advance: C beats N but not R => useful register, **no demonstrated incremental skill actuator**; cut actuator from default shipping. O beats T but C misses => perception/state binding is the bottleneck. O and T show no separation => no demonstrated benefit of the internal lever over correct current text at this resolution. O itself below 48/64 => report INELIGIBLE competence/integration ceiling, preserving C's results without retuning. A complete unmet conjunction is FAIL; missing work/global budget stop is INCOMPLETE; cap failures within completed episode accounting are failures, not exclusions. No failed-run rescue or pooling a new bank into this test.

GPU feasibility: 64 × five arms yields `5*(48*16+16*32)=6,400` maximum calls and `5*(48*512+16*768)=184,320` maximum output tokens. [40i](quick-checks/check40i/README.md) measured 21.99 GPU-min for 480 actual generations including load, not the 9 minutes in an earlier brief. Using 15 decode tokens/s, **assumed** 0.3s additional prefill/classifier/tool-held overhead/call, 2,700s for load/profile qualification/pilot and 25% evaluation reserve gives `2700+1.25*(184320/15+6400*.3)=20,460s=5.68h`. Longer-history throughput is unmeasured; this is a conditional budget, not a promise.

Before opening evaluation episodes, run disjoint 16/32-round DEV cost/competence pilots on the finished package and include all auxiliary GPU work in that 2,700s allowance. Author/train small heads on CPU; reuse qualified profiles where possible. Replace the throughput/overhead assumptions with measured conservative full-episode costs including tools, masks and cache resumes. If projection exceeds 21,600s, **do not launch or shrink N**; report the 6h design infeasible. Check deadlines cooperatively before forwards/new calls, reserve cleanup, preserve records, never signal. No process/model is launched as part of this report.

Register before evaluation: disjoint data/author/template lineage; episode authoring/sampling algorithm and seeds; all 64 manifests, initial repositories and hidden executable checkers; event oracle and discriminator witnesses; exact arms/T semantics; classifier/checkpoint/threshold hashes; profile/dose/edge certificates; precedence/default/render rules; provenance and fact-preserving mask policy; token/tool/time limits; power assumptions/tests/PASS reading; artifact writer fields and exclusion policy. Freeze implementation and models before authors' final evaluation content is opened; no training, selection or prompt repair from it.

Journal in the same run: raw/rendered input and token IDs, classifier inputs/scores/decisions, before/after registers, task/family/epoch, actual bias and mask/position traces, output IDs/EOS/status, tool call/result and artifact hashes, gold events/checker outcomes, timing/tokens and fallback reasons. Dry-assert these fields through the real writer before sealing. Save data before aggregates; never reconstruct missing provenance from successful outputs afterward.

Required preflight evidence: ordinary OFF consumer parity; tiny-model mask-vs-reference attention checks including forbidden-key mass; actual expert dispatch changes; final-token/cache-position bookkeeping; long HOLD/switch/BACK and save/reload/fork parity; stale/quoted rule rejection and narrow-scope overrides; survival of user/tool/assistant-derived durable facts; one generated tool call through the actual executor; complete same-run per-round record writing. Compare serving masks with 40i semantics before making an equivalence claim. Any mismatch stops before the larger bank.

Claim ceiling after PASS: on one frozen MoE trunk and 64 fresh bounded coding episodes from the registered distribution, classifier-driven register+render+certified routing/masking improves final executable success over matched rendering-only and normal-history arms within measured harm/cost limits. It does not establish arbitrary skills, dense-model transfer, trained knowledge gain, biological waves, elimination of stale information, unrestricted agents, or production reliability. C–R identifies the combined router/mask contribution, not each component separately. Generalization is only to tested families/edges; text and internal contributions remain explicitly separated.

**5. Cuts, order and odds.**

Days 1–2: incorporate 40g's outcome and 44b's NO-GO; freeze branch/claim scope; implement typed register/task bindings, renderer and exact cache/provenance contract. Ship explicit entry first, without relabeling it classifier-driven. Cut dense neurons, concept routing, online family discovery, profile mixtures, opposite-direction default biases, extra trunk extraction passes and universal cache/serving support.

Days 3–4: integrate JS and qualifying extra profiles, certify needed transitions, test artifact/fact preservation and unknown-family OFF; freeze independent classifier DEV thresholds. Day 5: package-level CPU checks, disjoint GPU cost/competence pilot and pre-evaluation freeze, only if eligibility holds. Days 6–7: at most one five-arm run, CPU executable re-scoring and report. If no qualified admission candidate exists, keep explicit entry and the INELIGIBLE result; no admission redesign or threshold rescue inside the larger test.

**Blunt subjective odds, conditional on the GPU slot becoming available:** **10–15%** that the classifier-driven composition meets the full larger-test PASS within one week, including obtaining independently eligible admission; **zero for an unchanged 44b candidate under these gates**. Roughly **70%** that an explicit-entry register with every-request rendering is usable within that week. These are engineering judgments, not calibrated probabilities. Even with qualified admission and Go+SQL transfer, I would put full-test odds around 40%: incremental benefit may vanish against R/T, task/key/relation generalization remains unresolved, and masks/tool code may disrupt useful context. The mechanism is specified; universal effectiveness remains an empirical question.
