**Programming concepts below expert routing — research and decision, 2026-09-05**

**Recommendation: test SUM versus PRODUCT, using the existing Qwen3-30B-A3B router actuator first. Let the selected experts handle their internal neurons.** This is a small, language-independent difference in computation with an exact checker and stronger causal precedents than recursion. It tests operation selection; it does not establish selection between algorithms computing the same function. If finer localization becomes necessary, investigate causally validated features/circuits. “Concept control requires SAEs” is too strong; “turn up the most active neurons” is poorly supported.

CPU/foreground research only; no model/GPU launch, signals, or sealed IFEval/BFCL contents read. **1. Which programming concepts, and what is actually localized?**

Universals are computational meanings: values and binding, composition/application, conditional choice, repeated computation, collection structure, state/effects, and valid operations on values. Every language need not expose each as a keyword: recursion can express iteration; failures need not use exceptions; types need not be annotated. Testing and refactoring are development activities, not universal language primitives. Universal expressibility also does not prove that a code LM stores a dedicated representation.
Three foundational results support separating meaning from spelling. [Utpala et al., NAACL 2024](https://aclanthology.org/2024.naacl-long.38/) separate language-specific and semantic embedding components; removing the former improves cross-language retrieval. This is representation evidence, not a neuron actuator. [Kargaran et al., 2025](https://arxiv.org/html/2506.01074v1) study CodeLlama-7B/Llama-3.1-8B: translated loop/range expressions align internally, and language-neuron ablations change perplexity across 11 programming languages plus English. They do **not** identify causal recursion/loop selectors. [Yin et al., FSE 2026](https://arxiv.org/html/2512.19980v2) find language-sensitive neurons and middle “concept layers” in Llama-3.1-8B/Qwen2.5-Coder-32B using activation/gradient attribution, ablation, semantic invariance and AST probes. Their downstream gains involve fine-tuning, embeddings and transfer, not frozen algorithm switching.
Ranking below is my research priority judgment. **L** = localization evidence: 3 causal intervention on the relevant computation, 2 distributed intervention or component-level evidence, 1 descriptive/adjacent evidence, 0 none found. **C** = short-task checkability; **I** = conceptual independence from surface language, each 1–3. I scores assess the distinction, not demonstrated intervention transfer. L=3 does not imply a raw neuron or complete generated-program controller.

| Rank | Concept / useful contrast | L / C / I | Evidence and executable distinction |
|---|---|---|---|
| 1 | Arithmetic composition/reduction: SUM / PRODUCT | 3 / 3 / 3 | Anthropic's addition feature follows renamed functions and composition; clamping changes simulated execution. Reduction-wide control remains an extrapolation. Execute the returned function on unseen lists and distinguish the two exact reductions. [2024 study](https://transformer-circuits.pub/2024/scaling-monosemanticity/index.html) |
| 2 | Type semantics: valid operation/type / name-based guess | 3 / 3 / 3 | Residual steering restores type prediction and transfers Python↔TypeScript across five models. This enables prediction, not arbitrary type choice or more precise types. Type-check plus runtime cases; an accuracy task rather than two equally valid policies. [Lucchetti & Guha, 2025](https://aclanthology.org/2025.blackboxnlp-1.22/) |
| 3 | Binding/data flow: follow the binding / copy a nearby value | 3 / 3 / 3 | Causal head/residual transplants identify dereference chains in a purpose-trained 37.8M transformer; not a pretrained Qwen code-generation result. Execute assignments with distractors. [Wu et al., ICML 2025](https://arxiv.org/html/2505.20896v2) |
| 4 | Control flow: loop / unrolled updates; conditional branches | 2 / 3 / 3 | Matched loop→unrolled MLP-output patches repair some predicted execution results in Qwen2.5-Coder-7B; not generation of different control flow. AST plus bounded traces distinguish executed loops/branches. [2026 preprint](https://arxiv.org/html/2606.17648v2) |
| 5 | Recursion / explicit iteration or stack | 2 / 3 / 3 | August 2026 residual-direction study includes stack/recursion and memoization/DP; algorithm labels improve inconsistently, generated-code correctness unmeasured. No raw recursion neuron found. AST call graph **and executed trace** required. [Jiang et al.](https://arxiv.org/html/2608.29459v1) |
| 6 | Error handling: raise / return sentinel | 1 / 3 / 2 | Qwen expert labels include cross-language exception handling; code-error SAE features concern detecting errors, not choosing an exception policy. Invoke valid/invalid inputs and capture return versus exception. Exception APIs are not universal. [Expert analysis, 2026](https://arxiv.org/html/2604.02178v2) |
| 7 | Collection representation: map / list; membership / index | 1 / 3 / 3 | Gemma-9B SAE circuits support dictionary-key error prediction; this does not demonstrate choosing a map instead of a list. AST/trace the actual container and test absent/duplicate keys. [Authors' 2025 research report](https://www.lesswrong.com/posts/PkeB4TLxgaNnSmddg/scaling-sparse-feature-circuit-finding-to-gemma-9b) |
| 8 | Algorithm strategy: DFS / BFS; comparison-sort variants | 2 / 2 / 3 | Residual steering evidence covers DFS/BFS, not a verified quicksort/mergesort neuron switch. Correct sorted output cannot identify the algorithm; instrument traversal/comparison traces. [Jiang et al.](https://arxiv.org/html/2608.29459v1) |
| 9 | Mutation / pure transformation | 0 / 3 / 3 | No inspected causal selector. Check aliases, input snapshots and returned values; local accumulator updates do not imply observable input mutation. |
| 10 | I/O effect / pure return | 1 / 3 / 3 | Expert labels include printf/format-string processing, an adjacent lexical result. Capture writes and return values; an API-name detector is insufficient. [Expert analysis](https://arxiv.org/html/2604.02178v2) |
| 11 | Test writing / implementation; refactoring / preserving source | 0 / 2 / 2 | No inspected localized clean switch. Run tests against seeded mutants; check refactoring with behavioral equivalence plus a specified AST transformation. Simply seeing assertions or renamed variables is inadequate. |

For recursion specifically, restrict to direct self-calls or a statically resolved helper-call graph; reject aliases, dynamic calls and mixed/unsupported strategies. Confirm a recursive call or loop actually executes on non-base inputs. Dead self-calls can fool AST-only checks; all-loop/all-recursive declarations can still compute incorrect answers. Recursion versus iteration is conceptually attractive, but currently weaker evidence than arithmetic or type semantics.

**2. Experts versus neurons: no universal syntax/concept boundary**

| Model/work | What the evidence supports |
|---|---|
| [Mixtral, 2024, §5](https://arxiv.org/html/2401.04088v1) | Little obvious topic specialization; expert choices correlate with syntax, notably early/late layers. This is a result about this model, not a law for MoEs. |
| [OLMoE, 2024/ICLR 2025, §5](https://arxiv.org/html/2409.02060) | Clearer GitHub/arXiv/domain and vocabulary specialization than Mixtral. The authors explicitly link domain differences to vocabulary distribution; these measurements do not isolate algorithms. |
| [DeepSeekMoE, 2024](https://arxiv.org/html/2401.06066), [ESFT, 2024](https://arxiv.org/html/2407.01906) | Fine segmentation/shared experts encourage specialization; ESFT profiles task-affine expert sets and selectively fine-tunes them. Task-affinity is evidence against “syntax only”; weight updates do not demonstrate transient focus. |
| [DeepSeek-Coder-V2, 2024](https://arxiv.org/html/2406.11931) | Code-heavy continued training and broad multilingual capability; its report supplies no causal atlas assigning recursion, mutation or sorting strategies to experts. Do not substitute architecture/benchmark success for localization. |
| [Multilingual Routing, 2025/ICLR 2026](https://arxiv.org/html/2510.04694) | Qwen3-30B has stronger natural-language routing differences early/late and more shared middle routing. Boosting 22 math experts in layers 8–35 improves non-English MGSM 76.4→78.0; some languages regress. This is natural-language/domain evidence, not Python↔JS algorithm transfer. |
| [The Expert Strikes Back, April/May 2026](https://arxiv.org/html/2604.02178v2) | Sparse probes find less polysemantic expert neurons; automatic labels describe narrow syntactic/semantic operations. Qwen L44-E32 is labeled exception handling across languages. Its “causal attribution” experiment measures direct-logit attribution on OLMoE, **not** Qwen expert replacement or executable policy switching. Treat the label as a hypothesis, never an imported actuator ID. |
| [SteerMoE, 2025/ICLR 2026](https://arxiv.org/html/2509.09660v2) | Promoting/suppressing behavior-associated experts steers document faithfulness and safety, including on Qwen3. This is frozen routing intervention by behavior, not merely language. Prompted tasks, dose-sensitive fluency and no algorithm-switch certificate limit the inference. |
| [Routing Sensitivity Without Controllability, March 2026 preprint](https://arxiv.org/html/2603.27141v1) | Fairness-associated routes are detectable without useful steering on Qwen3/Mixtral; changes in likelihood on other models fail to transfer to generation. Association, causal influence and useful control are different claims. |

Mechanistic inference: experts are layer-local transformations, selected from the current residual state after attention. A concept can involve overlapping experts **and** attention/residual communication; experts can implement pieces of that concept. Two tasks using the same experts can recruit different internal neurons, while different routes can merely reflect different spellings. There is no demonstrated universal hierarchy of “language expert → recursion neuron,” nor evidence that one expert stores an entire reusable algorithm.
Counts, verified against reports/configs: [Mixtral](https://arxiv.org/html/2401.04088v1) 8 routed/top-2; [OLMoE](https://arxiv.org/html/2409.02060) 64/top-8; [Qwen3-30B and 235B](https://arxiv.org/html/2505.09388v1) both 128/top-8, no shared experts. [Coder-V2 full](https://huggingface.co/deepseek-ai/DeepSeek-Coder-V2-Instruct/blob/main/config.json) has 160/top-6 plus two shared, [Lite](https://huggingface.co/deepseek-ai/DeepSeek-Coder-V2-Lite-Instruct/blob/main/config.json) 64/top-6 plus two shared; [V3](https://arxiv.org/html/2412.19437) 256/top-8 plus one shared.
**Correction to the question:** [V4-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4-Flash/blob/main/config.json) has 256 routed experts; [V4-Pro](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro/blob/main/config.json) has **384**, both top-6 plus one shared. V4 also uses token-ID hash routing in initial layers, so a learned-logit actuator is not uniform across its stack. [V4 report, 2026](https://arxiv.org/html/2606.19348)
More/smaller experts increase available combinations and can reduce entanglement, but expert width, routing sparsity, training and load balancing change together. Cross-model interpretability correlations are not a controlled proof that increasing expert count improves concept controllability. Qwen's 128 experts already provide fine segmentation. Increasing top-k changes compute and the trained mixture; splitting/adding experts requires an architectural/training project and creates no new knowledge by itself.
“Load different experts” is sensible only as selecting other **existing, co-trained experts at their original layers**. Normally routing changes which resident experts execute; disk/offload loading is a storage issue. An external expert from another checkpoint is not a compatible skill plugin without alignment/training. A fixed task-wide expert whitelist is especially questionable: different tokens need different suboperations. Keep token-dependent top-8 routing and apply a bounded task bias.

**3. Evidence below routing, and how to avoid the failures**

- **Strong semantic feature, narrower outcome:** Anthropic's 2024 residual SAE addition feature `1M/697189` follows function renaming/composition and, when clamped, makes simulated non-addition execution behave like addition. Code-error features respond across Python/C/Scheme; type-signature features also exist. These are feature directions, not individual model neurons, and not a statistically validated clean SUM/PRODUCT program-generation switch. [Primary report](https://transformer-circuits.pub/2024/scaling-monosemanticity/index.html)
- **Best direct cross-programming-language intervention:** type-prediction mean-difference residual vectors transfer Python↔TypeScript. The model can recover correct annotations after irrelevant renaming, but cannot thereby turn `any` into a more precise type. This supports activation of an existing semantic mechanism and shows why one broad “typing” address may be too coarse. [BlackboxNLP 2025, §§3–4](https://aclanthology.org/2025.blackboxnlp-1.22.pdf)
- **Closest algorithm-generation intervention:** the August 29 [latent-skills preprint](https://arxiv.org/html/2608.29459v1) adds contrastive residual vectors through the final half of layers. Qwen3-0.6B DP/recursion approach-match rises 16.7→41.7%, but Qwen3-1.7B stays 8.3→8.3%; graph-search alignment worsens on 1.7B. Targets include stack/recursion. Scoring is GPT-4o-mini approach judgment; the paper explicitly excludes functional correctness. Donor solutions being executed does not validate steered outputs. This is no raw-neuron localization or reliable strategy controller.
- **Loops, causal but at MLP-block level:** [Chen et al., August 2026 revision](https://arxiv.org/html/2606.17648v2), Qwen2.5-Coder-7B, transplant matched loop MLP outputs at layers 25–26 into unrolled-code execution. Correct answers recover on 18.6% of 70 initially wrong cases; attention/random-donor controls recover zero. Outputs are predicted results, not newly generated loop implementations; operand-matched transplantation can carry computation content.
- **Raw neurons are not ruled out:** [Arora et al., ICML 2026](https://arxiv.org/html/2601.22594v2) trace roughly 100-neuron subject–verb circuits and steer intermediate city→state→capital reasoning with small neuron sets. [Arithmetic Without Algorithms, 2024/2025](https://arxiv.org/html/2410.21272) causally ablates overlapping arithmetic-heuristic neurons. Neither establishes raw recursion/iteration or within-expert clean code control. I found no inspected 2024–2026 paper meeting that combined bar.
- **Available SAE tooling, conditional fit:** [Qwen-Scope, May 2026](https://arxiv.org/html/2605.11887v1) releases all-layer residual SAEs, including [30B-A3B, width 128K](https://huggingface.co/Qwen/SAE-Res-Qwen3-30B-A3B-Base-W128K-L0_100). These were trained on the **base** backbone; the current instructed model needs reconstruction/causal-transfer checks. Published examples concern natural-language switching/style, not a verified recursion selector. No new SAE training is necessary merely to investigate availability; compatibility and a useful feature remain unproved.

In [41b's recorded design/results](quick-checks/check41b/README.md), selected gain 3 makes one signed multiplier negative; correct and swapped shifts in proxy c are both about +20.6, and 23/32 correct-arm outputs start with ` moduleId`. This defeats a directional interpretation of that proxy at that dose. It does not by itself diagnose a software sign bug. Bare keyword logits at the first token can be unrelated to the fence/code decision, and parser acceptance is weaker than callable program correctness.
For a multiplicative gain, the local derivative is `dc/dg_i = x_i * dc/dx_i`; for an additive neuron change it is `dc/dx_i`; for an SAE feature it is `grad(c) dot decoder_i`. Preserve the loss/contrast orientation and validate with small positive/negative finite differences through the actual consumer. Require present, nonzero gradients; test each sign separately before using large gains. Ranking by absolute attribution alone loses direction, and sign-reversing a large perturbation need not reverse behavior.
Use paired activation **replacement** from observed competent states to test necessity/sufficiency before amplification; match positions and separate instruction selection from already-computed answers. Prefer patches at shared pre-output positions, test renamed variables/new operands, and measure complete programs. Patching corruption/metric choices matter, and integrated-gradient rankings still require exact interventions. [Best Practices, 2023/ICLR 2024](https://arxiv.org/html/2309.16042), [Faithfulness, 2024](https://arxiv.org/html/2403.17806)
For later within-expert tests, hold routes fixed while patching the actual SwiGLU product entering down-projection, then separately allow routing to change; otherwise local neuron and downstream routing effects are confounded. For SAE edits preserve reconstruction residual: `h_new = h + D(z_new-z)`, rather than replacing h with an imperfect reconstruction. Validate the feature on unseen equivalent syntax; its natural-language label is not ground truth.
Causal scrubbing tests an explicit computation hypothesis by resampling activations across examples that agree on hypothesized causal variables while varying irrelevant details. It is a falsification method, not a discovery algorithm or guarantee against off-distribution states; agreement assumptions can make it vacuous. Use it only after a candidate circuit exists. [2023 practical analysis](https://www.lesswrong.com/posts/DFarDnQjMnjsKvW8s/practical-pitfalls-of-causal-scrubbing)

**4. One proposed SET-only screen: additive versus multiplicative aggregation**

Why this pair: both are broadly pretrained, short, compositional operations with unambiguous executable outputs. An external SUM/PRODUCT/OFF state selects the intended operation while visible inputs retain all operands. The experiment asks whether routing can select semantic computation while language remains fixed. It does not claim that an addition SAE found in Claude corresponds to a particular Qwen expert or that reductions share one universal neuron.

1. **Lineage/freeze:** no weight fitting; profile only newly authored Python cued tasks (seed 95061), select one dose on disjoint Python setup prompts (95062), evaluate fresh banks (95063/95064), balanced over Python/JS. No benchmark prompts, responses, published expert IDs or check40/41 banks. Freeze prompts, checkers, seeds, gains, hook, hashes and reading before final generation; never replace failed examples.
2. **Task:** request one function returning a scalar reduction of a supplied integer list, with language and explicit-loop requirement fixed in text; omit only SUM/PRODUCT in non-text arms. Use whole-list/prefix/suffix/slice variants, distinct names/paraphrases and bounded integer operands. Controller sees only SUM/PRODUCT/OFF, no answer. Require competence in both modes; unsupported/truncated replies count as failures.
3. **Discovery:** 16 Python task pairs, explicit SUM and PRODUCT cues, both executable; require ≥15/16 competent per direction. Record raw router logits over the same last four neutral prompt tokens before code generation, not over operation-specific generated syntax. Average by example, not token count. Define `b_l = (mean_SUM - mean_PRODUCT)/2`, subtract its expert-wise mean; freeze zero-indexed layers 7–34 and zero elsewhere. This middle band is an informed prior, not proven code localization.
4. **Actuator/setup:** use the verified 40b router consumer, adding `±alpha*b_l` before softmax/top-8/renormalization, during current prefill and every decode step. Keep k=8 and all weights frozen. Grid only alpha={1,2,3}, eight Python setup prompts, both signs. Select the smallest alpha achieving ≥6/8 **paired** SUM-and-PRODUCT executable successes and zero malformed/nonterminating replies; if none, stop FAIL/NO SAFE SET. No JS-informed dose selection or second actuator.
5. **Controls:** same-prompt `+b`, `-b`, matched-norm per-layer expert-index shuffled `+b/-b`, OFF, text-SUM and text-PRODUCT: seven generations/prompt. Reuse opposite-sign outputs as swapped controls. Shuffle once using seed 95062, preserving exact within-layer values; no damaged null accepted. Setup totals 8×(six grid outputs + OFF + two shuffled + two textual)=88 generations; freeze then audit selected-dose controls.
6. **Executable checker:** parse the **entire extracted code body**, require only the declared callable, then evaluate supported ASTs with an instruction budget; reject unsupported constructs. Python AST and a JS parser feed a small bounded interpreter for assignments, arithmetic, indexing/slices and loops. Validate its results against hand-written functions on both sides before model use. Test lengths 0–8, negatives, zeros, repeats and multiple novel inputs per function; exact integer outputs and no input mutation/I/O required. Empty SUM=0, PRODUCT=1; include inputs whose answers differ. A fence label, `+`/`*` count, or parser success earns nothing alone.
7. **Final:** 32 fresh prompt instances, 16/language and eight per seed×language, balanced over the four list-selection families; each evaluated in all seven conditions =224 generations. Both addresses start from identical prompt/KV hashes within each instance. The Python-derived direction and dose transfer unchanged to JS. These are two synthetic banks under greedy decoding, not independent model-training seeds or a general code benchmark.
8. **Eligibility/collateral:** text controls ≥15/16 correct for each operation×language; otherwise INELIGIBLE/COMPETENCE. OFF and each shuffled sign must give valid, terminating code on ≥30/32 instances. Add 16 disjoint explicit-operation neutral tasks under OFF/+b/-b (48 generations); require no new task failures versus OFF. Changed routes/weights at dispatch must be recorded, and OFF must reproduce the unhooked consumer's outputs on identical inputs.
9. **PASS:** correct signs produce both intended executable programs on ≥24/32 paired instances, with ≥12/16 per language and ≥5/8 in each seed×language cell; introduce at most one newly malformed/nonterminating reply per sign versus OFF. Require ≥8 more paired successes than shuffled, swapped and OFF, plus one-sided exact paired McNemar tests against those three controls, Holm familywise .05. Use prompt instances as statistical units, not individual runtime inputs. Report discordances, counts and intervals; practical thresholds alone are not evidence of existence.
10. **Budget:** 32 donor +88 setup +224 final +48 collateral =392 generations, each ≤96 new tokens, ≤37,632 decode tokens. At the audit's measured ~15 tok/s, plus 314 s load and an estimated 600 s profiling/prefill allowance, ×1.25 reserve gives **1.188 GPU-h**; this is a projection, not a measurement for these longer tasks. Pilot the slowest setup family and project all remaining costs; refuse an over-1.5-hour matrix, never shrink after outcomes. Cooperative per-token deadline; foreground only, no signals, leave ≥30 s to save/return.
11. **Records/reading:** save prompts, full outputs/token IDs, EOS, seeds, bias/hook hashes, per-layer route changes, all execution results and elapsed allocation time in the same run. Invalid instrumentation→INVALID; cost/missing work→INCOMPLETE; eligibility failure→INELIGIBLE; otherwise missing a gate→FAIL. Language-only movement, both signs producing the same operation, and correct arithmetic with broken programs are failures for this claim. SET PASS warrants later hold/switch/clear; it proves none of those now.

**Blunt odds:** approximately **35%** subjective probability of this complete bounded SET screen passing, versus **10–15%** for an equally strict first raw-neuron recursion/iteration screen. These are planning judgments, not literature frequencies or calibrated posteriors. The largest risk is that the learned routing difference tracks the instruction words without controlling the selected computation. A valid null closes this actuator/pair/band/dose screen, not concept representations generally.
For practical coding, let the native experts handle concept composition under explicit task instructions unless extra control earns its keep. For the Miller-style scientific question, spend once on this oracle routing screen. Only a specific demonstrated shortfall justifies tracing below routing; SAE features and small neuron/head circuits are competing representations to validate, not prerequisites to assume.

**5. Cut**

Cut more experts/new backbones, expert swapping across checkpoints, top-k changes, router/LoRA training, exhaustive expert/neuron atlases, and a new SAE-training project. Cut style/fence/token-proxy success claims, raw activation-frequency gain sweeps, post-outcome dose rescue and benchmark-derived directions. Cut long sorting-algorithm implementations, pure/functional labels without an effect checker, and neuron-level “recursion” claims based on an AST keyword or LLM judge. Cut multi-turn persistence, learned classifiers and oscillators from this first screen; they become separate questions only after clean semantic SET.
