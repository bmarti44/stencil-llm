**The actual method, sufficiently specified to implement.**

DIRECTER retains the instruction text. “Instruction-aware” means the caller supplies token positions belonging to the current instruction; intervention targets their cached **keys**, across every KV head in selected layers. It is not a learned instruction classifier, a semantic router, or a fixed list of instruction heads. In the principal experiments, rewritten IFEval separates task and instructions; GSM8K marks the JSON-format instruction and excludes the math problem; LIFBench marks its instruction portion. Appendix D.2 separately tries model self-extraction of one verbatim instruction substring from original IFEval; its mean score is 80.1 versus original-prompt baseline 78.3, and ambiguous extraction can select the wrong clause. That extraction adds a model call and is not needed when our renderer already knows the span. [Paper §§3.1–3.2, A.2, D.2](https://arxiv.org/html/2603.06745v1#S3).

For an instruction index set I and candidate layers S, replace `K[l][:,:,I,:]` by `100*K[l][:,:,I,:]` for l in S. Leave V unchanged. This scales already cached key vectors, rather than adding a constant attention bias or imposing a target attention mass. Algebraically, an instruction logit s becomes 100s: negative logits become more negative. Therefore “amplifies attention on every instruction token” is too literal; the effect depends on queries and relative scores. All heads participate within a selected layer, including shared KV heads in grouped-query attention. There is no head profiling stage. [Paper §3.1](https://arxiv.org/html/2603.06745v1#S3.SS1); [released cache operation](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/src/cache_utils.py).

Layer ranking is **per prompt plus marked instruction span**, performed once before emitting the answer, then fixed for that answer. For each candidate source layer l, scale only its instruction keys and measure the resulting attention input/output states at all receiving layers j. With cosine distance d, its score is the mean over j of

`d(Hpre[j], Hpost_steered[j,l]) + d(Hpre_steered[j,l], Hpost[j]) − 2*d(Hpre[j], Hpost[j])`.

Sort source layers descending. The last term is constant across source-layer candidates and may be omitted **when averaging over receiving layers for each source layer**. This is an influence proxy, not a competence score. The released implementation prefills all but the last prompt token and probes that last token with the cached prefix, requiring L single-token steering forwards plus the raw reference. It does not run L complete prompt prefills. Re-rank for a new request or changed span; the published algorithm has no within-answer reranking and no cross-turn invalidation policy. [Paper Eqs. 2–6, Algorithm 2](https://arxiv.org/html/2603.06745v1#A3); [generator `_prefill`, `_rank_layers`](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/src/generator.py).

At **each output-token position**, the paper's loop is:

1. Compute raw next-token probabilities p with unmodified keys, conditioned on the actual already-emitted prefix.
2. If `p(second-best) < beta*p(best)`, emit the raw greedy token immediately. No different token could pass the following test. This shortcut preserves greedy token choice, not arbitrary sampling distributions.
3. Otherwise start with all ranked layers, compute a steered distribution q, and propose its argmax v. Accept only if `p(v) >= beta*p(argmax(p))`, with beta=0.5. This is one candidate-token likelihood-ratio test, **not KL/JS divergence, code execution, or a reward-model judgment**.
4. On rejection, halve the number of candidate layers, discarding the least sensitive half. Retry at the same output position. For 32 layers: 32→16→8→4→2→1→empty. Empty means emit the original raw token.
5. Advance one token and start the next decision from all layers again. Rejected candidate tokens never enter the answer.

There is no beam, whole-answer rejection sampling, backtracking over earlier emitted tokens, or second language model. The raw cache follows the generated trajectory; the code retains raw-pass cache updates and discards trial caches. Thus fallback restores the raw prediction **on the current, potentially already steered history**, not the counterfactual completion that an unsteered model would have produced from the beginning. This distinction alone rules out a global correctness guarantee. [Paper §3.2/Algorithms 1–2](https://arxiv.org/html/2603.06745v1#S3.SS2); [generation loop](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/src/generator.py#L169).

**What is trained, what is chosen, and what costs inference.** No trunk weights, steering vector, probe, or rejection classifier are trained for DIRECTER. Per-prompt ranking is test-time computation without labels; it is not free computation. Main settings are alphaK=100, alphaV=1, beta=0.5, descending cosine ranking, half-layer backoff, greedy decoding. The paper says one setting is used across tasks without task-specific tuning. It does not establish a preregistered, evaluation-blind origin for that setting: Figure 3 shows an IFEval beta sweep .1–.9 peaking near .5, alpha robustness over 10–100,000 with saturation around 100, and four prompt templates. Appendix E checks beta {.3,.5,.7} across benchmarks/models; C.6 explicitly tunes alternative divergence thresholds on an IFEval held-out split. “No training/no extra calibration dataset” must not become “no hyperparameters/no benchmark exploration.” [Paper §4.1, Figure 3, C.6, E.1](https://arxiv.org/html/2603.06745v1#S4.SS1).

The demo adds operational defaults not fully specified as benchmark settings: `max_new_tokens=2048`, `max_trial=10`, `fast_decoding=False`, optional decoding backend `sdpa`; model BF16, initially eager attention; Transformers exactly 4.52.1, with torch/accelerate unpinned. EOS handling, numerical precision of the probability test, prompt tokenization, and cache/backend implementation must also be frozen. These are reproduction variables, not knobs to search against benchmark scores. [Requirements](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/requirements.txt), [model utilities](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/src/model_utils.py), [CLI](https://github.com/mjk0618/directer/blob/ba4d50b5578e94d77a554e901f8b3e3cf4de3475/run_directer.py).

Reported H100 cost: approximately 16% lower throughput and 20% greater per-token latency; mean TTFT 1.160s versus .028s zero-shot, a computed 41.4× ratio but only 1.132s absolute increase. Table 19's reserved-memory *growth* is 185MB versus 94MB, not a portable peak-memory bound. Its average output lengths are 387.6/387.1 tokens. A 16% rate loss implies `1/.84=1.1905` times decode time, not 1.16. Worst-case paper decoding requires one raw plus six trial forwards per token on a 32-layer model, after 32 ranking probes. Frequent confidence skips explain why average overhead can be much smaller. Short replies and long caches need their own measurement. [Paper §4.3, D.3](https://arxiv.org/html/2603.06745v1#A4.SS3).

The released code repeatedly deep-copies the cache, even before determining a skip, and clones attention hook states; default mode keeps hooks attached throughout decoding. Those are real bandwidth/allocation costs. Optional fast decoding removes hooks after ranking and changes the attention implementation. FlashAttention-compatible **key editing** does not make the whole program a fused fast serving implementation. The [project page](https://mjk0618.github.io/directer/) advertises 90% throughput and no precomputation; use the paper's approximately 84% rate and explicit per-prompt ranking instead of merging these inconsistent summaries.

An arbitrary HF causal LM is **not supported just by passing its model ID**. The implementation assumes `config.num_hidden_layers`, module names matching `layers.*.self_attn`, keyword `hidden_states`, tuple-like attention results, mutable Cache with `key_cache/value_cache`, conventional four-dimensional tensors and effectively batch size one (`.item()` decisions). Model sharding and hybrid/recurrent caches need explicit adaptation. For a conventional attention+MoE trunk, the conceptual operation leaves the expert FFN/router alone, so MoE is not itself a barrier; changed attention can still change later routing indirectly. No MoE experiment is reported. A vLLM port would need instrumented layer probes, safe per-request trial cache branches, raw-logit access and token retries integrated with its scheduler/cache semantics; ordinary API calls/logit processors are insufficient to implement the key edits. Reusing shared prefix blocks after in-place scaling would be especially wrong. No vLLM implementation was found in the release. HF is the sensible S1 path; external whole-work validation in S2 can use our existing vLLM path without internal hooks.

**Transfer to changing coding obligations: limited, but one useful idea.**

The narrow GSM8K result uses one JSON response schema, one turn and no evolving repository. The *whole paper* is broader than “one fixed constraint”: IFEval has multiple heterogeneous instructions, LIFBench covers long contexts, and the appendix adds refusal/factuality. Nevertheless none establishes tool trajectories, mid-episode replacement, scope, restoration of prior obligations, or release from stale instructions. Even LIFBench uses a selected 467-example subset; Appendix A.2.2 omits the exact string-length cutoff and retained IDs. Do not call it full 128k long-horizon evidence. [Paper A.2](https://arxiv.org/html/2603.06745v1#A1.SS2).

What transfers: keep a competent baseline available, make an intervention tentative, inspect an independent signal, and back off when intervention is unjustified. Our renderer can supply exact current-span offsets without learned extraction. What does not transfer: its rankings across requests/models, its beta as an executable-risk threshold, its H100 speed, and the claim that a probable token protects a whole program. On a rule change, only the current effective instruction should be marked; repeated old instructions must not win a first-substring search. Ranking must be rebuilt against the changed prompt. This still does not solve admission, precedence, scope, or stale-answer influence.

Our ceiling is real but axis-specific. [Check 40j](quick-checks/check40j/README.md) already has text-only and text+bias at **16/16 JS executable successes**, with zero paired incremental wins. [Larger-test RESULTS](larger-test/RESULTS.md) has register delivery adherence **1.0000 across 64 measured episodes**. Those findings remove headroom on those measured endpoints; they do not say every format/coding obligation is solved. The same larger report has incomplete format adherence and a registered overall **FAIL**, with breakage in R20/N14 episodes.

The shorthand “register arm 9/54 episodes” needs correction. For indent, **54 common measured episodes yielded nine R wins, five N wins and 40 ties**, one-sided p=.211975; nine is not the number of compliant R episodes. R's own mean written-change adherence is .6759 across 54 episodes; its conditional paired gain is +.037037, but all-attempt sensitivity is −.0703125. [Pilot 7](quick-checks/composition-pilot-7/README.md) has R **10/15 written indent-change rounds**, N11/16, with episode discordances 1/1: no significant gain. Nonwrites cannot be dropped to create a success story.

Mechanistic judgment: attention control could plausibly bias whitespace/style decisions when multiple tokens are already plausible. But indentation can encode Python block structure, and a width change must preserve relative nesting across retained and new code. Token plausibility neither checks that invariant nor prevents a valid-but-wrong program. A confident stale indentation choice may actually trigger DIRECTER's skip gate. The local larger-test postmortem links differential breakage to indentation-change rounds, making executable validation pertinent, but it does not diagnose deficient attention as the cause. **Moderate plausibility for a guarded formatting intervention; weak evidence that DIRECTER's key-scaling machinery is the needed actuator.** [Local postmortem](larger-test/RESULTS.md).

**Plain-language verdict for Brian.** DIRECTER gives us a promising published guardrail: push the instruction, but back off when the model regards the proposed next token as unlikely. It reports no aggregate loss on its math-plus-JSON comparison; it does not establish that steering never breaks competence, and it is not unique among joint-positive results. We can replicate the idea, but a faithful numeric reproduction first needs the missing scorer/run details and resolution of the released code's mismatches. It has not shown that it fixes changing indentation rules in an agent.

**The single cheapest next step is a CPU-only, synthetic paper-versus-code conformance fixture for ranking, span boundaries, final-layer retry and gold-answer scoring.** This audit already exposes failures in three of those contracts at zero GPU cost. Resolve them before spending even a smoke run on claims of faithful reproduction. Once that gate is clean, the cheapest GPU check is the bounded synthetic timing smoke; the cheapest check of relevance to *our* problem is S2's DEV indentation-control/rollback fixture with a separate evaluation oracle. Do not start with a vLLM port or another all-layer search.
