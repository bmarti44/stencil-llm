**The Miller question and the next experiment**

“Sustained router bias = slow control selecting which stored experts express” is a fair **engineering analogy**: frozen weights hold transformations, and a task-level bias alters fast token-dependent expert mixtures. Here “slow” means an externally held setting relative to token updates, not a measured oscillation or learned controller timescale. Miller's proposal specifically involves spatial/temporal wave coordination of neural ensembles; the authors describe it as a theory still requiring direct tests of analog computation ([authors' institutional account](https://picower.mit.edu/news/cognition-and-consciousness-arise-analog-computations-says-new-theory)). No wave, biological mechanism or one-expert/one-skill mapping is established here.

Exact replacement for the stronger slogan: **“An externally maintained routing bias selects a narrow output mode using frozen co-trained experts. Whether it selects language-independent computation or supplies reversible task control remains unproved.”** 40c already undermines necessity of sustained late forcing;40d directly falsifies reversible control for that schedule. Further falsifiers include matched stable random directions giving the same effect, loss of functional differences once spelling/fences are controlled, or failure on fresh independently constructed prompts. For a maintenance claim, compare continued versus removed bias after identical SET outputs/cache histories; persistence in both arms would assign no demonstrated maintenance benefit to continued bias. Causal mediation by expert dispatch would require restoring the original expert indices/weights while holding the rest of the intervention fixed, rather than inferring it from changed route counts alone.

**Single most valuable next experiment: one calibrated concept SET test, prospectively frozen as 43b.** Keep SUM/PRODUCT semantics and a bounded executable checker, fix language and neutralize operation cues, measure neutral OFF before selection, and include a known-working JS actuator sanity control in the same runtime. Use a finite, predeclared setup grid with perturbation magnitudes contextualized against the successful JS band (about 6.8 and 10.2 norm, not an assumption that equal norm means equal efficacy). Select only on setup, retain both signs and stable matched shuffled controls, record actual dispatch/mixture changes and malformed outputs, then evaluate the one frozen choice on fresh banks with two seeds, multiple prompt formulations and both languages. Score complete executable programs, paired address specificity and collateral failures; stop mechanically if no safe setup cell qualifies. Preserve43's null. This directly tests the largest gap between language-style selection and selecting stored computation; another positive fence-label result would add little.
