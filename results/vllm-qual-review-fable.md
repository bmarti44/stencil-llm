**(3) Risks in the real episode loop.**

Determinism. The decode path is the one exercised by a live loop and it is verified invariant across batch sizes 1-4 and mixed arms. The residual risk is KV provenance: in the loop, round k+1's prompt reuses KV blocks that were computed during round k's *decode* (in whatever batch it happened to share), never re-prefilled — exactly what the cold pass here did (13,753 fresh tokens reproduces only if decode-cached output blocks count as hits). Batch invariance is supposed to make decode-time and prefill-time KV identical, but this qualification never compared them. If it does not hold, an episode's outputs would depend on the co-scheduling history of its earlier rounds, which is arm-correlated in pilot 3's within-arm waves. The cheap check is the post-restart reverse-order C4 replay above (about 3 GPU-minutes). Also untested: chunked prefill of a >2048-token cold prompt (never occurs in the loop unless a server restarts mid-episode) and batch size >4 (C8 not qualified; pilot 3 correctly fixes max-num-seqs 4).

Cost projection. 7.845 h assumes the measured 39.9 tok/s aggregate, i.e. a permanently full 4-slot pool with the 16-round frozen token mix. The pilot-3 schedule is not that: it runs within-arm, round-synchronous waves (submit up to 4 active episodes, wait for all), and the two 32-round episodes finish at C2. Break-even for the 12 h ceiling with this formula is a sustained aggregate of **22.0 tok/s** (C4 measured 39.9; B1 measured 20.9 fails). Wave sync loses little inside R/N (outputs ~200 tokens each) but T waves are bounded by 512-token cap hits, and per-stream decode falls with context: B1 R decode goes 26.1 -> 16.6 tok/s from 0.8k to 11k tokens (C4: 12.6 -> 9.3), roughly -0.9 tok/s per 1k context, so 32-round histories (~20k+ tokens) will decode well below the 5-11k rate the projection is built on; the 16-round weighted output count also does not cover 32-round output volume. Pilot 3's gate measures the actual schedule rate and uses the max per-episode token count per arm, which is the right correction; expect the served-only projection to land between 8 and 11 h, and treat anything above ~10 h as leaving no room for HF hidden-state recovery, which is still uncosted. The projection is not wrong; it is a full-pool upper bound on throughput that the wave schedule will not reach.
