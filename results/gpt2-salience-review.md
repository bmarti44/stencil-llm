For the shared 768-dimensional salience weight, filler’s gradient-vector norm was approximately:

- 22× rule under auxiliary loss.
- 320× rule under main loss.

The signed auxiliary gradient on rule tokens was positive, meaning the immediate optimizer step predominantly **closes rule tokens**, not opens them. Filler signs are approximately random and cancel incompletely.

This is the smoking gun: the downstream objective does not contain a usable learning signal for discovering the cue mask. It feeds the salience classifier an enormous, noisy lexical gradient generated by the state it is supposed to clean up.

Mechanistically:

```text
loss at query
  → normalized query code
  → ~6e6-RMS oscillator state
  → sum of contributions from ~1024 gated embeddings
  → shared lexical salience weight
```

The answer perturbation is only about 0.0008 of the normalized state, while filler supplies hundreds of recurrent contributions. Because the same salience weight is shared across all positions, the filler terms win before the gate learns any selectivity.

## Minimal fix

Use direct, balanced supervision on the salience **logits**, initialized mostly closed. Do not launch another run with only a bias or LR adjustment.

This is the smallest change that bypasses the bad downstream credit path:

```python
sal_logits = model.salience(model.wte(toks_d)).squeeze(-1)

rule_mask = torch.zeros_like(toks_d, dtype=torch.bool)
for b, seq in enumerate(seqs):
    for lo, hi in seq.rule_spans:
        rule_mask[b, lo:hi] = True

# Balanced BCE: statement spans open; everything else closed.
salience_loss = 0.5 * (
    F.softplus(-sal_logits[rule_mask]).mean()
    + F.softplus(sal_logits[~rule_mask]).mean()
)

loss = loss + AUX_WEIGHT * aux_ce + SALIENCE_WEIGHT * salience_loss
```

Use `SALIENCE_WEIGHT = 1.0`.

Add all initial and update statement spans to `NLSequence` at [nl_task.py:90](/home/bmarti44/stencil-llm/src/stencil/nl_task.py:90). Record `(start, end)` whenever rules are appended at [nl_task.py:137](/home/bmarti44/stencil-llm/src/stencil/nl_task.py:137), [nl_task.py:157](/home/bmarti44/stencil-llm/src/stencil/nl_task.py:157), and [nl_task.py:168](/home/bmarti44/stencil-llm/src/stencil/nl_task.py:168).

Initialize the gate at approximately 5% open:

```python
nn.init.constant_(self.salience.bias, -3.0)
```

That replaces [gpt2.py:228](/home/bmarti44/stencil-llm/src/stencil/gpt2.py:228). Importantly, do this **with** the direct `BCEWithLogits`-equivalent loss. That loss has gradient `sigmoid(z)-target`, so rule-opening gradients remain strong even at bias −3. Without the direct loss, a negative bias merely reduces the already bad downstream gradient.

For speed, give salience its own optimizer group:

```python
salience_params = list(model.salience.parameters())
salience_ids = {id(p) for p in salience_params}
other_params = [p for p in trainable if id(p) not in salience_ids]

opt = torch.optim.AdamW(

        {"params": other_params + list(aux_head.parameters()), "lr": 3e-4},
        {"params": salience_params, "lr": 3e-3, "weight_decay": 0.0},
    ],

)
```

### Is this scientifically acceptable?

Yes, if described honestly.

The span mask affects only a training loss. At evaluation, the model still receives only tokens and computes salience using `Linear(wte(token))`; no mask or position annotation is supplied. Therefore it is not evaluation leakage.

It does change the claim from “task loss spontaneously discovered salience” to “a supervised cue detector learned to identify memory-worthy tokens and generalized without eval-time masks.” Given the fixed vocabulary and templates, it may largely learn a lexical whitelist. That is a narrower claim, but it is an honest and fast test of whether the oscillator works once routing is learnable.

## Candidate ranking

As standalone interventions:

1. **(e) Direct salience supervision — strongly recommended.** It supplies the missing, correctly signed gradient directly to the logits.

2. **(d) Auxiliary prediction at rule/update ends — useful after salience works.** Add it rather than replacing query-position aux, because query aux tests retention. Alone, statement-end state is still polluted by all preceding filler.

3. **(b) Higher salience LR — accelerator only.** Under the present loss it amplifies filler noise. It becomes useful once direct supervision supplies the correct direction.

4. **(a) Mostly-closed initialization — useful only with (e).** Uniformly scaling all inputs leaves the filler/rule ratio unchanged, and later RMS normalization largely cancels uniform scale. At −4, downstream sigmoid gradients are also about 14× smaller than at zero.

5. **(c) L1/entropy prior — do not use alone.** It will coherently close everything. The weak downstream loss cannot selectively reopen rule tokens. Balanced BCE already provides a much cleaner closing signal.

If salience separates cleanly but query aux remains flat, then add rule-end auxiliary supervision. That would distinguish “capture failed” from “retention failed.”

## Additional code finding: base salience is effectively canceled

For the base arm, [control_states()](/home/bmarti44/stencil-llm/src/stencil/gpt2.py:265) returns `g_t * embedding_t`, immediately followed by per-token RMS normalization at [gpt2.py:287](/home/bmarti44/stencil-llm/src/stencil/gpt2.py:287):

\[
\operatorname{norm}(g e) \approx \operatorname{norm}(e)
\]

for positive, non-negligible \(g\). Therefore ordinary salience changes have essentially no downstream effect in the base arm.

The current test sets the bias to −30 at [test_gpt2.py:186](/home/bmarti44/stencil-llm/tests/test_gpt2.py:186). At that extreme, the normalization epsilon dominates, so the test observes a change; it does not prove useful sensitivity around gates of 0.1–0.9.

This does not cause the oscillator failure, but base salience quantiles are not meaningful evidence of actuator behavior.

**Severity: medium. Confidence: high.**
