Never fit on any exposed bank or its outputs.

**Prepare one end-to-end DEV test of automatic rule selection immediately followed by code in the same worker response.** Rank: (1) worker co-emission, (2) separate extraction/reconciliation, (3) trained small interpreter. This ranking concerns the most useful next experiment, not established success probabilities. Keep the recurrent updater line and failed fixed source reader parked.

## Three options, one choice

| Rank | Mechanism and strongest case | Counterevidence / decision |
| --- | --- | --- |
| 1. Coding worker selects rules, then writes code | Directly tests the desired behavior from ordinary natural requests. A short disposable selection precedes code in the same generation, so selection can influence that answer without a separate maintenance service or trained model. | This is a new executable endpoint and coupled generation task, not evidence that code context cures empty outputs. Selection can be wrong, waste output budget, or harm otherwise good code. Test against retained history and accurate manual reminders. |
| 2. Extract changes, then reconcile | Stage1 interprets only the new message with necessary original context, producing semantic changes with scope, modality, target description and source evidence; stage2 maps them to actual state operations. Separate recorded stages reveal where failure occurs. | Cold2/2 supports only the easiest extraction cases. References, restoration and scope remain semantic work; a bad extraction can poison reconciliation. Two model calls and an interface add cost and failure surfaces. This is worth a full pipeline gate only if direct worker selection fails or a separate persistent store becomes necessary. |
| 3. Fit a small dedicated interpreter | Changes learned behavior rather than repeatedly rewriting prompts; inference can eventually be cheaper than the large worker. Audited synthetic supervision is feasible in principle. | Kimi labels can encode wrong scope/lifecycle semantics. Memorizing authored phrasing is not generalization, and successful SFT on a small local budget is unproved. Do not start a full updater fit without a source/label audit, grouped split, training-cost projection and frozen sequence-level gate. |

## Primary evidence that changes the decision

**Decomposition has precedent, not an isolated causal result.** Mem0's original method extracts candidate facts then reconciles them against retrieved memories using an LLM. It used GPT-4o-mini, not this Qwen. Its conversational QA experiment does not measure complete scoped instruction histories. Moreover, the authors later replaced reconciliation with additive extraction, citing destructive updates while changing retrieval too. These sources support testing explicit stage boundaries, not adopting the old design as settled. [Chhikara et al., 28 April 2025, section2.1](https://arxiv.org/html/2504.19413v1); [Yadav / Mem0, 16 April 2026](https://mem0.ai/blog/mem0-the-token-efficient-memory-algorithm). Confidence: high on designs; low on transfer.

**Training can improve memory behavior, but the closest evidence is expensive RL.** Mem-α compares trained and untrained Qwen3-4B within the same memory framework, reporting higher average validation performance after training. Its recipe used 32H100 GPUs for three days, approximately2,304GPU-hours. It also argues that teacher-generated memory traces can be unreliable. Thus it supports learnability but does not support a one-hour Kimi-SFT claim. [Yu Wang et al., 30 September 2025, sections3–4.3](https://arxiv.org/html/2509.25911v1). Confidence: moderate for transfer, no local cost guarantee. Self-Instruct shows filtered model-generated instructions can improve instruction tuning; it does not establish correct scope/reinstatement labels or the required sample count here. [Yizhong Wang et al., 25 May 2023 revision](https://arxiv.org/abs/2212.10560v2).

**Co-emission is an experimentally justified question, not a literature-proven repair.** Plan-and-Solve provides a precedent for producing intermediate work before solving a task; its GPT-3 reasoning results do not establish coding-rule selection. Intrinsic self-correction can also fail or degrade reasoning, so generated assertions of compliance are not an outcome measure. [Lei Wang et al., 26 May 2023 revision](https://arxiv.org/abs/2305.04091v3); [Huang et al., 14 March 2024 revision](https://arxiv.org/abs/2310.01798v2). Confidence: low on exact transfer. Executing code with independently frozen checks is what makes the next test informative.

## Smallest meaningful gate to prepare

Propose four new Kimi-authored conversations, six coding requests each, with natural intervening changes:24 coding decisions. Across the four trajectories cover multiple simultaneous obligations, global/task scope, requirement/permission, replacement, withdrawal/restoration, task override cancellation, rejected quotations, tool text and explicit user adoption. Every rule must have an independently checkable behavioral consequence; include ordinary functionality checks so compliance cannot be bought by producing useless code. Before inference, audit reference solutions and deliberate stale-scope/withdrawal mutants. This is new DEV informed by earlier mechanism failures, not clean confirmation.

Run three fixed arms through all24 decisions: **H**, actual retained source/answer history; **C**, the same worker with an automatically generated brief applicable-rule selection immediately before its code; **M**, the worker with accurate, independently authored manual prose reminders plus its actual history. Seventy-two calls total. M is an evaluation control, never an input requirement for C or H. Use the same trunk/settings and total output cap; never use M's answers or reminders to repair either automatic arm.

Carry each arm's own code answers and immutable natural source messages forward. Keep C's selection in its receipt, but do not inject it as a future note or authoritative instruction. Preserve authenticated source roles; assistant/tool content remains context unless the user adopts it. A claimed source ID or exact quotation does not prove correct scope. No register updates, retries, manual interventions or self-scored success.

Predeclare a strict feasibility bar: C must produce working code satisfying every active obligation on all24 decisions and all four trajectories, with no cap/transport failure. Require M24/24 to establish the intended competence control; otherwise the comparison is inconclusive about automatic selection parity. Report H alongside C and M, including exact paired wins/losses, executable failures, stale-rule leakage, scope errors and invented constraints. Do not count turns as independent episodes. Audit selections separately: correct code with incorrect stated rules supports observed coding behavior, not a reliable explicit selector. If H already passes everything, C establishes no gain over ordinary history and its added cost needs justification.

A completed failure parks this co-emission recipe; no near-identical repair loop. A pass earns a separately registered larger executable evaluation, not deployment or broad non-inferiority. This is the next falsifiable capacity question: **can the actual worker turn natural history into correct constrained code, and does explicit automatic selection help or interfere?** It avoids another prerequisite-only interpretation trial.

## Cost, training alternative and stopping point

At the prior [registration's](PROTOCOL.md) measured24.75completiontokens/s, 72calls capped at1,024tokens imply about2,979decode-seconds; adding600startup and60cleanup gives about3,639seconds, or61minutes, before additional prefill variability. At1,536tokens the same arithmetic gives about85.5minutes. These are extrapolations, not measured runtime promises. CPU sizing must establish sufficient code-plus-selection space and a full-run budget before any launch; do not shrink the bank or truncate required code to meet a nominal ceiling. Record token/latency overhead of C against H and M. Same-call selection avoids a second request, not its extra decoding tokens.

If choosing training later, first author wholly new FIT families and separate development/sequence-test families; keep all paraphrases, related targets and episodes in one split. Independently audit natural-language-to-change labels, including no-op negatives and crossed scope/lifecycle cases. Compare a frozen untrained small model with one frozen fitted checkpoint under the identical contract, and roll sequences from each model's actual state. Teacher-forced accuracy with gold previous states alone is insufficient. There is no evidence-supported magic512-example dose or cheap training duration to prescribe here. A CPU artifact/data review and measured cost preflight can make that proposal concrete; neither is bundled into this memo.
