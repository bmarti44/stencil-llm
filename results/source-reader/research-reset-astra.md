**Why defer A and B.** A, per-message semantic extraction followed by state reconciliation, makes stage errors observable and can isolate interpreting a message from selecting a stored target. But context-dependent references, global/task scope, and restoration still require semantic reasoning. Correct reconciliation cannot recover an obligation the extractor omitted, and incorrect intermediate interpretations may become durable state. The two successful cold messages do not establish that this split works. B, a dedicated interpreter trained on wholly new Kimi data, changes the learned policy more substantially, but adds label-quality, distribution-shift, training-cost and rollout-validation questions before reaching the coding endpoint. Neither option is rejected as impossible; neither should run in parallel with C or become an automatic fallback after any unfavorable C result.

**The smallest useful next gate is four independent new conversations, six coding requests each, three arms: 72 worker calls.** New Kimi authoring should use the abstract mechanism specification and new task families, without old prompts, outputs, benchmark cases or failure-specific paraphrases. Author natural messages, small evolving code artifacts, private functionality checks, applicable-rule annotations and correct manual prose. Independent review must resolve ambiguous semantics and verify executable reference solutions before freezing the recipe and bank. All related turns and variants belong to one episode. This is newly authored development screening, not pristine confirmation of a research program already informed by failures.

Each episode should maintain an actual code artifact across requests and include a return to a previously visited task. Across the four, cover admission, persistence through irrelevant material, task switching, global/task exceptions, replacement, withdrawal/restoration, cancellation of an override, permission versus requirement, quoted/tool material, and explicit adoption. Every episode must exercise a real change followed by a later use; independent snapshots do not test a trajectory. Every obligation must have a checkable behavioral consequence. Where a permission does not require a particular implementation, the checker must not invent one. Reference checks and deliberately wrong retired-rule/scope variants must demonstrate that failures are observable before any model output exists.

The three arms use the same pinned worker/settings, code-submission interface, natural source messages, coding tasks, output limit and execution rules:

- **H — retained history:** ordinary coding with the arm's actual earlier code and public tool outcomes.
- **C — automatic recap:** the same workload, with a short applicable-obligation recap immediately before code in the same response. The original natural history remains available. No oracle reminder, gold state, extraction service or corrected recap enters this arm.
- **M — accurate manual prose:** the same workload plus independently authored correct current reminders, supplied as an evaluation control. Neither its reminders nor its code may repair another arm.

Each arm carries its own actual code state forward. Keep every raw response in receipts, but omit prior C recaps and prior M reminder blocks from later model requests; retained assistant content is their code and ordinary task-relevant output. Make this history construction explicit and identical apart from the registered intervention. Preserve authentic source roles and required adoption antecedents. Freeze any public test-feedback policy; private assertions and rule annotations never enter worker context. No gold code resets or outcome-dependent repairs. Use one simple code region understood by the same consumer in all arms; surrounding recap text must not become a parser penalty accidentally counted as code incompetence.

Proposed prospective **SCREEN-GO**: C has correct code and applicable-obligation behavior on all 24 requests and all four complete trajectories; its recaps also contain all applicable obligations without invention, stale leakage or scope/modality errors; M passes all 24 coding requests; zero human corrections or extra model calls occur; accounting and measured cost are complete. Score code functionality, obligation behavior and recap semantics separately before forming that joint gate. Correct code with a wrong recap does not qualify the explicit selector. Report every H/C/M episode, including C losses on functionality alone. If M fails, the screen fails to establish automatic/manual matching; do not repair its prompts or silently remove difficult tasks. If H also passes everything, the screen shows no measured benefit for C and provides no reason to scale C simply because it passed.

A completed semantic or executable miss parks this fixed co-emission recipe. A transport/deadline failure is incomplete evidence; an output-cap finish fails capacity eligibility rather than earning a shorter rerun. No prompt repairs, retries, extra examples, sampling switch or fitted rescue within this screen. A useful pass goes directly to larger fresh validation of the unchanged method. It does not earn an open-ended sequence of interpretation pilots.

**Adequate larger proof is a separate, predeclared gate.** Four perfect episodes still have a one-sided exact 95% upper failure-probability bound of `1 - 0.05^(1/4) = 52.71%`; even four favorable paired discordances give one-sided sign-test `p = 1/16 = 0.0625`. Twenty-four correlated turns do not increase the independent sample to 24. No equivalence, reliability or general improvement claim follows from SCREEN-GO.

Before larger authoring, specify the population of coding work, an acceptable practical loss margin versus M, the primary whole-episode endpoint, and a sample-size calculation.
