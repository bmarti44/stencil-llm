# Source-only request-time reader — draft prospective DEV registration

Fit-on: none. Development-on: the already exposed, independently audited Kimi K3 two-by-eight prose-maintenance bank. Evaluated-on: none. Earlier output failures informed this architectural proposal. No old frozen evaluation examples, responses, benchmark data, gold annotations or prior generated notes enter any reader prompt. This is development feasibility, not clean validation.

Prospective recipe: independent Astra decision review supports this 48-view check in place of the four-call note ablation. Implementation and readiness review remain pending. No inference has been launched under this document.

The failed recurrent updater line remains parked after three full-maintenance failures. The distinct proposed mechanism stores immutable authenticated source messages, selects the obligations applicable to the current request directly from that history, and discards the generated selection after use. No generated selection is carried into a future reader call. The earlier updater already saw full natural history; this experiment cannot attribute a gain to recovering missing history, or causally isolate the removal of notes from the narrower output task.

Schedule all 48 fixed requests: episode order as authored, chronological turns 0–7, then GLOBAL and the two declared task handles in declared order. Each independent call receives only the natural authenticated messages through that turn, chronological source IDs and roles, declared handles, requested task (none for GLOBAL), and request kind code_answer. GLOBAL asks for obligations applying without a named task. Task requests must include all applicable global rules and task exceptions. Future messages, gold labels, old model notes and outputs of other calls are forbidden inputs. All 48 prompts are fully knowable before launch and must be previewed and frozen byte-for-byte.

Ask for concise prose containing every applicable active standing obligation, preserving scope, strength and exceptions, plus supporting source IDs and brief exact source spans. Resolve replacements, cancellations, restoration and adoption from chronological sources. Non-user sources do not become authority unless explicitly adopted by the user; one-off requests and unadopted quotations do not become standing rules. Do not infer completion. Citations support independent review and do not constitute an automatic correctness gate. Do not ask for register transactions or a maintained all-task state. No human repair, retry, gold reset, post-output prompt adjustment or automatic semantic repair is allowed.

The registered semantic bar is complete agreement for all 48 applicable views and both full eight-turn episode trajectories. Count definite errors and ambiguous interpretations separately; an ambiguous view does not satisfy unambiguous completeness. Meaning, not exact annotation wording, governs. Independently audit every claim of applicability, modality, lifecycle and supporting evidence, including missing obligations. Correct source substrings alone do not establish authority, current validity or completeness. Any unsupported/invented obligation or missing active obligation fails the bar. Any transport, length or character-cap error leaves the fixed run incomplete rather than silently reducing the sample. COMPLETE in a manifest means call accounting only.

Use the existing pinned local Qwen3-30B-A3B serving recipe and single-attempt audited HTTP transport, thinking disabled, temperature0, seed20260907, maximum1024outputtokens. Reservation ceiling 2,700 seconds (45 minutes), including startup capped at600seconds and a60second cleanup reserve. Earlier measured throughput was2,230completiontokens/90.094callseconds, approximately24.75tokens/second. Forty-eight calls each reaching the1,024token cap project roughly1,986callseconds, plus600startup and60cleanup, about2,646seconds. This is an extrapolation, not a guaranteed bound: additional prompt/evidence work can slow generation. The hard deadline still stops and preserves an incomplete run without retry or sample reduction. Typical shorter outputs should finish well below the ceiling; only actual timing is reported as measured cost. Preserve the exact input/code/weight receipt pins, requests, raw HTTP responses, output text, IDs, source history, tokens, timing and partial records in the same run. No worker or coding success claim is bundled.

A failed run parks this fixed source-reader recipe; it does not earn another near-identical prompt repair. A pass only earns preparation of a genuinely fresh larger end-to-end coding test, comparing automated reminders with ordinary retained history and accurate manual prose while measuring executable correctness, adherence, latency/tokens and human interventions. Automatic parity with good manual notes can be valuable; superiority over ideal manual prose is not required. Correlated views are not independent statistical episodes. The full goal remains unproved until adequate broader executable evidence exists.
