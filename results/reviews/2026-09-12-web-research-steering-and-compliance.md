# Web research: attention steering and convention-compliance for 1.7B–4B models

Date: 2026-09-12 · Author: Claude Opus 5 (web research, max reasoning effort)
Scope: literature only. No local code read or modified. All numbers carry a URL and date.
Task framing: frozen Qwen3-1.7B/4B must APPLY a regex-checked coding convention (e.g. `gn_` prefix)
stated earlier in a long session (MemoryCode, ACL 2025). Tonight's finding: 1.7B scores strict 0
even on an ORACLE reminder — it paraphrases the rule in prose and then does not apply it in code.

---

## Executive summary (ranked interventions)

1. **Verifier-gated sampling (best-of-N against your own regex) is the highest-probability fix, and also the decisive diagnostic.** Inverse IFEval: on counter-intuitive instructions where models score ~47–55% at N=1, Best-of-N (N=32) pushes four models to ~90% — the capability exists, the single-sample policy fails. Measure pass@k on the oracle arm first: pass@32 > 0 means a policy problem; pass@32 = 0 means a true capability floor at 1.7B and no inference-time trick will save it.
2. **External check + deterministic repair pass** (lint/regex → rewrite). Strongest measured convention effect anywhere: Pylint convention violations 84.21% → 12.28% (GPT-4o); one oracle-verifier turn lifts mechanically-checkable repo rules to 90–100%; runtime-enforced rules cut violations 100% → 2% OOD.
3. **Constrained decoding at the `def ` site.** The only intervention with a guaranteed floor lift, and untested in the literature for naming conventions. Keep it narrow: whole-output schema decoding costs a 3B model 15.3 answer-accuracy points ("constraint tax").
4. **Attention boosting of the reminder span (frozen additive pre-softmax bias) — your planned intervention is real and correctly specified.** GUIDE (Δ=+2 on tagged tokens, all layers) is additive pre-softmax and includes a 2B model: +30% on JSON generation, 29.4% → 60.4% on its main task. SpotLight on Qwen2.5-3B: IFEval prompt-level 0.42 → 0.53, with the gain concentrated in **structural/format** constraints and explicitly "small" on lexical ones. InstABoost is the cleanest strength/quality tradeoff but 7–8B only.
5. **Scale and thinking mode.** Qwen3-4B is materially better than 1.7B on every instruction axis (IFEval 81.2 vs 68.2; code-instruction-following 18.0% vs 13.3%). Thinking mode helps at every size and dominates on counter-intuitive instructions.
6. **Switch the primary metric to fractional compliance.** Strict all-or-nothing scores are a known dead zone below ~8B (CodeIF CSR 0.03–0.10 at 1–3B vs SSR 0.22–0.45; CIFE 2B: 0.177 strict vs 0.691 soft).
7. **Do NOT expect more prompt engineering to help.** Rules-file size, position, architecture and conflicts are a measured null across 1,650 agent sessions (BF10 0.05–0.10); compact vs verbose constraint encoding is a null (Cliff's δ < 0.01) across 11 models / 830 invocations.
8. **Do NOT expect memory/synopsis/RAG to help.** MemoryCode's own ablation: handing the model ONLY the instruction chain (perfect memory) reproduces the collapse. Mem0 on rule-application: 3.4 vs 82.4 for plain long context.
9. **Do NOT expect self-critique to help at 1.7B.** Models already restate the rule correctly while violating it (probe accuracy 97.3%, knows-but-violates up to 99%). In frozen 0.5–1.5B code models, informed self-repair tied blind resampling (9.0% vs 9.0%).
10. **Your oracle floor is informative, not a bug:** verbatim restatement right before the request already buys the full positional/recency benefit, so the residual gap is capability/policy — which is why the fix has to be verifier-side or scale-side, not prompt-side.

## Q1 — Attention steering / amplification of instruction spans

### The method family, precisely

| Method | Mechanism | Pre- or post-softmax | Layers/heads | Strength | Frozen? |
|---|---|---|---|---|---|
| **PASTA** (2311.02262, ICLR 2024) | rescale attention *probabilities* on emphasized span, then renormalize: `[T(A)]_ij = αA_ij/C_i if j∈G else A_ij/C_i`, default **α = 0.01** (i.e. scale non-emphasized DOWN) | **post-softmax + renormalize** | selected subset, **53–86 of 294 heads** on LLAMA-7B; profiling needs ~1,000 samples × 4 tasks | α stable 0.002–0.05 | yes |
| **AutoPASTA** (2409.10790) | prompt the model to emit the key sentence, then PASTA-upweight that span | post-softmax | as PASTA | — | yes |
| **GUIDE** (2409.19001, NeurIPS 2024 MINT) | `w̄ = w + Δ` on tokens between `<!-> <-!>` tags | **additive pre-softmax** | **all layers** where tags appear | **Δ = 2** for instructions, Δ ≈ 1 retrieval, Δ ≈ 3 JSON; safe ≤ 5 | yes |
| **SpotLight** (2505.12025, EACL 2026) | additive, *dynamic*: `B = log(ψ_target/ψ_current)` only when the span's attention share falls below target | **additive pre-softmax** | **all layers, all heads** | ψ_target = 0.1 default | yes |
| **InstABoost** (2506.13734, ICLR 2026) | **constant additive bias B on instruction-key attention logits** (equivalently multiplies the instruction softmax numerator by e^B) | **additive pre-softmax** | **all layers, all heads** | multiplier M ∈ [1,20], tuned on validation | yes |
| **DIRECTER** (2603.06745, ICLR 2026) | element-wise scale instruction **key vectors** in the KV cache (α = 100) + plausibility-gated decoding that backs strength off per step | KV-side | sensitivity-ranked layer subset | α stable 10¹–10⁵ | yes |
| **Guiding Giants** (2505.20309) | trainable controller predicts global + per-layer scale of an **activation** (not attention) patch | n/a (activation steering) | all layers | learned | needs a trained controller |
| **Stolfo et al.** (2410.12877, ICLR 2025) | instruction-specific **activation difference vector** added at one layer | n/a | single optimal layer | coefficient c (e.g. 20) | yes |
| **Memory Inception** (2605.06225) | inject text-derived KV slots at selected layers | KV-side | selected | — | yes |

**Answer to "is a frozen additive pre-softmax bias on selected prompt tokens what they do?"** — Yes, for **GUIDE, SpotLight and InstABoost**. That is exactly the family. PASTA is the post-softmax variant and needs per-model head profiling; DIRECTER is the KV-scaling variant.

### Results and model sizes

- **PASTA** — GPT-J-6B and LLAMA-7B only. LLAMA-7B: JSON Format 96.64 format / 85.09 prediction acc.; Pronouns 96.42; BiasBios 95.28; CounterFact 99.60 ES. Headline: **"average accuracy improvement of 22% for LLAMA-7B"**, and 53% on Pronouns Changing. Degeneration: steering too many heads "over-amplifies user-specified information at the expense of other essential information"; fluency drops 6.10 → 4.62 on pronouns in the task-agnostic variant; **GPT-J-6B JSON prediction accuracy collapses to 18.63% despite 91.50% format accuracy** — the exact "got the format, lost the content" failure you must watch for. https://arxiv.org/abs/2311.02262 · https://ar5iv.labs.arxiv.org/html/2311.02262 (Nov 2023 / ICLR 2024)
- **AutoPASTA** — average **+7.95% for LLAMA3-70B-Instruct**. No small models. https://arxiv.org/abs/2409.10790 (16 Sep 2024)
- **GUIDE** — **Mistral-7B-Instruct and Gemma2-2B-Instruct** (the only ~2B result in the attention-steering literature, and both "showed consistent improvement patterns with identical Δ values"). Main task 29.4% → 60.4% at Δ=2; Needle-in-Haystack 87.0% → 92.1% at Δ≈1; **JSON generation +30% average at Δ≈3**; beats SFT up to 1M training tokens. Degeneration: **Δ > 5 produces "nonsensical outputs" and token repetition**; at Δ=9, a phrase repeats dozens of times. Also ships `Influence`, a non-gradient per-token propagation metric (ROC AUC 0.62–0.74 for predicting instruction-following success) — usable as your instrumentation for "did the reminder actually get attended to". https://arxiv.org/html/2409.19001 (NeurIPS 2024 workshop)
- **SpotLight** — Qwen2.5 **3B**/7B/72B, Llama-3.1 8B/70B, Granite-3.1-8B, Mistral-7B-v0.2. IFEval prompt/instruction: **Qwen-3B 0.42/0.53 → 0.53/0.62**; Llama-70B 0.45/0.57 → 0.54/0.64; average **+26% prompt-level, +17% instruction-level**. ManyIFEval Qwen-3B 0.15/0.53 → 0.19/0.62. Multi-turn MT-IFEval: baseline loses 18.2% across turns, SpotLight only 9.3%. HotpotQA +10% over baseline, +6% over PASTA. **Constraint-type breakdown (critical for you): "most impact on structural constraints … output formats, templates, punctuation"; lexical-constraint improvements "small."** Over-steering at high ψ_target makes output incoherent and causes refusal of benign prompts. https://arxiv.org/html/2505.12025 · https://aclanthology.org/2026.eacl-long.174/ (EACL 2026)
- **InstABoost** — **Llama-3-8B-Instruct** primary, gemma-7b-it in Appendix D. **No model below 7B.** Steering success over 15 tasks: InstABoost 0.925 (AI Persona), 0.880 (Emotion), 0.594 (Jailbreak), 0.625 (QA), 0.620 (Toxicity) vs PASTA 0.885/0.823/0.000/0.560/0.580 and SpotLight 0.790/0.927/0.025/0.580/0.580. Default (no instruction) is 0.160/0.043/0.006/0.590/0.050. At maximum tested strength **M = 19** outputs stay "fluent and directly relevant" — only a "small, gradual decline", vs latent methods' fluency collapse (DiffMean α=0.6 degenerates into repetition) and SpotLight's relevance collapse at ψ_target=0.4. Theory: instruction-following as **rule competition**; Theorem 3.2 gives a subversion-budget inflation factor `Infl(B) = (m·e^B + k)/(m + k) ∈ [1, e^B]`; Theorem 3.3 warns excessive boosting suppresses task-relevant context. **No code-generation or formatting benchmark.** https://arxiv.org/html/2506.13734 · https://iclr.cc/virtual/2026/10019172 (Jun 2025 / ICLR 2026)
- **DIRECTER** — the only steering paper with a **1B** number, and it is the warning shot. Llama-3.1-8B: IFEval 73.5/81.5 → **78.8/84.8**; GSM8K-Format **79.2 → 99.1 format** with task accuracy 82.7 → 86.9; LIFBench MultiDoc 40.9 → 51.7; overall 70.0 → 76.5. **Llama-3.2-1B-Instruct: 61.3 → 61.6 on IFEval (+0.3 pp). Qwen-2.5-3B: 63.9 → 67.1 (+3.2 pp). 8B: +4.9 pp.** The paper states "prior steering baselines also exhibit similar inconsistency" at small scale. Also documents oversteering in the baseline: **PASTA* on GSM8K-Format trades task accuracy 82.7% → 62.7% to win formatting.** https://arxiv.org/html/2603.06745 · https://iclr.cc/virtual/2026/poster/10009750 (Mar 2026 / ICLR 2026)
- **Guiding Giants** — Llama-3.1-8B, **Llama-3.2-1B**, Mistral-7B; activation steering for harmfulness, not instruction following; requires training a controller. Not applicable to a frozen-weights constraint. https://arxiv.org/abs/2505.20309 (May 2025)
- **Stolfo et al., ICLR 2025** — **Phi-3 Mini, Gemma-2 2B, Gemma-2 9B, Mistral-7B-v0.1.** Format instructions with NO instruction text: ~10% → ~30% across all models. **Format instructions WITH the instruction present in the prompt: baseline 60–90%, and steering still improves 2 of 4 models** — the paper's framing is that steering "counters instruction drift" even when the instruction is visible, which is the closest published analogue to your oracle-arm question. Cross-model transfer: vectors from instruction-tuned Gemma-2 2B sometimes beat same-model steering on the base 2B. Quality cost comparable to just adding the instruction, with "nonsensical tokens or repetition" in some cases. https://arxiv.org/abs/2410.12877 · https://ar5iv.labs.arxiv.org/html/2410.12877
- **Memory Inception** (2605.06225, 9 May 2026) — Llama-3.1-8B and Qwen3-30B-A3B; **no 1–4B**; personality/dialogue steering, 6–118× KV savings, no capability loss on GSM8K/MMLU. Not an instruction-following result.
- **Scale caveat from the steering literature generally**: steering effectiveness is widely reported as scale-dependent and high-variance; composition of 3 behaviours goes 59.5% at 8B → 68.0% at 14B, and sub-3B activation spaces have "less clean directional structure". See also "On the Limits of Steering Vectors for Preference-Aligned Generation" (https://arxiv.org/html/2607.01802) and "Analysing the Safety Pitfalls of Steering Vectors" (https://arxiv.org/html/2603.24543v1).

**Nothing in this family reports results on a ~1–4B model following a formatting/coding constraint.** The nearest points are GUIDE's Gemma2-2B JSON (+30%) and SpotLight's Qwen2.5-3B structural constraints. Your experiment would be new evidence.

## Q2 — Instruction-following failures of small models on constraint-heavy prompts

### Baseline capability by size

- **Qwen3 technical report** (https://arxiv.org/html/2505.09388v1, 15 May 2025), IFEval strict prompt accuracy — thinking / non-thinking: 0.6B **59.2 / 54.5**; **1.7B 72.5 / 68.2**; **4B 81.9 / 81.2**; 8B 85.0 / 83.0; 14B 85.4 / 84.8; 32B 85.0 / 83.2. Multi-IF: Qwen3-32B 73.0 / 70.7. Note IFEval's constraints are single-turn and shallow — 1.7B at 68–73 there contrasts sharply with its code-constraint numbers below.
- **IFEvalCode** (https://arxiv.org/abs/2507.22462, 30 Jul 2025; 1.6K samples, 7 languages, 40+ LLMs; decouples Corr. from **Instr.** = coding style / line count / structural constraints), English split: Qwen3-0.6B 6.2 / **12.7**; **Qwen3-1.7B 12.5 / 13.3**; **Qwen3-4B 15.4 / 18.0**; Qwen3-8B 17.4 / 15.3; Qwen2.5-Coder-1.5B 13.2 / 11.4; -3B 16.7 / 14.4; -7B 26.7 / 16.0. **This is the single most transferable table: Qwen3-1.7B follows code-style instructions 13.3% of the time in SHORT-context single-turn conditions, before any session burial.** (Caution: my two extractions disagreed on the Llama-3.1-8B row — one returned 18.1/10.6, the other 29.9/20.7, the latter colliding with the ControlledCoder base row. Re-pull that row before citing it. The Qwen3 rows were consistent across both pulls.)
- **CodeIF** (https://arxiv.org/abs/2502.19166, Feb 2025; ACL 2025 Industry) CSR (all constraints) / SSR (mean fraction): Llama-3.2-1B **0.034 / 0.218**; Qwen2.5-Coder-1.5B 0.058 / 0.358; Qwen2.5-3B 0.078 / 0.415; Qwen2.5-Coder-3B 0.097 / 0.445; Qwen2.5-Coder-7B 0.142 / 0.514; Llama-3.1-8B 0.145 / 0.467; GPT-4o 0.383 / 0.748; DeepSeek-V3 0.414 / 0.821.
- **CIFE** (https://arxiv.org/html/2512.17387, 22 Dec 2025; 1,000 Python tasks, ~7 constraints each, 13 categories) CSR / SSR / C2A: Granite-3.1-2B **0.177 / 0.691 / 0.055**; Granite-3.1-8B 0.309 / 0.801 / 0.117; Granite-3.3-8B 0.393 / 0.824 / 0.152; **Granite-3.3-8B reasoning 0.449 / 0.844 / 0.200**; Llama-3.1-8B 0.419 / 0.832 / 0.166; Qwen3-8B 0.638 / 0.914 / 0.310; GPT-4o 0.656 / 0.924 / 0.479; o3-mini 0.840 / 0.967 / 0.720. "Adherence declines sharply as the number of requirements grows."
- **StyleMBPP** (inside https://arxiv.org/html/2509.21051, Sep 2025) — Python generation under **style constraints** (license header, indentation, docstrings, line length, variable-name length). Prompt-level accuracy at n=6: GPT-4o 0.68, **Claude-3.5-Sonnet 0.01**, Gemini-1.5-Pro 0.13, o3-mini-high 0.37. Functional correctness stays stable while joint compliance collapses. **A frontier model scoring 0.01 on six code-style constraints is the same failure shape as your 1.7B floor — it is not unique to small models.**
- **ManyIFEval** (same paper) prompt-level at n=1/5/10: GPT-4o 0.94/0.57/0.21; Claude-3.5-Sonnet 0.95/0.72/0.48; Gemini-1.5-Pro 0.96/0.71/0.39; o3-mini-high 1.00/0.90/0.78; DeepSeek-R1 0.95/0.71/0.38. Models evaluated include **Gemma-2-2B** and Llama-3.1-8B. Naive independence (products of single-instruction rates) predicts poorly (MAE 0.21 ± 0.07); a logistic model on instruction count alone gets MAE 0.04 ± 0.03 — degradation is a systematic load effect, not independent per-constraint failure.
- **IFScale** (https://arxiv.org/pdf/2507.11538 / https://www.emergentmind.com/papers/2507.11538, Jul 2025; 500 keyword-inclusion instructions, 20 models): best frontier models reach only **68% at 500 instructions**. Three degradation regimes — threshold decay (o3, Gemini-2.5-Pro), linear (GPT-4.1, Claude-3.7-Sonnet), **exponential (Claude-3.5-Haiku, Llama-4-Scout — i.e. the weaker/cheaper models)**. Primacy effects peak around 150–200 instructions. Errors are overwhelmingly **omission** as density rises; reasoning models shift toward modification instead.
- **Reliability** — "Revisiting the Reliability of Language Models in Instruction-Following" (https://arxiv.org/html/2512.14754v1, 15 Dec 2025; IFEval++, `reliable@k`, 46 models, 0.6B–80B+): relative accuracy drop to the reliability metric is **61.8% for Qwen3-0.6B** vs **18.3% for GPT-5**. Small models are not just lower, they are far more fragile to rephrasing and distractors.
- **Inverse IFEval** (https://arxiv.org/html/2509.04292v1, Sep 2025) — "**cognitive inertia**": failure to follow instructions that conflict with SFT-learned conventions. Eight task types including **Counter-Conventional Formatting** and **Code without Comments**. English scores: o3-high 75.66; o3-mini 74.67; GPT-5-high 73.72; GPT-OSS-120B 64.59; Qwen3-235B-A22B-Thinking 54.22; Qwen3-30B-A3B-Thinking 49.21; **Qwen3-32B 47.04**; DeepSeek-R1 50.00; **Qwen3-30B-A3B-Instruct (non-thinking) 30.43**. Thinking mode beats non-thinking consistently. **The key intervention: Best-of-N with N=32 pushes four models to ≈ or > 90%, "suggesting the benchmark lies within their capability."** Your `gn_` prefix is precisely a counter-conventional formatting instruction, so this is the most on-target generalization in the whole sweep.

### Does placement / checklist formatting / "repeat the constraints" help?

- **Placement: measured null at agent scale.** "Instruction Adherence in Coding Agent Configuration Files: A Factorial Study of Four File-Structure Variables" (https://arxiv.org/abs/2605.10039, 11 May 2026) — **1,650 Claude Code CLI sessions, 16,050 function-level observations**, Sonnet 4.6 primary + Opus 4.6/4.7. Overall instruction-compliance 63–64%. **None of file size (25–500 lines), instruction position (top/center/bottom), monolithic vs distributed architecture, or conflicting adjacent files produced a detectable contrast after multiple-testing correction**; affirmative-null Bayes factors BF10 0.05–0.10 for the size and conflict nulls. The one robust effect: **within-session attenuation of ~5.6% lower compliance odds per additional generated function (OR 0.944, 95% CI [0.937, 0.951], p < 10⁻⁴²)**, plus a huge task-identity effect (84.4% vs 45.1%, p < 10⁻⁷⁷). Single-author preprint — weight accordingly, but it is the largest-N study on exactly this question.
- **Encoding/format: measured null.** "Compact Constraint Encoding for LLM Code Generation" (https://arxiv.org/abs/2604.07192, 8 Apr 2026, rev 22 Apr 2026; Hanzhang Tang) — 6 rounds, **11 models, 16 tasks, 830+ invocations**: compact headers cut constraint tokens ~71% and full prompts 25–30%, but **"no statistically significant differences in constraint satisfaction rate across three encoding forms or four propagation modes; Cliff's δ < 0.01, 95% CI ±2.6 pp."** The two things that DO move compliance: **constraint type (Δ = 9 pp normal vs counter-intuitive) and task domain — "counter-intuitive constraints opposing model defaults fail at 10–100%, while conventional constraints achieve 99%+ compliance regardless of encoding."** Also: **"model self-assessments systematically overestimate compliance relative to rule-based scoring, revealing a gap between constraint understanding and execution."** Conclusion quoted: "engineering effort toward compliance is better directed at constraint design than prompt formatting." **Read-across: `gn_` is a counter-intuitive constraint; no amount of reminder formatting will move it, and the model's own claim to have applied it is worthless.**
- **Repetition: strong positive, but off-target benchmarks.** "Prompt Repetition Improves Non-Reasoning LLMs" (Leviathan, Kalman, Matias, Google; https://arxiv.org/pdf/2512.14982 / https://arxiv.org/html/2512.14982v1, 18 Dec 2025). Method: duplicate the whole prompt verbatim (`<QUERY><QUERY>`), variants with "Let me repeat that:" and ×3. **Without reasoning: 47 wins / 0 losses / 23 neutral out of 70 tests. With reasoning: 5 wins, 1 loss, 22 neutral.** Largest gain: Gemini-2.0-Flash-Lite **21.33% → 97.33%** on a custom NameIndex task. Mechanism: causal attention means past tokens cannot see future ones; the second copy lets every prompt token attend to the whole prompt. Controls: padding with periods gives nothing — the gain is semantic repetition, not length. Repeating only the question gives nothing. **Caveats for you: seven frontier API models, no small open models, no sizes disclosed, and the benchmarks are ARC/OpenBookQA/GSM8K/MMLU-Pro/MATH + two custom retrieval tasks — no instruction-following or formatting benchmark.** Also note duplicating your reminder breaks the token-matching to the control; you would have to re-match.
- **Re-reading (RE2)** (https://arxiv.org/abs/2309.06275, EMNLP 2024): 14 datasets, 112 experiments; text-davinci-003 Vanilla+RE2 **+3.81% arithmetic, +2.51% commonsense, +1.85% symbolic**; CoT+RE2 +2.22/+1.23/+5.25. Optimal 2–3 re-readings. Small, reasoning-oriented gains; no constraint-satisfaction evidence.
- **"Restate the constraints before answering" is the intervention your model already performs, and it does not transfer to the code.** "Models Recall What They Violate: Constraint Adherence in Multi-Turn LLM Ideation" (Garvin Kruthof, TUM; https://arxiv.org/html/2604.28031v1, 30 Apr 2026). **Probe accuracy 97.3%** (6 of 7 models at 100%) — models restate the constraints correctly — while the **knows-but-violates rate** is GPT-5.4 8%, GPT-5.4-mini 16%, Gemini Pro 18%, Qwen3-235B 55%, Gemini Flash 76%, **Llama-3.3-70B 93%, Sonnet 4.6 99%**. Mitigations: structured-reflection checkpointing moves Qwen 55% → 36%, Sonnet 99% → 87%, **Llama 93% → 92%**; a second model monitoring each constraint per turn leaves Sonnet at 97% and Llama at 89%. "Neither intervention closed the dissociation." Llama-3.3-70B produced the **shortest** outputs (445 tokens mean) and the highest drift, with a **+0.80 surface-fidelity gap** — it "sounds on-task while substantially failing on constraints." **That sentence is a precise description of your 1.7B oracle-arm transcript.**
- **Self-check-and-revise: needs an external verifier at small scale.** DeCRIM (decompose–critique–refine; https://arxiv.org/abs/2410.06458, Oct 2024) gives **Mistral +7.3% on RealInstruct and +8.0% on IFEval**, and open models with DeCRIM + strong feedback beat GPT-4 on both; GPT-4 itself misses ≥1 constraint on >21% of RealInstruct instructions. "Small Language Models Need Strong Verifiers to Self-Correct Reasoning" (https://arxiv.org/html/2404.17140v2): LLaMA-2-13B **+4.2%** and Gemma-7B-it **+6.2%** on GSM8K with a GPT-4 verifier (Gemma avg +8.3% over five datasets), **negligible with a self-verifier**, +8.8% / +11.1% with an oracle. And the one study run on frozen models in your exact size class — "Falsification, Not Exposure: An Internally Preregistered Placebo-Controlled Decomposition of Self-Repair Feedback in Frozen Small Code Models" (Mehmet Iscan; https://arxiv.org/html/2606.31511v1), on **qwen2.5-coder:1.5b, qwen2.5-coder:0.5b-instruct, deepseek-coder:1.3b**, 290 dead task-cells: bare-code retry **2.8%**, **blind resample 9.0%**, facts-only 5.2%, code+executed-facts **9.0%**, generic-bullet placebo 3.8%. CF-SF vs bare-code OR 6.1:1 (Holm p = 0.00042); CF-SF vs placebo OR 3.0:1 (p = 0.0041); **but code+facts exactly tied blind resampling at 26 unlocks.** Conclusion: the value is "externally executed counterevidence," and even then it does not exceed just sampling again. **For 1.7B, budget resampling, not introspection.**
- **Constrained decoding has a real tax.** "The Constraint Tax" (Jaideep Ray; https://arxiv.org/html/2605.26128v1, 20 May 2026) on Qwen2.5-0.5B/1.5B/3B and SmolLM2-1.7B: hard answer-schema decoding at the 3B boundary **loses 15.3 points of answer accuracy and adds 31.6 points of wrong-but-valid-schema output**; in a calendar tool-call task, **43.5 points of executable accuracy** lost at 100% schema validity. Policy quoted: "use the least intrusive constraint that satisfies the downstream contract, and package answers only after the model has solved the task"; a delayed constraint reached 40.7% answer accuracy at 100% validity. "When Correct Isn't Usable" (https://arxiv.org/html/2605.02363v1, 4 May 2026; Llama-3.1-8B, Gemma-2-9B, Qwen-2.5-7B): no system prompt → **0% output accuracy despite 77–85% task accuracy**; grammar decoding 15–52% output accuracy at **3.6×–8.2× latency**; black-box prompt optimization 84–87% on GSM8K. Grammar-constrained decoding is surveyed as able to restrict generated function names (https://arxiv.org/pdf/2305.13971) and is called out as especially useful for resource-constrained small models, but **I found no study measuring grammar-constrained decoding against a naming-convention or style rule** — a genuine gap, and a cheap arm, since a `gn_` prefix only needs a logit constraint at the first identifier token after `def `.
- **Attention decay is positional, and re-injection does not cure it.** "When Attention Closes: How LLMs Lose the Thread in Multi-Turn Interaction" (https://arxiv.org/html/2605.12922, 14 May 2026). Metric: **Goal Accessibility Ratio (GAR)** = attention mass from generated tokens to goal-defining system-prompt tokens. GAR declines monotonically in every architecture (Mann-Kendall p < 10⁻⁷), **27–48% of turn-1 value by turn 50**; under a 4096 sliding window it hits the numerical floor at turn 23 (Mistral), 19 (LLaMA), 20 (Qwen/Mixtral); window size vs crossover turn is linear at R² > 0.999. Models: Mistral-7B, Llama-3.1-8B, **Qwen-2.5 3B/7B/14B/32B**, Mixtral-8x7B, 10 architectures 2B–32B. Consequences at T=50: 5-fact recall 100% → 11–45%; persona violation rates Mistral 6.2% → **77.5%**, Qwen 4.0% → **63.8%**, Mixtral 8.7% → 45.0%, LLaMA 5.3% → 10.2%. **Appendix H: periodic user-role goal re-injection FAILED**, explained by RoPE's distance decay — re-injected goal tokens decay against the generation position just like the originals: "repeating or retaining text is not equivalent to preserving goal information." **This is the mechanistic reason an oracle reminder can be inert, and the reason an attention-side bias is the right next lever.**

## Q3 — MemoryCode

Interventions reported, and their outcomes:
- **RAG over session history** (Cohere `rerank-english-v3.0`, session-level): "marginal improvement over cumulative for short conversations, but it then converges with Cumulative for the long ones." **Fails where it matters.**
- **Instructions-chain** (strip all filler; hand the model only the chain of rules and updates — the idealized perfect-memory upper bound): "the trend is strikingly similar to the one observed in History, with the model still struggling even if only the relevant information is provided." **Perfect retrieval does not fix it.**
- **Sanity check**: <0.01 accuracy with no instruction present, so the benchmark is not solvable by priors.
- **Diagnosis**: "inability to reason compositionally over a sequence of instructions," not retrieval and not updating — "stability across update ranks … primarily due to the model's difficulty in jointly following multiple rules."
- **Prior-frequency bias**: instructions unlike training data (e.g. names containing a digit) score lower than conventional ones (docstrings, annotations). Same direction as the counter-intuitive-constraint finding above.
- CoT, summaries, explicit instruction listing and larger context windows were **not** tested.

## Q4 — Memory / synopsis architectures for long sessions

**Rule application is where memory systems lose outright.** MemoryAgentBench (ICLR 2026; https://arxiv.org/html/2507.05257v1, Jul 2025) has a Test-Time Learning competency — apply a rule/label scheme introduced in-dialogue. Classification avg / recommendation: **Claude-3.7-Sonnet long-context 89.4 / 18.3; GPT-4o-mini long-context 82.4 / 15.1; MemGPT (Letta) 67.6 / 14.0; Mem0 3.4 / 10.0.** "Long-context models achieve the best performance on TTL." Conflict Resolution (stale/superseded facts), single/multi-hop: GPT-4o-mini 45.0/5.0; MemGPT 28.0/3.0; Mem0 18.0/2.0 — "all methods fail on the multi-hop situation (at most 6%)." Conversely RAG dominates pure retrieval (BM25 100% vs 22.8%). **Clean split: retrieval → memory helps; rule application → memory hurts.**

**Mem0** (https://arxiv.org/abs/2504.19413 / html v1, Apr 2025; GPT-4o-mini backbone, LoCoMo, LLM judge): **Full-Context (~26k tok) 72.90 overall; Mem0 66.88; Mem0-graph 68.44; Zep 65.99; LangMem 58.10; OpenAI memory 52.90; A-Mem 48.38.** The paper concedes full context "still achieves the highest J score (approximately 73%)." Mem0's wins are efficiency: p50/p95 latency 0.708/1.440 s vs 9.870/17.117 s; ~7k tokens vs ~26k. **The headline "26% relative improvement" is over OpenAI's memory product, not over full context, which beats it.** Zep/Graphiti (https://arxiv.org/abs/2501.13956, 20 Jan 2025) reports DMR 94.8% vs MemGPT 93.4% and "up to 18.5%" on LongMemEval with 90% latency reduction. MIRIX (https://arxiv.org/abs/2507.07957, Jul 2025): LoCoMo 85.38% vs **Full-Context upper bound 87.52%** — full context wins again. MemOS (https://arxiv.org/abs/2507.03724) and MemoryOS (https://arxiv.org/html/2506.06326v1) report large *relative* gains over weak memory baselines with no full-context comparison; treat as unverified. Letta's own test (https://www.letta.com/blog/benchmarking-ai-agent-memory/, 12 Aug 2025) finds an agent that simply stores history **in files** scores 74.0% on LoCoMo with gpt-4o-mini, beating Mem0-graph's 68.5%: "memory is more about how agents manage context than the exact retrieval mechanism."

**Treat all LoCoMo rankings as noise.** Zep's audit of Mem0 (https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/) found role mis-assignment and sequential search, recomputing Zep at 75.14% ± 0.17 vs Mem0-graph ~68%; Mem0's counter-audit (https://github.com/getzep/zep-papers/issues/5, 8 May 2025) recomputed Zep's 84% claim as 58.44% ± 0.20 (excluded adversarial questions counted in the numerator only, modified prompts, single run). An independent audit reports the LoCoMo LLM judge over-accepts **62.8%** of deliberately wrong answers (https://dev.to/gde03/the-ai-memory-benchmark-everyone-quotes-forbids-saying-i-dont-know-o1n).

**At your exact scale, and why it does not generalize to your question.** MemFlow (https://arxiv.org/html/2605.03312v1, May 2026) runs a **frozen Qwen3-1.7B**: LongMemEval 61.8 / LoCoMo 51.2 / LongBench 51.1, avg **52.4%** at 2,223 answer tokens, vs same-backbone Direct-QA-full **29.0%** (8,614 tok), RAG 46.2%, ReAct 46.2%, MemGPT 30.9%, Memobase 9.6%; GPT-4o ceiling 74.3%. Cross-backbone gains +6.0 pp (Gemma-3-1B) to +23.4 pp (Qwen3-1.7B, SmolLM2-1.7B). **But: memory wins at 1.7B only because 1.7B full-context is broken at 29%, and these are recall tasks, not rule application.** A-MEM (https://arxiv.org/html/2502.12110v1, Feb 2025) is the only other mainstream memory paper with sub-4B backbones (Qwen2.5-1.5B/3B, Llama-3.2-1B/3B); absolute numbers are poor (Qwen2.5-1.5B multi-hop F1 24.32).

**Procedural memory** — Memp (https://arxiv.org/abs/2508.06433, Aug 2025, ACL 2026) lifts GPT-4o TravelPlanner constraint satisfaction 71.93% → **79.94%** and ALFWorld 42.14% → **77.86%**, and claims migrating procedural memory to a weaker model yields substantial gains — but the measured quantity is task success, not regex-verified convention adherence, and no 1–4B numbers are given. **CodeMEM** (https://arxiv.org/html/2601.02868v1, Jan 2026, Findings of ACL 2026) is the one positive memory result on coding-instruction adherence: CodeIF-Bench Instruction Accuracy **46.1%** (CodeMEM) vs 41.1% (Full-Context+BM25), 39.1% (MemGPT), 32.5% (Mem0); tokens 107.8k vs 131.8k. DeepSeek-V3.2 only, no small models, and the ceiling is still 46%. **TRACE** (https://arxiv.org/abs/2606.13174, Jun 2026) compiles user corrections into runtime checks and reports that **Mem0-style memory leaves 57.5% of applicable preferences violated** — "a correction remembered in one session may still be violated in the next" — while runtime enforcement cuts violations 100.0% → **37.6%** in-distribution and 100.0% → **2.0%** OOD.

**Rules files, measured.** ETH Zurich SRI, "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" (https://arxiv.org/abs/2602.11988, Feb 2026, rev Jun 2026): "providing context files does not generally improve task success rates, while increasing inference cost by over 20% on average"; LLM-generated files *reduced* success ~3%, developer-written gained ~4% on one benchmark at up to 19% extra cost. Crucially: **"instructions in the context files are well followed by coding agents"** — the harm is overview bloat, not disobedience. Plus the McMillan factorial null and the 5.6%-per-function decay above (https://arxiv.org/abs/2605.10039). Rule-file mining (https://arxiv.org/abs/2606.12231, Jun 2026; 7,310 rules, 83 repos, 99 practitioners, 1,540 evolution events): 77.78% of developers edit rules to correct AI errors, mainly by **adding negative constraints**; after rule updates average artifact compliance rose **22.99 pp (49.14% → 72.13%)**.

**The one result that endorses your verbatim reminder.** "Governance Decay: How Context Compaction Silently Erases Safety Constraints in Long-Horizon LLM Agents" (https://arxiv.org/html/2606.22528v2, 27 Jun 2026): violation rate **0% in control → 30% pooled after a single compaction** (DeepSeek-V4 59%, Kimi-K2.5 59%, GPT-5.4-mini 41%, **Qwen3.6-27B 30%**, Claude-Sonnet-4.6 19%, Gemini-3.5-flash 4%, GLM-5.1 0%) — "compacting a policy can be worse than never stating it." Violation tracks the **summarizer**, not the agent (a GLM summary holds 7–13% regardless of agent; a DeepSeek or Claude summary yields 33–93%). **Constraint Pinning — constraints exempted from compaction and re-injected VERBATIM after every compaction step, plus an entailment integrity check — restores violations to 0% across all seven models, at ≈47 pinned tokens (<0.5% of a ≥10k history), preserving 99% of legitimate actions.** Residual failure: an operator-impersonation rescind in recent context still yields 17% violations (10% with provenance markers).

## Q5 — Coding-agent convention adherence, 2025–2026

- **RepoComplianceBench** — "A First Look at Coding Agents' Compliance with AI Contribution Rules in Open-Source Communities", Wenhao Yang, Runzhi He, Minghui Zhou (Peking University), https://arxiv.org/abs/2607.26819v1 (29 Jul 2026). 106 issues / 49 repos; four rule types (Refuse, Disclose, Verify, Handoff); four agents (DeepSeek-V4-Pro/OpenCode, GPT-5.3-Codex, GPT-5.5/Codex, Claude Sonnet 4.6/Claude Code). Baseline: **Refuse 0% for all four agents; Disclose 17–40%; Verify 4–92%; Handoff 0% for all.** Interventions: a **generic reminder** gives Disclose 14–31%, Verify unchanged, Refuse 0%; a **verbatim rule quote placed in AGENTS.md** gives Disclose **Sonnet 77% (23/30), GPT-5.5 76%**, Verify flat, Refuse ~0–10%; **one round of oracle verifier feedback naming the violated clause** gives Disclose 55–97% and **Verify 90–100%**, but Refuse ≤23% and Handoff ≤33%. Also: **agents proactively open the relevant policy file in only 3.5% of episodes.** Read-across: verbatim quoting and one verifier turn are the two interventions with large measured effects on mechanically-checkable rules — exactly the class `gn_` belongs to.
- **ZORO** — Jenny Ma, Sitong Wang, Joshua Kung, Lydia Chilton (Columbia), https://arxiv.org/abs/2604.15625 (Apr 2026, rev May 2026). Enrich plans with rules → require the agent to **prove** compliance → evolve the ruleset. Cline + Claude Sonnet 4.6, 36 sessions, 9 tasks, two repos (22k & 11k LOC). **Baseline 51% ± 0.08 → enrich-only 68% ± 0.07 → enrich+enforce 80% ± 0.08.** By rule type: **process rules 35% → 87%; coding/style rules 59% → 75%.** The 80% ceiling is attributed to **rule ambiguity** — agents follow literal wording while diverging from intent. Design note for you: define "function" precisely in the convention text (nested? methods? lambdas? decorators?).
- **Static analysis as a feedback loop** — https://arxiv.org/html/2508.14419v1 (Aug 2025). Pylint/Bandit reports fed back, ≤10 iterations, **GPT-4o only**: **convention violations 84.21% → 12.28%** (best strategy: fix all issues at once), 54–74 pp reduction across strategies; diminishing returns by iteration 3–4. Partial failures: functional correctness improved only 5–7% (max 10.94%), the loop **introduced 994 new convention issues** and new security issues in 5% of iterations. Pylint's Convention class literally includes naming checks, so this is the closest mechanical analogue to a `gn_` post-pass — and the strongest effect size in the sweep, with the caveat that it is a single frontier model.
- **CodeIF-Bench** — https://arxiv.org/abs/2503.22688 (Mar 2025). 9 verifiable instruction types, test-case validated, static vs dynamic conversation, 6 frontier LLMs. Instruction following **degrades with added repository context and with accumulating interaction history**; the authors name **context management** as the primary improvement direction.
- **Constraint decay** — Francesco Dente, Dario Satriani, Paolo Papotti, https://arxiv.org/html/2605.06445v1 (May 2026). API contract held constant while layering architecture/database/ORM constraints L0→L3, 291 assertions over 19 endpoints. **Capable models lose ~30 pp of assertion pass rate from L0 to L3.** Marginal effect per constraint: PostgreSQL −19.3 ± 2.5 pp, SQLite −14.3 ± 2.5, Clean Architecture −9.1 ± 1.6, ORM −0.6 to −1.5. Convention-heavy frameworks fare worst (FastAPI 24.2%, Django 25.4%, Hono 18.5% vs Express/Koa/Flask ~50%). Post-hoc verifiers changed results ≤2.7 pp; no constraint-reinforcement intervention was tested.
- **ControlledCoder** (IFEvalCode, https://arxiv.org/abs/2507.22462) — the only published convention-targeted training delta: Qwen2.5-Coder-32B with forward + backward constraint generation, Corr./Instr. **29.9/20.7 → 34.5/26.4 → 38.2/30.4 → 40.3/34.2** (+13.5 pp instruction-following). Even after targeted training, 34.2% — controllability is hard at any size.
- **Gap:** I found no benchmark that measures grammar-constrained decoding against a naming convention, and no MemoryCode run with any memory system.

## What would most likely NOT work, and why

1. **More/better prompt formatting of the reminder.** Measured nulls, twice, at large N: rules-file size, instruction position, architecture and conflicting files show no detectable contrast across **1,650 agent sessions** with affirmative-null BF10 0.05–0.10 (2605.10039); three constraint encodings × four propagation modes show **Cliff's δ < 0.01, ±2.6 pp** across 11 models and 830 invocations (2604.07192). The same paper's conclusion is explicit: effort belongs in "constraint design," not "prompt formatting." A reminder-formatting arm will burn GPU hours to measure zero.
2. **Asking the model to restate the convention before coding.** It already does — and that is the diagnosis, not the cure. Probe accuracy 97.3% with knows-but-violates up to 99% (2604.28031); structured-reflection checkpointing moved Llama-3.3-70B 93% → 92%; a second model checking every constraint per turn left Sonnet at 97%. Self-assessed compliance "systematically overestimates" rule-based scoring (2604.07192). Your transcript — correct prose paraphrase, non-compliant code — is the canonical signature of this dissociation, and the literature has no prompt-level fix for it.
3. **Memory, synopsis, RAG-over-history, or a summarized "rules in force" block.** MemoryCode's own instruction-chain ablation shows perfect, lossless retrieval reproduces the collapse; its RAG arm converges with cumulative on long histories (2502.13791). Mem0 scores **3.4 vs 82.4** for plain long context on applying a newly-stated rule (2507.05257). TRACE measures memory leaving **57.5%** of preferences violated (2606.13174). And summarizing the rule is actively harmful: compaction takes violations 0% → 30% pooled, tracking the summarizer not the agent (2606.22528). Every memory paper that beat full context beat either a broken baseline (Qwen3-1.7B full-context at 29%, 2605.03312) or a weak product baseline (OpenAI memory at 52.90, 2504.19413).
4. **Intrinsic self-critique / self-check-and-revise at 1.7B.** Small models need a strong external verifier: self-verifiers give negligible gains, GPT-4 verifiers +6.2 pp, oracle +11.1 pp (2404.17140). In frozen 0.5–1.5B code models, informed feedback **tied blind resampling** (9.0% vs 9.0%) and the placebo arm reached 3.8% (2606.31511) — so any gain you see from a "check your work" turn must be benchmarked against plain resampling at equal sample budget, or it is unattributable.
5. **Expecting attention steering alone to rescue 1.7B.** This is the load-bearing risk for the planned intervention. DIRECTER at 1B: **+0.3 pp** on IFEval, with the authors noting prior steering baselines are similarly inconsistent at that scale (2603.06745). No attention-steering paper reports a model below 2B; GUIDE's 2B is the floor of the evidence. Steering cannot create a capability — and IFEvalCode puts Qwen3-1.7B at **13.3%** code-instruction-following in short, single-turn, uncontaminated conditions. Plan for 4B to be the smallest responsive model and treat 1.7B as a likely null.
6. **Pushing the steering strength up until compliance appears.** Every method in the family has a documented cliff: GUIDE Δ > 5 yields "nonsensical outputs" and token repetition (Δ=9 degenerates outright); SpotLight at ψ_target 0.4 ignores the query; PASTA on GPT-J-6B hits 91.50% JSON format with **18.63%** prediction accuracy; PASTA* trades GSM8K task accuracy 82.7% → 62.7% to win formatting; latent steering collapses fluency at α=0.6. InstABoost's Theorem 3.3 formalizes it: excessive boosting suppresses the task-relevant context you still need to write working code. A "format compliant, semantically broken" win is the default failure mode, so instrument task correctness in the same run.
7. **Repeating or re-injecting the instruction as a cure for attention decay.** "When Attention Closes" tested periodic goal re-injection and reports it as a **negative result**: GAR declines 27–48% by turn 50 because RoPE attention decays with relative distance, so re-injected tokens decay identically — "repeating or retaining text is not equivalent to preserving goal information" (2605.12922). Note the boundary with Constraint Pinning's success (2606.22528): verbatim re-injection works when the rule would otherwise be **deleted**; it does not work when the rule is **present but unattended**. Your oracle arm is the second case, which is exactly why the oracle reminder bought you nothing — and exactly why an attention-side bias is the right lever rather than a prompt-side one.
8. **Whole-output constrained decoding or schema enforcement.** At the 3B boundary, hard schema decoding costs **15.3 points of answer accuracy** and adds **31.6 points of wrong-but-valid** output; a tool-call task lost **43.5 points of executable accuracy** at 100% validity (2605.26128); grammar decoding costs 3.6×–8.2× latency for 15–52% output accuracy (2605.02363). If you constrain, constrain narrowly — a single-token logit mask at the identifier after `def `, not a grammar over the program.
9. **Leaning on the strict all-or-nothing metric as the primary reading.** Below ~8B, strict CSR is a measurement dead zone: CodeIF 0.034–0.097 at 1–3B against SSR 0.218–0.445; CIFE 0.177 strict vs 0.691 soft at 2B. A strict 0/16 reading cannot distinguish "slightly better" from "no effect," so a real steering gain would be invisible. Report fraction-of-functions-prefixed as primary and strict as secondary.
10. **Hoping scale inside the small band closes it.** MemoryCode's long-history column is nearly flat from 8B to 405B (12.5 → 20.9) even as the instruction-only column runs 71.7 → 95.2 — once the rule is buried, parameters buy little. 1.7B → 4B buys roughly +4.7 pp of code-instruction-following (13.3 → 18.0); it will not get you from 0 to a publishable margin by itself.

### The one thing the evidence says to measure first

Run **pass@k on the oracle arm** (k = 8, 32) with your regex as the only judge, at both 1.7B and 4B, before building anything. Inverse IFEval's Best-of-N result (≈47–55% → ≈90% at N=32 on counter-conventional instructions, 2509.04292) means a strict-0 at N=1 is consistent with the capability being present and the sampling policy failing. If pass@32 > 0, the whole problem is policy and the winning stack is cheap: reminder + narrow decode constraint or verifier-gated resampling, with attention boosting as the elegant single-pass version of the same push. If pass@32 = 0 at 1.7B, that is a capability floor, no inference-time intervention in this literature will clear it, and 4B becomes the minimum viable artifact.
