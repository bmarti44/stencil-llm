# Automatic maintenance — draft consumer contract

This isolates a research updater. It does not change `loop.authenticate`, set `Message.adopted=true` for inferred text, or alter production admission. The research policy is to attempt automatic interpretation of authenticated direct user messages, then measure the errors. Source-role validation proves transport authority, not semantic adoption of a quoted instruction. Tool/assistant messages can be provided as context but cannot authorize a new obligation. Higher-authority obligations are real system/developer entries, never overridable `Register.defaults`.

For each new conversation message, the updater receives its authenticated envelope, declared task handles/request kind, bounded prior natural conversation, and its own full versioned state, including retired versions needed for reinstatement. Gold expected operations and expected views are never in this input. A proposed state change addresses an opaque existing key/version or requests a new key. Host-assigned IDs and source identities do not come from model-supplied role fields. Binding a new paraphrase to an old key is a model decision, not lexical matching.

The proposed response is a single bounded JSON object containing a base-state hash and an ordered list of operations. Freeze the exact schema/prompt before any held-out model call. Each operation includes action, existing key or new-key marker, scope, kind, literal value or target reference, and current-source evidence. For retirement and reinstatement, copy immutable target fields deterministically. Task-local override adds a narrower entry; it does not retire a global entry. Conflicting operations and stale hashes reject the whole transaction. No partial application, silent retry, auto-correction from labels, or gold-state reset.

The base-state hash covers canonical register events and pending proposals plus declared scope, not `generation` alone: generation is a request clock. Validate against the exact state shown to the updater and append every accepted operation atomically. For this screen, completion from assistant self-report is forbidden; explicit user closure can be evaluated separately using a current authenticated user-event reference. Lack of admissible evidence leaves the original obligation active and counts as a miss when appropriate.

Following every turn, compare semantic effective views over every declared task/request scope plus global scope. Do not require a model to reproduce the gold author's arbitrary IDs to receive semantic credit. Separately audit the stored version/retirement history through future cancellations and reinstatements so temporary output equality cannot hide deleted obligations. Retired records remain stored; only their live mask changes. Missing views, all-no-op policies and overbroad masking must fail controls.

On malformed/invalid proposals, preserve the previous state and log the complete raw response and rejection reason. The next turn receives that actual state. A no-op at a necessary update is an error even if the system made no unauthorized change. Human correction or clarification, if later permitted, is an intervention with its own outcome category, not autonomous success. This initial protocol has no per-turn human corrections.

For later end-to-end comparison, use the same worker model and task stream with (A) automatically maintained reminders, (M) independently supplied ideal manual prose, and (N) ordinary retained history. A may render its typed state as prose. Do not bundle a representation-format intervention into the automation contrast. Count A's updater call cost as well as worker calls. M has gold maintenance supplied for quality comparison; it supplies no measured human-time estimate. A subsequent automated-prose updater control is needed before attributing benefit uniquely to a versioned register.

Pending before implementation freeze: reviewed sample and reading; complete source-span semantics for paraphrastic updates; history truncation policy; schema caps; predictable opaque key allocation; durable per-call receipts; updater/worker timing; and independently checked coding oracles. The two current DEV seeds validate authoring and consumer structure only. They cannot establish model accuracy, equivalence to prose, or competent automated focus.
