2. GENERALITY — whether learning earns its cost

**HIGH G1 — The current program can declare mechanism success while failing its learned-selector objective.** Leg A's primary decision depends on A1/A3, not A2 (`LEDGER-PLAN.md:715-721`; `src/stencil/bfcl.py:1592-1625,1835-1850`). A classifier may beat a deliberately nonselected complement and recover headroom while offering no advantage over recency. Furthermore Leg A's recency comparator inherits the classifier's per-role quotas and echo quantity (`scripts/bfcl_mt.py:1080-1107`). That is useful for isolating within-role ranking, but it does not compare two independently deployable selectors. Leg B's role rule likewise borrows its budget (`scripts/multiif_evict.py:271-287`). The outcome addendum correctly acknowledges this (`LEDGER-PLAN.md:814-815`).

Keep the frozen classifier as an experimental candidate for mixed user/tool histories; stop treating it as the presumptive destination. C2 rejects the engineering presumption that learning is necessary for this instruction style. It does not establish that no classifier could help elsewhere. The original G0 ordering—try simple policies, learn only when they leave useful headroom—was sound (`LEDGER-PLAN.md:450-473,516-528`). Its self-continuation NLL oracle did not measure standing-rule utility adequately, so abandoning that oracle need not mean abandoning the simple-policy-first decision.

**HIGH G2 — A three-scope label taxonomy is not a scope-resolution mechanism.** Labels explicitly depend on whether an artifact/sub-unit is still active and include changes and cancellations (`data/classifier/LABELS.md:17-40`). Deployment scores a sentence and role without the current task or conversational context (`LEDGER-PLAN.md:572-574,654-660`; `src/stencil/selector_v2.py:105-145`). The same stored sentence therefore gets the same score after a task switch, completion, or reversal. Rebuilding the candidate set each turn does not fix this. The system has an admission heuristic for potentially useful information, not a demonstrated policy for selecting what is applicable now. No current result establishes cancellation, stale-rule suppression, cross-task scoping, or fact correction. This gap matters more to “focus” than another small improvement on formatting labels.

The single experiment I would run next is a **frozen-policy comparison on independently authored, executable delayed-use episodes**, with no new fitting:

- Before any outcomes, freeze the existing classifier and one deployable parameter-free rule. A concrete baseline is prior-user spans newest-first, then prior-tool spans newest-first, under an input-derived cap `B=floor(0.25*evictable_columns)`. The rule has its own fill procedure; it never reads classifier scores, selected counts, or role quotas. Both policies get the same maximum pin and echo budgets, renderer, protected prefix, and eviction order. Report actual usage and selector/echo latency; identical resource ceilings are the practical estimand, not an artificial exact match to the learned policy's chosen dose.
- Commission fresh fictional editing and tool-work episodes from authors given a benchmark-free task specification, with procedurally sampled names, IDs and values and executable final checks. Cross age with role and relevance so both old and recent information are sometimes needed. Include continuing tasks, completed tasks, explicit overrides, and irrelevant durable-looking facts. Do not construct a challenge consisting only of the recency failures one hopes the classifier will solve. Keep reference answers inaccessible to both policies.
- Use a small separate setup slice to verify base competence and timing, then one frozen test set—e.g. 256 independent episodes, balanced across the two source styles—with one scored final decision per episode. Use common unmodified histories to isolate selection. Primary is paired binary task success, classifier versus rule, with an exact one-sided McNemar test and a paired effect interval. Require positive evidence and a prespecified worthwhile magnitude (for example 5 percentage points), plus fixed safety/cost limits; report each source style separately. No pass based on classification accuracy or oracle NLL. If the fixed budget is too small for power, report inconclusive rather than manufacture equivalence.
- Keep learning only if that comparison demonstrates a useful gain. Otherwise choose the simple policy for the next system prototype by the simplicity rule, while saying “no useful learned advantage demonstrated,” not “equivalent.” A positive result warrants one subsequent untouched external-family evaluation; it does not prove universal generalization.

Yes, this experiment can be authored and run without accessing any evaluation benchmark. Its new items, references, setup slice and test slice can all be independent of Multi-IF/BFCL/IFEval. It cannot erase the existing classifier/spec's historical benchmark influence. Call it an independent test of a development-informed policy. The authors must not receive this review's benchmark error examples or the outcome-review diagnostics. This is a bounded experiment proposal, not a request to run it during the current GPU job.

4. RIGOR versus OVER-ENGINEERING — what Leg A can decide

**HIGH R1 — The registered sign-flip test is not distribution-free for the stated mean-effect null.** `LEDGER-PLAN.md:631-632` calls it distribution-free; `:681-685` applies it to means of binary turn differences. `src/stencil/bfcl.py:847-865` correctly enumerates all signs. Exact enumeration is not an exact sampling justification. For general case means, validity needs a sign-symmetric null distribution or a justified within-case treatment-label exchangeability/randomization argument. Neither is established by running deterministic policies on a sampled cohort; A3 is a three-arm composite, not an ordinary randomized paired binary comparison.

Here is a CPU-cheap counterexample within the allowed support of case-mean binary differences. Let an independent case have difference `+1/5` with probability `5/6`, and `−1` with probability `1/6`. Its population mean is exactly zero. With six cases, all six are positive with probability `(5/6)^6 = 0.334898`. Every such sample receives sign-flip p=`1/64 = 0.015625`, passing even the first three-test Holm threshold. A nominal 5% test of zero mean can therefore reject on at least 33.49% of this mean-null distribution. This is not a numerical issue or a criticism of the enumeration code. It refutes the unqualified mean-inference claim.

Before any sealed inferential claim, either state and defend the stronger null assumptions, or prospectively choose an estimand/test that does not require them. The cheapest robust simplification is one binary endpoint per independent case and an exact paired McNemar test of equal marginal success probabilities; the repo already has that primitive (`src/stencil/stats.py:122-129`). A sign test on case-mean signs instead tests frequency of improvement, not the mean number of passed turns, and must be named accordingly. Do not merely remove the word “distribution-free” while continuing to market an assumption-free mean-benefit conclusion.

**MEDIUM R2 — The cohort has much less effective information than “64 cases” suggests.** Recomputing the registration's binomial planning arithmetic gives `P(k<6)=0.105057` and `P(k<8)=0.401810` for 16 potentially exposed cases at exposure probability 0.5. Those numbers are correct *conditional on that planning assumption*, not measured void probabilities for the sealed cohort. At k=6, one zero raises the best sign-flip p to `2/64=0.03125`; at k=7, one sufficiently small negative can still give `2/128=0.015625`. The corrected grid explanation in the registration is accurate. It does not supply power.
