**Dense focus: what is worth testing on Qwen3.8-27B**

gpt-6-astra · 2026-09-06 · CPU/web research; no installs, model launches, GPU work, or reads under `data/bench`.

**Recommendation: keep the extracted-vector/neuron search closed; allow one tightly bounded experiment with learned, switchable control. Start with two small LoRAs on the local Qwen3-4B.** A successful proxy would justify testing the same design on 27B, not transferring its weights. Do not start a general weight-side research program merely because the trunk is larger and dense. There is new, relevant evidence for Qwen3.5-27B SAE steering, but no opened source establishes executable coding competence plus text-free HOLD plus behavioral SWITCH/CLEAR on Qwen3.8-27B. Rendering remains the shipping choice. Masking remains a contingency, and its existing certificate does not automatically transfer to the hybrid dense trunk.

This is a research recommendation and prospective screening design, not an experiment registration or launch authorization. I read the archived science/process documents, current ledger, [composition v2](focus-mechanism-composition-v2-astra.md), [quick-check index](quick-checks/README.md), and the Fable reviews of [30](check30-review-fable.md), [31](check31-review-fable.md), [32](check32-review-fable.md), [34](check34-review-fable.md), [35](check35-review-fable.md), [36](check36-review-fable.md), and [38](check38-review-fable.md). Their results are premises here, not experiments to repeat. In particular, discriminability is not causal controllability, correct syntax is not executable competence, and restoring edited tensors is not behavioral release. The lock owner and parent were inspected: the concurrent pilot4 continuation is not a review/coder wrapper; its artifacts are untouched.

**Data lineage for every proposal, before any fitting or brief:** fit/profile-on = newly authored procedural development families with independently checked reference implementations; select-on = separate authored setup families; evaluate-on = newly frozen task families, seeds, wording, and lifecycle episodes disjoint from both. No public benchmark prompts, benchmark responses, previous decision-bank failures, or their paraphrased relatives enter training, feature discovery, dose selection, or harness tuning. Published benchmarks below are evidence about the papers, not proposed training sources. No such training data or experiment artifacts were created in this research task.

**The question has three different meanings.**

| Claim | What would actually establish it? |
|---|---|
| Select an existing capability | The unmodified trunk already passes both explicitly cued tasks; an external mode chooses between them on new executable tasks. Fine-tuned adapters might also teach something, so this operational result does not identify a pre-existing circuit. |
| HOLD without rule text | Keep only the selected adapter/vector/prefix and normal session state; give subsequent requests no natural-language rule. Report whether the actuator remains applied on every token, a learned prefix remains in context, or a one-time intervention truly persists after removal. These are different results. |
| Reversible | Distinguish unchanged trunk parameters, identical OFF computation on identical inputs, and successful behavioral CLEAR after the model has produced contrary history. All three matter. Removing an intervention cannot undo already emitted code or facts. |

A controller retaining a mode and applying it every generation is consistent with a separate persistent control signal. It is not evidence that the transformer autonomously latches a transient pulse. A learned prefix is a compact conditioning message stored as weights; LoRA selects a parameter delta; an SAE direction edits activations. Calling all three “weight-side” must not erase these distinctions.

**The actual trunk changes the engineering calculation.**

The official [Qwen3.8-27B model card](https://huggingface.co/Qwen/Qwen3.8-27B) confirms a dense 27B language component, hidden size 5,120, 64 layers, and 16 repetitions of three Gated DeltaNet blocks followed by one gated-attention block. Thus there are 48 recurrent linear-attention blocks and 16 full-attention blocks. The card exposes thinking controls; a short screening run must freeze them consistently across arms. This is not the old Qwen3-4B architecture enlarged.

The [Transformers Qwen3.5 implementation](https://github.com/huggingface/transformers/blob/main/src/transformers/models/qwen3_5/modeling_qwen3_5.py) is the relevant implementation family. **Engineering inference:** switching a prefix or adapter can invalidate both ordinary KV and recurrent/convolutional state. Masking stale assistant keys in the 16 full-attention blocks cannot erase their contributions already integrated into the other 48 blocks. Start with complete state rebuilds at switches; charge their cost. Do not infer semantic release from a successful 2D attention-mask call, or cache compatibility from matching tensor shapes.

FP8/GGUF availability is supplied by Brian; I did not qualify those runtimes or locate/download the external checkpoints. The local 4B config is `qwen3`, 36 layers, width 2,560. bf16 27B parameter storage alone is approximately 54 GB decimal, before activations, caches, workspaces, or the vision component. Small trainable adapters avoid full-model optimizer state; they do not eliminate backward computation through a dense trunk. FP8 inference availability does not establish a working FP8 adapter-training path. Use the existing qualified 4B path for the cheap screen; a 27B attempt needs its own measured preflight.

**1. Task vectors, function vectors, ICV, and activation addition.**

The strongest large-model positives deserve an accurate reading:

| Opened primary source | Actual evidence and effect | What it does not establish |
|---|---|---|
| [Hendel et al., In-Context Learning Creates Task Vectors, EMNLP 2023](https://aclanthology.org/2023.findings-emnlp.624.pdf), necessary historical anchor | Includes dense LLaMA-30B; 18 tasks limited to single-token outputs. Their patched intermediate state retains roughly 80–90% of ordinary ICL accuracy across models. For 30B, country→capital is baseline .27, task vector .72, ICL .88; last-list-element .02/.64/.96. | Task induction is real, but neither multi-line coding nor persistent dialogue control was evaluated. The vector is a replaced hidden state, not a parameter update. |
| [Todd et al., Function Vectors, ICLR 2024, Table 2](https://arxiv.org/html/2310.15213v2) | Causally selected attention-head contributions produce an FV. GPT-NeoX-20B: zero-shot 6.7→57.1%; Llama-2-70B: 8.2→83.8%, averaged across six simple mapping tasks. The main portability analysis filters to examples the model solves with 10-shot ICL. | These are conditional recovery numbers, not general coding pass rates. No SET/HOLD/SWITCH/CLEAR trajectory. Original FVs are not identical to mean residual differences used under that name elsewhere. |
| [Liu et al., In-context Vectors, ICML 2024](https://arxiv.org/html/2311.06668v3) | Latent demonstration directions, injected with rescaling, tested on 7B/13B LLaMA and 7B Falcon/Vicuna. Falcon ParaDetox toxicity: ICL 73.09%, ICV 34.77% at λ=.1; ROUGE-1 falls 73.58→65.76. | No 20–30B coding test. Removing demonstrations does not mean every experiment removes its task instruction; Appendix A retains the paraphrase instruction for style transfer. Similarity tradeoffs are visible. |
| [Stolfo et al., ICLR 2025](https://arxiv.org/html/2410.12877v2) and [official code](https://github.com/microsoft/llm-steer-instruct) | Instruction-specific activation differences improve format, length and word constraints on Phi-3 Mini, Gemma-2-2B/9B and Mistral-7B. Some constraints work without explicit text. Layer choice varies by instruction/model. The paper documents nonsense/repetition and quality losses; e.g. length steering uses c=20, not a transferable universal dose. | No 27B executable coding or lifecycle certificate. Its IFEval-based extraction recipe is prohibited for our fitting. Read the paper as evidence, not as a permissible data recipe. |

The broad replication is unusually useful. [Steering off Course, ACL 2025, §4.2](https://aclanthology.org/2025.acl-long.974.pdf) finds default FVs recover five-shot performance in only 20% of model/task combinations, versus 52% after a substantial parameter search; task vectors reach 35%. Even optimized FVs recover at least half of five-shot performance in only 76%. **Counterevidence to blanket closure:** the authors say all seven larger models, ≥13B, worked reasonably with task vectors. That raises the prior for *simple task induction* on a larger dense model. It does not establish complex coding, a universal dose window, or reversible persistence.

[Extending Activation Steering to Broad Skills and Multiple Behaviours (2024)](https://arxiv.org/html/2403.05767v1) explicitly investigates extension beyond narrow behaviors; it provides no dense-27B executable lifecycle certificate. [ReFT, NeurIPS 2024](https://arxiv.org/abs/2404.03592) learns low-rank representation interventions on a frozen model, reporting strong task adaptation with substantially fewer trainable parameters than LoRA. This is a legitimate untested distinction from unoptimized mean vectors, but needs supervised fitting and position-specific integration. It is another adaptation method, not evidence that one generic focus vector exists.

**Expected bars/cost:** induction on familiar label/mapping tasks is plausible; task-preserving program selection is low-confidence after the local negatives. Sustained injection supplies external HOLD, but disabling it leaves downstream state/history. A narrow 4B forward-only probe can fit tens of minutes; a full head/site/dose replication or competent 27B lifecycle search is not demonstrated within an hour. Shipping a direction costs little; discovery and damage control dominate. Do not rerun the old sort screen or relabel it “27B function vectors” without a distinct causal hypothesis.

**2. SAE / representation-engineering control: new assets, narrower evidence.**

**Qwen SAEs do exist.** The opened [Qwen-Scope 27B card](https://huggingface.co/Qwen/SAE-Res-Qwen3.5-27B-W80K-L0_100) lists Qwen3.5-27B as its backbone, all 64 residual layers, width 81,920, top-k=100, and separate encoder/decoder matrices. This is the instruct-backed exception in the suite. [Qwen-Scope's report, May 2026](https://arxiv.org/html/2605.11887v1) describes 14 groups across seven backbones, including an L0=50 alternative. Its inference case studies suppress unwanted Chinese and induce classical-Chinese style. These are natural-language behaviors, not Python↔JavaScript or code correctness. Its supervised post-training improvements must not be counted as frozen-trunk feature-clamping results.

I found **no verified Qwen3.8-27B-specific SAE release** in the official suite or targeted HF/web searches as of this report. This is a bounded search result, not proof none exists. Qwen3.5→3.8 transfer is a hypothesis despite shared architecture. Nor does the suite supply an exact local Qwen3-4B SAE. Base-to-instruct transfer examples cannot certify transfer across later model training. No source identified a validated universal feature for “follow whichever rule the controller currently means.” A language feature cannot encode an arbitrary new rule value or decide its authority/scope.

[Gemma Scope, 2024](https://arxiv.org/abs/2408.05147) and the [official Gemma-2-27B residual SAE release](https://huggingface.co/google/gemma-scope-27b-pt-res) establish that 27B-scale dictionaries are practical artifacts. They do not make Gemma directions portable to Qwen, or feature labels into competence-preserving actuators.

**The strongest directly relevant scale result:** [CircuitSteer, August 2026, Appendix F](https://arxiv.org/html/2608.05732v1) evaluates aligned multi-layer SAE circuits on **Qwen3.5-27B**. On RealToxicityPrompts, coefficients −1/−2/−3/−4 give behavioral reductions .212/.344/.419/.451 with normalized perplexity 1.01/.97/.95/.90. It transfers its discovery hyperparameters from smaller models. This is encouraging dose-window evidence on the right architectural generation. However, it measures toxicity and fluency, not executable programs, rule retention, or CLEAR; the August source is a preprint. Full circuit discovery is much more work than using one already identified feature.

The coding-specific warning is particularly direct. [Mechanistic Interpretability of Code Correctness via SAEs, §5.2, opened v1](https://arxiv.org/html/2510.02917v1) reports **4.04% repair of initially incorrect code but 14.66% corruption of initially correct code** at its selected correct-steering dose α=29. These percentages have different denominators; subtracting them is not an overall accuracy change. The study also finds formatting/anomaly features and polysemantic behavior. It is a smaller Gemma study, not evidence against every 27B feature, but squarely rejects “correctness-correlated feature ⇒ safe correctness knob.”

**Implementation/cost inference:** use a residual edit `h' = h + αd` while preserving the original residual and SAE reconstruction error; replacing the whole residual with the SAE reconstruction adds another intervention. True feature clamping needs the current encoder activation; a fixed decoder-direction addition does not and must be named accordingly. One 5,120-element bf16 direction is 10 KiB. A full 81,920×5,120 encoder+decoder is 838,860,800 matrix elements: 1.56 GiB at bf16 or 3.125 GiB at fp32, per layer, plus biases. All 64 would be about 100/200 GiB respectively. Downloading/loading the entire suite is not a “small file” check. Select one layer, profile new development inputs, and export only qualified directions. The card's license is marked `qwen`; preserve/check the actual redistribution terms before bundling derived assets.

**Expected bars:** medium plausibility for a simple natural-language/style effect on the matching 3.5 model, lower for 3.8 programming-language selection, very low evidence for generic instruction control. Addition can be switched off mechanically; no behavioral release is guaranteed. Ship fit is excellent *after* feature selection. A single-layer inference screen may fit the cap; fitting a new SAE or running all-layer circuit discovery on GB10 is outside this quick-check recommendation.

**3. LoRA as the selected control state.**

Let the frozen trunk use `W + B_m A_m` when mode `m` is selected, and exactly `W` at OFF. Store two adapters; never merge them into the trunk. Train on requests without a language/rule cue, with target outputs exhibiting the selected mode. The external mode then supplies information absent from the text. Keeping that adapter selected supplies HOLD. This is the clearest operational implementation of separate stored behavior and current selection, although the adapter can contain newly learned behavior as well as select existing behavior.

[Activated LoRA, NeurIPS 2025](https://arxiv.org/html/2504.12397v3) activates adaptation only from an invocation boundary onward, permitting reuse of the preceding base-model cache. Experiments cover classification/generation tasks and RAG intrinsics, with accuracy competitive with ordinary LoRA; initial timing experiments use seven models ≤14B and short evaluator outputs. For example, Llama-3.1-8B WIQA is 74.92% LoRA versus 78.00% aLoRA. These are specialized-operation results, not code-language HOLD without a cue. Invocation tokens are still an explicit control signal.

The later [multi-adapter serving paper](https://arxiv.org/html/2512.17910v1) reports up to 58× end-to-end and >100× TTFT improvements over conventional LoRA in its cache-heavy pipelines. Those are relative serving speedups, not better task scores and not transferable GB10 forecasts. [IBM's original repository](https://github.com/IBM/activated-lora) now directs users to PEFT. [Granite Switch](https://github.com/generative-computing/granite-switch) demonstrates packaging a model with multiple adapters and an invocation mechanism. Its Granite-specific integration does not establish Qwen3.8 hybrid-cache support.

The current [PEFT LoRA documentation](https://huggingface.co/docs/peft/main/package_reference/lora) supports selecting loaded adapters and aLoRA. Crucially, its examples state that cache produced after aLoRA activation is adapter-specific; the base model must use a saved uncontaminated cache or recompute. aLoRA is not permission to feed adapter-A suffix state directly into adapter B or OFF. [PEFT hotswapping](https://huggingface.co/docs/peft/main/en/package_reference/hotswap) addresses replacing adapter weights without repeated compilation under supported configurations. [vLLM LoRA support](https://docs.vllm.ai/en/latest/features/lora/) supplies per-request `LoRARequest` selection and runtime loading. Neither interface proves persistent rule adherence or the correctness of reusing a changed-adapter cache.

[LoraRetriever, Findings ACL 2024](https://aclanthology.org/2024.findings-acl.263/) retrieves and composes adapters based on input prompts. [Mixture of LoRA Experts, ICLR 2024](https://arxiv.org/abs/2404.13628) learns how to combine LoRA branches. They support the skill-library idea, but input-based routing cannot identify a hidden current rule from an otherwise identical request. For Stencil, use the authoritative register to select an adapter; another learned router adds an avoidable failure channel. Combining several adapters also creates interference not tested by one-at-a-time switching.

**Expected bars:** fixed-family, no-rule-text induction is plausible; arbitrary new rules are not covered unless some text/parameter channel supplies their values. HOLD is deterministic *selection state*, behavioral adherence remains empirical. Start with ordinary LoRA and explicit full-state rebuilds on mode changes. aLoRA is a later efficiency optimization only after the semantics pass. Same-history replay removes stale numeric state but preserves the model's own linguistic/code demonstrations; CLEAR still has to beat those without deleting them.

**Size/cost inference:** rank-8 q/v adapters on the local 4B have `36×8×[(2560+4096)+(2560+1024)] = 2,949,120` parameters, about 5.625 MiB bf16 per adapter. This uses the local config, not a generic square-projection assumption. An illustrative 27B rank-8 adapter only on the 16 full-attention output projections has `16×8×(6144+5120) = 1,441,792` parameters, 2.75 MiB; this smaller target choice is not an efficacy claim. A 4B miniature fit plus test is plausible within an hour after throughput qualification. No evidence here certifies a 27B fit in that cap. The extra file size and arithmetic overhead are small; dense backward passes and repeated prefill dominate.

**Would it outperform rendering?** No opened source establishes that for our rule lifecycle. At best it may match behavior while eliminating repeated rule tokens, or improve a recurring mode the trunk follows inconsistently. An adapter's tiny size is not a reason to accept any new executable failures. For simultaneous, arbitrary, scoped rules, rendering has a large compositional advantage and requires no per-rule training.

**4. Attention, pinned instruction state, and learned prefixes.**

| Mechanism / opened source | Evidence | Fit to this task |
|---|---|---|
| [StreamingLLM, ICLR 2024](https://arxiv.org/abs/2309.17453) and [author project](https://hanlab.mit.edu/projects/streamingllm) | Retaining initial sink tokens supports stable streaming over millions of tokens; up to 22.2× speedup versus window recomputation. Sinks may be semantically unimportant. | Stability is not memory of an evicted rule. Pinning actual instruction tokens is conditioning/caching; it neither discovers a skill selector nor validates hybrid-state erasure. |
| [Gist tokens, NeurIPS 2023 / 2024 revision](https://arxiv.org/abs/2304.08467) | Trains a bottleneck for instruction compression on LLaMA-7B and FLAN-T5-XXL; up to 26× compression, 40% FLOPs reduction, only 4.2% wall-time improvement in the reported setting. | Strong reminder that compression ratios are not latency gains. Requires learned compression; no arbitrary insertion into untouched Qwen. |
| [ICAE, ICLR 2024](https://arxiv.org/html/2307.06945v3) | Trains a context encoder using LoRA and memory slots while retaining the LLM decoder, compressing context into soft memory. | A separate learned write/read interface, not an operand-free KV packet extracted by averaging. Good architectural precedent; no released 3.8 compressor or one-hour port verified. |
| [Prefix tuning](https://arxiv.org/abs/2101.00190), [prompt tuning at scale](https://arxiv.org/abs/2104.08691) | Frozen-backbone continuous conditioning can approach ordinary tuning on covered tasks; prompt tuning benefits from model scale. | Foundational rather than new 27B evidence. A few learned vectors per rule fit the ship form; training still backpropagates through the model. |

The most useful recent result is [Compositional Steering Tokens, ACL 2026](https://arxiv.org/html/2601.05062v2). It learns behavioral embeddings and a composition token on frozen 3B–14B models. On Qwen3-8B unseen two-behavior combinations, tokens score 76.9 versus natural-language instruction steering 71.8; unseen three-behavior combinations 59.5 versus 54.0. Response quality is LLM-judged **on constraint-successful responses**, not an unconditional executable-competence measurement. In Qwen3-14B four-behavior tests, pure tokens score 53.5 versus instructions 64.4; hybrid reaches 67.5. Training uses 50,000 examples per behavior, two epochs. This is evidence for learned compression/composition, not a one-hour recipe or a 27B result. [Released implementation](https://github.com/nec-research/SteeringTokens) supports the approach; I found no verified ready-made 3.8 rule tokens.

**Prospective carrier:** four learned embeddings per fixed rule, 4×5,120×2=40 KiB bf16 on 27B (20 KiB on 4B). Keep the trunk embedding matrix frozen by supplying separately stored input embeddings. No semantic natural-language instruction need remain. However, virtual tokens remain a conditioning channel and consume sequence positions. A repeated learned token is compressed rendering; a once-installed prefix with no HOLD refresh is a stronger retention test.

**Reversibility:** replace the active prefix, then rebuild downstream KV and recurrent state from the complete retained transcript. Deleting the prefix or swapping its initial KV alone leaves other state influenced by it. Adding a new prefix each turn while retaining old ones is not a clean swap. Prefix length savings must be compared against the actual tokenizer length of the concise rule; four virtual tokens can already be more expensive than a two-token language label. With cached text, theoretical saved tokens may yield almost no wall-time gain.

[When Do Prompting and Prefix-Tuning Work?, ICLR 2024](https://arxiv.org/abs/2310.19698) analyzes expressivity limits, including invariance of relative content attention within its modeled attention layer. This motivates caution about learning new computations from prefixes; it is not a theorem that deep models cannot select known skills, nor a theorem about the whole Qwen hybrid architecture.

**Expected bars/cost:** learned prefixes are a credible alternate carrier for a finite mode library, with modest expectation of improving code quality over text. Full steering-token/gist training is outside one hour; a 4B miniature proof is possible but may fail from insufficient training. Shipping is excellent if it works. Long-horizon persistence, new rule values, conflicts, and cheap safe switching remain unestablished.

The biologically motivated distinction remains useful for design; the analogy supplies no layer, feature, frequency, or dose for Qwen. The correct cost entry for a port of these architectures is **outside the ≤1 GPU-hour line**, even if running an already trained smaller model might be cheap. Do not substitute scratchpad text for a weight-side result or mistake successful long-context QA for continuing rule obedience.

**6. Negative evidence, and the strongest counterarguments to closing everything.**

The actionable negative evidence is not “steering never works.” It is that optimizing the control proxy often fails to preserve the task:

| Evidence | Decision consequence |
|---|---|
| ACL 2025 cross-model replication above: high variability, large hyperparameter-search gains, incomplete ICL recovery | Model size alone is insufficient reason to reopen extracted vectors. Count search and unsuccessful cells. |
| SAE coding study above: 4.04% corrections alongside 14.66% corruption | Run hidden executable tests on previously correct cases; a correctness feature's name or probe score is inadequate. |
| [DIRECTER, March 2026, Table 1](https://arxiv.org/html/2603.06745v1) | On its GSM8K-format test, baseline task accuracy is 82.7; PASTA gives 99.2 format accuracy but only 48.1 task accuracy. DIRECTER reaches 99.1/86.9 using instruction-aware attention control with dynamic rejection. A format win can conceal a catastrophic task loss. This positive alternative retains instruction information and adds decoding machinery; it is not text-free selection. |
| [ContextEcho, May 2026, Appendix L](https://arxiv.org/html/2605.24279v1) | Qwen3-32B assistant-axis projection improves with dose while visible persona scores do not track it (reported Δ=−.24, correlation −.80). This is a proxy/behavior dissociation, not a measured coding-pass degradation from steering. Do not cite its separate continuation panel as that experiment. |
| [Aligned open-ended generation, April 2026](https://arxiv.org/html/2604.08169v1) | Studies Llama-3.3-70B and Qwen3-32B. Distribution-aware variants preserve general capability measures better than fixed-coefficient steering; layer/dose choices still matter. Its capability suite is MMLU/MT-Bench/AlpacaEval, not executable lifecycle coding. |

Three positive refinements prevent a scientifically honest universal closure. [ReCoVeR, EMNLP 2025](https://arxiv.org/html/2509.14814v1) separates content from natural-language control: on Qwen2.5-7B MultiQ, ReCoVeR+ improves language adherence 90.7→93.2 and accuracy 61.8→66.5. It does not establish programming-language or long-session switching. [SKOP, May 2026](https://arxiv.org/html/2605.06342v1) projects query-steering directions away from utility-critical key differences, reporting 5–7× less utility degradation while retaining >95% steering efficacy on Llama-3.1-8B/Gemma-2-9B. Its default calibration uses 4,000 examples, and its long-context result is retrieval/formatting, not coding. Adapting the idea to 48 DeltaNet blocks is not automatic. [ROAST, February 2026](https://arxiv.org/html/2602.14143v1) uses on-distribution rollouts and continuous state steering on models up to 32B; reported gains include math/truthfulness, without our lifecycle certificate.

My inference is therefore **engineering closure for broad extracted-control searches, not a claim of impossibility**. Prompting exploits a trained interface that already binds content, authority, and current task; a low-dimensional edit may also perturb attention, length, or generation dynamics needed for execution. New geometry-aware or optimized methods can reduce that damage, but none of the inspected results warrants an unbounded search here. There is also no literature theorem that prompting always dominates at scale: the positive counterexamples above explicitly prevent that wording.

**Prewritten common contract for the ranked quick checks.**

These are proposed one-hour *maximum allocations*, not measured promises of completion. Author/check/freeze the CPU harness before any launch. No installs or launches occur in this task. A prospective run begins only when the existing runtime can execute it without a backend-development detour.

Use newly authored small programming tasks with branches, collection transformations, empty-input and type/boundary cases, and independent Python/Node executable checkers. Keep reference solutions within 96 tokens under the actual tokenizer; do not truncate a larger coding task into an expression-only screen. Reference implementations and deliberately wrong/stale mutants must validate the consumer. No LLM judge, syntax-only surrogate, or answer repair. Record syntax, language, semantic success, truncation, and required presentation separately.

Modes are A=Python and B=JavaScript. The task text specifies semantics and a neutral function identifier, without naming either language or using a language-specific scaffold. Generic fixed code-output instructions are shared across arms. In setup, explicitly cued unmodified A and B must each execute correctly on ≥7/8 tasks; the cue-free default must be Python on ≥7/8. Otherwise the declared pair is INELIGIBLE, with no fallback pair selected from outcomes. This avoids treating newly taught competence as demonstrated selection.

Each of 12 independent evaluation episodes has five decisions: SET, HOLD after one complete neutral exchange and intervening content, SWITCH, BACK, CLEAR. Counterbalance A→B→A and B→A→B. Each decision is new executable work; preserve every own answer, including failures, with proper role closures.
