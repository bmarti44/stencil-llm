**1. FIRST-SHIP v1 SCOPE — the cut list applied**

The public entry is `{action,key,scope,kind,value,target_version?}`, wrapped in authenticated source/event metadata. `kind` is language, style, format or process; `scope` contains declared task/artifact handles and applicable request kinds. Those identifiers are supplied by the caller. A normal tool continuation inherits its task handle and carries its actual request kind. This eliminates the proposed task-type head.

Use the existing register machinery, reduced to these operations:

- `add` creates a live version under a new key/scope. `supersedes` retires an exact live target and adds its replacement atomically. `cancels` and `completes` retain different retirement reasons. `reinstates` creates a new version referencing an identified retired version; it never mutates history back to live. Although fable proposed cutting inferred reinstatement, Brian explicitly requests these events: retain the small structured operation, not speculative natural-language undo resolution.
- Require `target_version` for every operation on an existing rule. Reject missing/ambiguous targets, stale versions, unsupported scope intersections and incompatible same-scope additions. Deduplicate by event ID. A malformed transaction changes nothing. A narrower declared exception shadows a broader rule only in that explicit scope; cancellation reveals the remaining applicable broader rule or configured default. Reject complicated overlapping scopes rather than invent generalized precedence.
- Preserve immutable source events, original values, version links, recorded order, source role/message/span, authority, scope, status and transition evidence. Derive a live-view bit mask over versions. Retirement changes eligibility; it never deletes source text, transcript messages, historical records or workspace history. **Register retirement masks and optional attention key masks are different mechanisms.** The default path performs only the former.

**Frozen classifier boundary.** Bundle the frozen relation classifier and its operating thresholds for semantic entry validation and supported free-text relations. Use relations v3 only after its separately registered GO; do not infer readiness from a DEV score or a queue entry. Typed schema, identity and version checks are deterministic. A classifier assesses semantic consistency/relations in full authenticated context; it is not replaced by regexes, keyword rules, substring matching or sentence heuristics. Equality of explicit IDs/enums is schema handling, not semantic string matching.

An unambiguous, valid structured action specifies its own operation. A contrary classifier prediction is journaled; it cannot silently reinterpret `cancels` as `supersedes`. If semantic interpretation is needed and the classifier abstains, the transaction is left pending with no mutation. Until a relation candidate passes its GO, learned judgments are assistive only and all authoritative transitions require the complete structured action. This restricted explicit mode remains usable and testable; it earns no automatic-relation claim. After GO, freeze the supported learned path and its coverage before evaluating it. No threshold rescue on the larger bank.

Automatic admission, including queued **44c**, remains a proposal UI: source spans and suggested entries may be shown, but proposals do not enter the register without explicit adoption until the independent admission GO passes. An admission-negative user cancellation can still be a relation candidate; do not require a sentence that retires a rule to be classified as a new standing rule. Tool output, quoted code and assistant prose cannot acquire user authority. A later GO licenses only its registered coverage, not an automatic runtime swap halfway through this test.

**Every-request renderer.** At each user request and each tool continuation, render every applicable live obligation, including language and active defaults, from the validated register. Match format/process obligations to the request form: a final-answer JSON schema does not govern a tool-call envelope; a system code-block default applies to code answers unless legitimately overridden. System authority remains above user rules. Give global rules, task rules and request-local exceptions explicit provenance. Use declared request/task handles for matching, borrowing NLSI's separation between stored and applicable instructions; do not train a new scope head this week. Unknown bindings return an explicit unsupported/clarification status, not a guessed omission of a mandatory rule.

Use one production render layout, frozen on DEV: the current request's existing prepend placement, with a compact ordered live block, then a separately labeled retired block, then the request. Do not alternate JSON and literal cues by arm. 40j tested a literal cue, whereas the earlier production renderer used a JSON wrapper; the package's exact rendered bytes must therefore be exercised in the DEV pilot and larger test. No separate wrapper-comparison screen.

**Tombstone hypothesis, not established benefit:** for the first three generation requests after retirement, render `Retired: indent v2; no longer binding in task A; replaced by indent v3.` Include cancellation/completion reasons and the current replacement/default, never issue the retired value as an imperative. Use all applicable retirements in that fixed window, with no salience ranking. Once a version is reinstated as a new live version, make that distinction explicit. Historical tombstones remain in the transcript; expiry only stops their fresh rendering. The three-request window is an engineering choice to freeze, not a literature-derived optimum. [ReBIND](https://arxiv.org/html/2608.12599) motivates testing revocation notes and measuring relapse, but its reported improvements do not establish transfer to this trunk. The main comparison tests the whole renderer including tombstones; it cannot isolate their incremental contribution. Do not add an ablation this week merely to fill that gap.

**One-generate loop and journal.** Authenticate entry → validate/classify → atomically update the live view → resolve request applicability → render → install any explicitly enabled experimental mask/hook → call the trunk decoder once → restore hooks in `finally` → return literal output and session state. Small CPU classifiers are not additional trunk generations. Tools execute in the caller; their results trigger another request. Invalid/truncated calls remain recorded failures, without a silent second generation, answer selection or correctness retry. Ordinary later repair attempts consume normal scheduled rounds. Restore hooks on every exit path.

Write the same-run journal before aggregates: raw and rendered messages/token IDs; source events and classifier inputs/scores/abstentions; before/after versions and live masks; defaults and applicability; actual outputs/EOS/truncation; attempted and executed tool calls, results and artifact hashes; timestamps, per-call CPU/GPU-held time and token counts; optional bias hash, whole-body intervals, keep mask and absolute positions; failures and fallback reasons. Evaluation records additionally carry the hidden oracle/checker results, inaccessible to the model. Dry-assert the complete field list through the real writer/executor path before sealing. No later reconstruction of missing per-turn provenance.

**One HF repository download.** Put the unchanged trunk shards, tokenizer/config, classifier weights and tokenizer assets, controller/register/renderer/journal modules, frozen experimental JS tensor, manifests, and `custom_generate/generate.py` in the same model repository. Pin runtime requirements in `custom_generate/requirements.txt` and document session arguments/returns. The HF custom-generation interface is reusable; a second remote weight repository, local project checkout or separately fetched classifier is not the shipping contract. Standard pinned runtime dependencies remain an installation prerequisite. Validate local asset hashes and demonstrate local-only loading after the single snapshot download. This is the thin ship form Brian requested, not a serving-framework project. [HF custom generation documentation](https://huggingface.co/docs/transformers/en/generation_strategies).

**Experimental flag:** `actuator=off` by default; retain explicit `mask_only` and `js_bias_mask` research settings. The only existing bias/release certificate is Qwen3-30B-A3B, alpha3 JS, the **40c open-form arithmetic request**, short bodies, and the measured 40i Z schedule. It is an exploratory operating envelope, not a general production certificate. Store its exact template ID, model/router/backend hashes, tensor hash, dose and body-length/transition envelope in one manifest. No profile library. Request-form eligibility is checked from declared template metadata, never inferred by a string matcher. Uncertified natural edits/tool requests keep bias OFF; language='JS' alone cannot enable it.

Keep 40i's persistent whole-assistant-code-body key mask: include the body's fences and failed code, preserve user/tool turns, headers, EOS/closures and absolute positions. Accumulate masks at validated retirement/epoch boundaries; reinstatement does not unmask old bodies. Do not mask tool observations or free prose. Do not split mixed tool-call JSON into supposedly fact-free subspans: unsupported body types remain visible and the transition falls back to rendering. Preserve artifact handles and exact tool-confirmed facts outside assistant bodies. A declared need for an old body disables that transition's actuator; there is no learned fact-preservation policy. Re-reading a file has real cost and the mask does not erase information already mixed into surviving KV.

Adapt HF's `create_masks_for_generate` with causal-AND-keep semantics on the pinned version, retaining the verified 40i 2D path until consumer parity holds. Check prefill and one-token decode, forbidden-key mass, past+current lengths and monotonically increasing absolute positions; do not derive positions from the visible-key count. This is an interface adaptation, not automatic semantic parity. [HF mask documentation](https://huggingface.co/docs/transformers/en/attention_interface).

**Cut from this week:** task-type head; skill discovery/clustering; multi-family library/dose searches; dense-neuron/concept rescue; prefix-cache sharing, cross-session sharing and replay/fork infrastructure; new serving backend or FlexAttention optimization; automatic fact extraction; fact-preserving partial masks; extra model judges, planners or admission trunk calls. Keep normal per-session retained history/KV and append-only journal storage. No new benchmark framework dependency unless the current small tool loop demonstrably cannot host the bank.

**2. THE LARGER TEST — conditional registration, rendering-only primary**

The question is now: **does the shipped explicit-entry/classifier-assisted register plus correct request-time rendering improve executable continuation over ordinary retained history under competing live rules?** R–N is the single primary contrast. R–T is descriptive. O–R measures perception/validation/state binding under the frozen input mode, not actuator benefit. The design review's proposed actuator-primary ordering is superseded by 40j and Brian's v2/addendum instructions.

**Generator design: Stencil Lifecycle-API Bank (SLAB-1).** Independently implement a seedable, small evolving entity/validation API specification generator. Reuse StaminaBench's procedural spec → change → executable-checker pattern, with our own schemas, scaffolds, wording, seeds and lifecycle operations. Use tiny in-process Python/Node modules and native tests, not 64 hand-authored repositories or a Docker/HTTP service stack. Each episode has two task/artifact handles and a 2–3-file workspace. The generator emits an immutable initial specification, public requests, structured source entries, oracle lifecycle events and executable hidden checkers. This is our new distribution, not a StaminaBench score or copied benchmark task. [StaminaBench generator design](https://arxiv.org/html/2606.19613v1).

Generate **64 independent seeds** from a frozen grammar/distribution, with independent identifiers, schema graphs, validation cases and lifecycle schedules. Common grammar limits external generalization; renaming the same fixed problem 64 times is insufficient. Keep DEV and evaluation scenario families and wording productions separate; reserve evaluation seeds/content before model feedback. Freeze the generator first; CPU validity checks may reject an unsatisfiable specification by a prewritten rule, never by a model outcome. Save every rejection and replacement seed before launch. Reference implementations must pass every stage, while deliberately stale/wrong-scope mutants fail the intended checkers. Hidden test bodies/answers never enter tool feedback, prompts or classifier training.

Each episode has **20 generation rounds**. The first ten are real scaffold-extension/code-edit work intended to elicit ten retained own bodies of **100–300 tokens** while 3–5 rules are active. The next ten contain the lifecycle challenges and actual read/edit/test continuations. At the first revocation there should be ten prior substantial own turns; later probes can have up to nineteen prior own turns. These are intended/observed pressure levels, not padded or regenerated outputs. Use scaffolded edits to keep bodies near the lower end without a 100-token generation minimum. Record short bodies, failures and total own-output tokens; do not fabricate histories to qualify pressure.

Include at least one rule of each of language, style, format and process, with 3–5 concurrently applicable obligations at the challenge boundaries, including defaults. Examples are a declared implementation language; indentation or semicolon style in emitted code; a code-fence/final-report schema; and a test-before-final receipt requirement or allowed artifact scope. Supersede a stylistic rule after the ten-turn history; cancel a distinct rule so its declared default applies; complete a task-local obligation; switch tasks and return; explicitly reinstate a retired rule as a new version. Schedule events at fixed request boundaries independent of arm success. Not every change requires a whole-file rewrite. Spread events across the ten challenge rounds with intervening tool opportunities; freeze per-round request-kind and gold-applicability tables. Misleading quoted/tool instructions are payload negatives. The renderer still runs on every continuation, so delay since the original rule event is not delay since its last rendering.

**Endpoints and exact power.** The statistical unit is the independent episode, not its turns or rules. Primary final success requires hidden cumulative integration tests, all applicable live obligations on final artifacts/reply, and satisfaction of still-binding process receipts. A repaired historical violation can coexist with final success; the separate trajectory endpoints prevent concealing it.

For every generation and actual execution, score applicable rules against the frozen oracle, including system defaults. Record language, style, format and process independently, with an explicit applicable/not-applicable denominator. Each kind gets both (a) violating turns / applicable turns and (b) violated rule-turns / applicable rule-turns, plus episode-level any-violation counts. Report against turn index, turns since lifecycle change, prior substantial-body count, and cumulative own-output tokens. Confidence intervals/resampling for these descriptive rates cluster by episode.

**Relapse = stale execution after a revoked rule:** an actual edit/tool action or delivered artifact/reply implements the retired version on a prewritten discriminating witness where the effective replacement/default requires a different behavior. Mere continued compatibility with an old rule is not evidence of relapse; cancellation without a discriminating replacement/default cannot identify it. Once a rule is legitimately reinstated, following the new version is not relapse. Score attempted stale tool calls separately from actually executed stale actions, and report whether the obsolete trait appeared in prior own bodies. Do not claim own-output causality from the R trajectory alone. Include stale style edits, not just stale language, and retain failures even when later repaired.

Breakage is any episode with a malformed tool call, invalid required complete program, empty/repetitive/truncated reply, resource failure or unintended workspace damage. Keep language mismatch, style/format/default violations, semantic test failures, fact loss and process violations separately as well. A bare function can be executable-correct and format-noncompliant. The **only breakage acceptance clause is paired: `B_R - B_N <= 1 episode`**; equivalently, R-only broken minus N-only broken is at most one. No absolute `B_R<=2/64` bar. Report wins/losses/ties and uncertainty; this practical tolerance is not a noninferiority proof. Optional actuation uses the same clause against O_off, never against a classifier-divergent R.

Test R>N on final success with one-sided exact McNemar/sign-on-discordants at **alpha=.05**, once, after complete accounting. No co-primary actuator test or split alpha. Let w = R-only success, l = N-only success; `p = sum(comb(w+l,j), j=w..w+l)/2**(w+l)`, with p=1 when w+l=0. Require observed gain at least **8/64 = 12.5 percentage points** as the separate practical bar. Report paired gain and a conservative 95% interval from Bonferroni 97.5% Clopper–Pearson win/loss marginal intervals. T/O and rule-kind endpoints remain descriptive, with no uncorrected significance claims.

Power recomputed by exact finite enumeration, not Monte Carlo. For each `m=0..64`, weight `Bin(64,p10+p01)`; enumerate `w=0..m` under `Bin(m,p10/(p10+p01))`; sum probabilities for which the null binomial tail is <=.05. For the practical column also require `2w-m>=8`.

**3. RELAPSE PRESSURE — go directly into the agentic test**

The addendum overrides the earlier 20-minute arithmetic-screen proposal. 40j had no language relapse, but it did have style imitation. Increasing arithmetic samples would keep testing the saturated categorical axis. Put explicit style reversals, rule load and long retained own bodies in SLAB-1's DEV pilot and final trajectories. Distance since initial instruction is a covariate; every-request rendering deliberately keeps the live-rule reminder current. Do not disable rendering or withhold a rule to manufacture an actuator win.

Use a **prewritten DEV-only contingent trigger**: after the four full pilot episodes, R must show relapse on at least **15% of applicable post-retirement turns for some rule kind**, with at least **20 applicable opportunities across those episodes** and relapse in at least **two different episodes**. Count a turn once per kind. Require the same obsolete trait to be observable in that episode's prior own code bodies. Additionally require O to show the same kind of relapse in at least two pilot episodes with correct register/render state; otherwise first suspect perception/state binding, which masking cannot fix. Log all four kinds and denominators, including zeros. This floor authorizes only spending on a contingent mechanism screen; it is neither a significance test nor evidence of mask benefit.

If the floor is not met, leave the flag OFF and cut all optional GPU work. If it is met, the **only extra screen this week** is a maximum **20-minute DEV agentic O_off/O_on comparison**, charged inside the six-hour cap, on independently authored reserve DEV episodes fixed before the pilot. Use the same gold schedule and exact renderer in both, with naturally divergent own histories; compare the **mask_only** setting first. No new JS bias on tool forms. Retain complete per-turn records and all costs of file re-reads. Keep a whole-body fact-survival witness and code-block-default checker. Fewer completed cases means an incomplete screen, not selected successful pairs. Cut the screen altogether if its measured projection would displace the 64-pair primary.

This optional comparison cleanly identifies the selected mask policy's total effect, including downstream tool/trajectory costs, because perception/events are held to the same oracle. It is not a claim of single-token direct effect. A future `js_bias_mask` comparison would identify the combined actuator, not either half; it would additionally need independent certification of the actual request forms. Existing certification cannot be stretched to style or long tool-call bodies. This week the mask extension is diagnostic-only, even if encouraging; no default enablement on a handful of DEV outcomes. A convincing reduction with intact defaults, facts and executable work can justify a separately registered test later.

The first final-bank outcome is never used to choose, fit, tune, or activate an arm on that bank. If relapse first appears in final R/O, report it and queue a fresh successor hypothesis; do not replay the failing final episodes as mask development data.
