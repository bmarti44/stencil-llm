## The benchmark (v2)

**Task D: compositional instruction state under dynamic updates.** The fix for "latch-shaped" (sol #1): task state is no longer one cue but **four independent instruction slots**.

- **State**: 4 slots, each holding one of k=8 rules (existing Latin-square tables, `seed_rules=0`, rules shared across slots).
- **Tokens (role-separated; sol r2 #12)**: UPDATE slot markers are cue-range tokens 29..32; QUERY slot markers are DISTINCT tokens 60..63 (reserved from the distractor-range top). An update is `[USLOT_d][CUE_r]`; a query is `[QRY][QSLOT_d][x]`. B3/B4/latch semantics trigger on cue-range tokens only, so queries never perturb latches or retention sets.
- **Layout**: initial block sets all 4 slots (4 updates in slot order); thereafter updates arrive intermittently (each changes exactly one slot — the "changes" half of Brian's spec), interleaved with distractor spans and queries. Sequence length 4096, window 64 (receptive field 252 — old content genuinely unreachable; compaction analog, scoped honestly per sol #10 as "local-attention persistence," not summary-compaction).
- **Why this discriminates**: the sufficient statistic is a 4-rule register. The single-slot latch (B3 as built) is *provably* insufficient — any update to another slot clobbers it. Retained attention (B4) must search a growing pile of stale slot-updates. Reinsertion must re-inject all 4 active rules, paying cost proportional to state size. The oscillator's 128-dim state has room for compositional superposition — this is the first task in the project where its capacity class could actually matter. (If it still loses, that is a clean, meaningful negative.)
- **Answer-leakage kill (sol #2)**: gold answers NEVER appear in the input stream. The input at each answer position is a fixed placeholder token (PAD, 0); training loss and eval compare `logits[p]` (at the operand position) against a **separate target array** carried in metadata — not `tokens[p+1]`. No later query can recover a rule from an earlier answer. This is a registered, tested departure from the Task A/B alignment contract, applied to task "d" only.
- **Fixed shapes (sol #9)**: exactly Q=16 queries per sequence at stream-scheduled positions and a family-fixed update count — every sequence has identical decision counts and tensor shapes (batching + CUDA graphs unchanged, no ragged machinery).

**Schedule families (sol #7 — exact, sealed).** All draws from the existing named streams; every family a pure function of config; config hash recorded per run.
- Generation law, fully frozen and arithmetic-checked (v5; sol r4 #7/#9/#13). **ONE COMMON LATENT CORE for every contender**: length `L_core = 3848`. The schedule (updates, queries, distractors) is generated ONCE per (family, offset, sequence index) on the core; every contender receives the identical core. Policy-specific expansion to exactly 4096 final tokens: reinsert-128 inserts exactly 31 refresh blocks of 8 tokens (248 = the full reserve, zero filler): one before the token that would occupy each final-coordinate multiple of 128 from 128 through 3968 inclusive (31 multiples; exact-position test required); prequery inserts 16 × 8 (128) + 120 trailing neutral distractors; all other contenders append 248 trailing neutral distractors. Fixed shapes: final length always 4096; decisions always Q=16; **update count is FIXED AT 12 FOR ALL TRAINING AND ALL FAMILIES' training draws — the curriculum varies ONLY gap bounds (steps 0-8k: U{32..128}; linear integer interpolation of both bounds per step, floor-rounded, to U{64..320} by step 12k) so cue-position tensor shapes never change (sol r4 #9)**; eval families: train 12, drought 3, burst 8 updates. Registered event-tensor contract: cue-event tensors have FIXED width 16 events = 32 token positions (12 max updates + 4 initial), padded with a validity mask in all cases (an event is a [USLOT][CUE] pair = 2 retained token positions; sol r5 #9); reinsertion contenders are b0_local-class (no cue-consuming module — no event tensors), so per-config shapes are constant everywhere the CUDA graph or B4/latch consumers touch. Query events are FOUR-token blocks `[QRY][QSLOT][x][PAD]` (the placeholder is part of the block; collision exclusion covers all 4 tokens; sol r4 #7). Gap-vector rejection: if cumulative updates + 16×4 query tokens exceed L_core − 64, redraw the entire gap vector; maximum 64 redraws, then a REGISTERED FALLBACK: scale only the final gap down to fit (deterministic; occurrence counted and reported; with the verified bounds the expected redraw rate is <1%, fallback rate ~0). Draw order per core sequence: (1) initial block: 4 rules from `cues` (U{1..8}), slots 1..4 in order; (2) update gap vector from `delays`; (3) update target slots from `cues` (U{1..4}); (4) update rules from `cues` (U{1..8}) — a rule draw equal to the slot's current rule is a LEGAL no-op whose staleness clock resets; (5) query start positions: 16 sequential draws, valid-start set recomputed before each to exclude any position whose 4-token block overlaps an update pair or a placed query block or comes within 2 tokens of either, draw = index into the current set from `operands`; (6) query slots from `cues`; (7) operands from `operands`; (8) distractors elsewhere. Active rule at a query = most recent update to that slot strictly before its QRY position (core coordinates); the generator asserts no update inside any query block. ALL distances and schedule ids live in core coordinates.
- Family gap parameters (restored v7.1 — these bounds were registered in v4, arithmetic-verified by sol r5, and lost in a v5 splice; editorial restoration, no new content): `train` gaps U{64..320}; `drought` gaps U{768..1280}; `burst` start offset U{64..512}, intra-cluster gaps U{8..32}, inter-cluster gaps U{640..1200}, clusters sized exactly (3,3,2).
- `id-control`: the `train` family drawn at eval offsets.
- **Sealing**: two eval offsets. `validation` (eval_seed_offset) may be consulted for adequacy/retry decisions during the campaign. `final` (eval_seed_offset × 2 + 1, disjoint by construction) is evaluated exactly once per run, after every training decision for the whole fleet is frozen; verdicts use `final` only.

**Contenders (8 × 3 seeds = 24 runs):** m1, m1b, b2 (non-oscillatory recurrent control), **b3k — the matched 4-slot keyed latch (sol r2 #1): four 32-dim registers within the same 128-dim state budget; an update `[USLOT_d][CUE_r]` overwrites only slot d's register; same RMS-gate readout — the exact non-oscillatory solution to the task; an oscillator win counts only if it beats this**, b3 (single latch — DESCRIPTIVE ONLY, never verdict-bearing: it is intentionally under-capacity for 4 slots and exempt from adequacy; sol r4 #4), b4 (retained instruction tokens), reinsert-128 (all four active rules re-injected every 128 tokens; strong periodic incumbent), reinsert-prequery (active rules injected immediately before each query; ALSO a real incumbent and INSIDE the verdict — sol r2 #3 — reported with its token overhead). Reinsertion is a generator-level data policy on b0_local.

**Training**: 30k steps, batch 64, registered optimizer block, deterministic curriculum on GAP BOUNDS ONLY, update count fixed at 12 throughout (steps 0–8k: gaps U{32..128}; both bounds interpolate linearly per step, floor-rounded, reaching U{64..320} at 12k; boundaries from config). **Adequacy (decoupled from the estimand)**: ≥95% on `id-control` VALIDATION. ALL initial seeds enter primary results; adequacy is its own adoption-reliability column; one 45k-step retry allowed, reported separately, never replacing; an adoption failure of the sealed primary oscillatory variant forbids verdict V1.

**Metrics (frozen; sol r1 #8 + r2 #8/#13):** the DECISION AXIS for every cross-contender comparison is **distance since the queried slot's last TRUE update** (reinsertion-invariant, shared support for all contenders; sol r2 #13); contender-specific information age (counting reinserted copies) is reported descriptively only. Canonical shared bins on the decision axis: [0,64],(64,128],(128,252],(252,512],(512,1024],(1024,2048],(2048,∞); a bin enters comparisons only if EVERY compared contender has ≥200 samples in it (shared-support rule; bins failing it are reported NA with counts; no data-dependent merging — sol r2 #8). Per family × contender on 10k sealed sequences: (a) sequence-weighted exact-match; (b) accuracy by decision-axis bin (numerators/denominators recorded); (c) accuracy vs GLOBAL update count absorbed (registered meaning); (d) first-crossing survival (largest D with all bins ≤D at ≥90%); (e) stale-slot preference excess, error-conditioned (sol r4 #8): observed = (# wrong answers matching a superseded rule's output for the queried slot) / (# wrong answers); null = mean over WRONG-ANSWER queries of |{rule_r(x): r superseded on that slot, rule_r(x) ≠ rule_active(x)}| / 15; excess = observed − null (reported NA when a cell has no wrong answers, with the count; measures stale-rule preference, not overall accuracy; registered here, hand-tested); survival rule with NA bins: first-crossing D is the largest distance such that every bin ≤D is non-NA AND ≥90% — an NA bin caps D at the last non-NA bin below it (sol r3 #8); (f) cost axis: injected-token overhead per contender (zero for stateful paths) + train/eval wall clock. Paired comparisons key on the reinsertion-invariant schedule id = (family, eval offset, sequence index).

**Decision procedure (v4 — disjoint by construction; sol r3 #4/#5):**
- **Aggregation, frozen**: for contender c and each (family, shared bin), acc(c) = mean over the 3 training seeds of the sequence-weighted accuracy, paired across contenders by latent schedule id. Δ(S) = acc(OSC) − acc(S) on that (family, bin). "Overall" = the family-level sequence-weighted figure, same seed-mean rule.
- **Primary oscillatory variant (OSC)**: the one of {m1, m1b} with higher id-control VALIDATION accuracy; exact tie → m1 (registered tie-break; sol r4 #6); sealed before any final eval; the other is descriptive.
- **Verdict-bearing contenders**: OSC, b3k, b4, b2, reinsert-128, reinsert-prequery. (b3 and the non-primary oscillator are descriptive.) **Adequacy** (adoption, not capability): all 3 seeds ≥95% on id-control validation, applied to every verdict-bearing contender. Any OSC seed failure → V1 impossible. Any verdict-bearing RIVAL failure → V1 impossible AND that rival stricken as V2 evidence; V2 may fire from remaining adequate rivals; else MIXED with the adoption-reliability table as headline.
- Tail = shared-support bins strictly >512 (latent axis) on drought and burst. Cost scope, registered: the verdict's cost axis is INJECTED-TOKEN OVERHEAD ONLY; controller compute/memory are reported in the cost table but do not enter the verdict (a registered limitation of this benchmark).
- **V1 — SUBSTRATE BENEFIT**: all contenders adequate; OSC id-control ≥95%; for every reinsertion policy R: rival_margin(R) = acc(R) − acc(OSC) < 1.0 at every material (family, bin) [material = tail bins and family overalls on drought/burst]; for every stateful rival S: Δ(S) ≥ 1.0 on at least one tail (family, bin) AND rival_margin(S) < 1.0 at every other material point; AND the seed-robust tail floor: define tail(c, family, seed) = the sequence-weighted accuracy pooled over that family's shared-support bins strictly >512 (one number per family per seed); V1 requires the OSC seed-MEAN of tail(·) ≥50% on EACH of drought and burst, AND tail(OSC, family, seed) ≥40% for EVERY seed on EACH of drought and burst (per-seed, per-family floor — a single catastrophic seed defeats V1).
- **V2 — NO SUBSTRATE BENEFIT**: some ADEQUATE verdict-bearing rival has rival_margin ≥ 1.0 at any material point, OR there EXISTS one adequate zero-token stateful rival (b3k, b4, or b2) with |Δ| < 1.0 at ALL material points (per-rival parity — one exact simpler register matching OSC everywhere suffices; sol r4 #5). Reinsertion-policy parity does NOT trigger V2 (OSC avoids their token overhead — compatible with V1).
- **V3 — MIXED**: anything else.
Disjointness: V1 requires all rival_margins < 1.0 (negating V2's first clause) and some Δ ≥ 1.0 at a tail point (negating V2's parity clause at that point). Exact-boundary values (margin = 1.0) belong to V2 by the ≥/<  assignments above.
