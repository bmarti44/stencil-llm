## Findings

1. **High — `determinism.py` does not guarantee the registered `CUBLAS_WORKSPACE_CONFIG=:4096:8` (concur sol#1, independently re-verified).** `src/stencil/determinism.py:7` uses `os.environ.setdefault`, so any ambient value (e.g. the also-deterministic `:16:8`) survives and the registered value is never in force. Section 3 registers the exact string as part of the contract: "`torch.use_deterministic_algorithms(True)` and `CUBLAS_WORKSPACE_CONFIG=:4096:8` set in a shared determinism.py imported by every entrypoint". The effective value is absent from the run-identity preimage (`src/stencil/config.py` `run_id`, four-term formula) and from `env.json` (`src/stencil/train.py:171-192` records git/diff/untracked/dirty/torch/gpu/driver only), so two environments can run under different cuBLAS modes with identical run ids and no audit trail. Severity rationale: on the registered CPU-only gate this does not produce observed nondeterminism (both common values are deterministic), but this is a fidelity hole in the single artifact this phase exists to prove — the fix is one line plus an `env.json` field. Related latent edge sol did not note: `tests/test_config.py` imports `torch` at module top before any `stencil` import, so in whole-suite collection orders that import test_config first, torch loads before `determinism.py` executes; harmless for `use_deterministic_algorithms` (a runtime flag) and moot on CPU, but the entrypoint-first-import discipline should be stated in the fix.

Metrics are never appended across invocations."). `Makefile:6-13` runs only the three named tests plus ruff. No test invokes `config_hash` (`src/stencil/config.py:72-74`), `git_identity`/`run_id` (`src/stencil/config.py:167-210`), or `run`/`_prepare_run_dir` (`src/stencil/train.py:124-168`) — the dirty refusal, `--allow-dirty` stamping, same-git-state `--force` replacement, different-state refusal, and the artifact trio (`config.json`, `env.json`, `metrics.jsonl`) can all break or be deleted with a green gate. `tests/test_config.py:23-30` hashes a two-key dict literal and never exercises the delivered config-dict path. 5. **Low — the determinism gate has no non-vacuity anchor (new; sol missed).** `tests/test_determinism.py:10-18` and its duplicate in `scripts/verify_determinism.py` assert only that two 200-step loss sequences are identical. A future regression in which the optimizer silently no-ops (e.g. param groups wired to detached tensors, lr forced to zero) would still pass: losses vary step-to-step because the data stream advances, and both runs would remain bitwise identical. The registered test spec does not require more, so this is not an implementation deviation — but rubric item 1 asks whether a gate test can pass vacuously, and this one can with respect to its own subject ("training ran"). One-line hardening: assert the model's parameters differ from their seeded init after training, or `losses[0] != losses[-1]`.

6. **Low — `git_identity` has a crash edge and deviates from the registered diff command's literal form (new; sol missed).** (a) `src/stencil/config.py` `git_identity` frames untracked files with `(root / path).read_bytes()`, which follows symlinks; a dangling untracked symlink raises `FileNotFoundError` uncaught and crashes any run/force flow. Edge-case, but the fix (lstat and frame symlink targets, as `tools/amend.sh:23-54` already does) is small. (b) The diff is gathered with `git diff HEAD --no-ext-diff --binary` while Section 3 registers `sha256(git diff HEAD)`; the added flags are defensible hardening but are an unregistered deviation, and they are inconsistent with the byte framing amend.sh already converged on (`--binary --full-index --no-textconv --no-ext-diff`). Materiality is genuinely low — clean trees (the only gate-eligible runs) produce an empty diff, and env.json records the exact inner hash — so this is an alignment item, not an integrity hole.

7. **Low — residual schedule-formula choices exercised but not ledgered; cosine branch unreachable under the gate config (new; sol missed).** The warmup form `config.lr * (step + 1) / config.warmup` and the cosine denominator `max(1, steps - warmup)` (`src/stencil/train.py` `_learning_rate`) are choices the PLAN leaves open.
