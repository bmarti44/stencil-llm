## Findings

1. **High — The “closed-form” oracle is another 1,000-step recurrence.** PLAN requires the exact discrete matrix-power solution plus the forced particular solution as the fp64 oracle (`PLAN.md:357`; `tools/codex-agents/phase2-models.md:17`). Instead, `_closed_form` loops `steps` times over `state = matrix @ state + drive` and accumulates the resulting trajectory (`tests/test_models.py:62-83`), mirroring the production cell's step loop (`src/stencil/model.py:113-125`). The 12-case count and tolerances are correct, but the gate never exercises the analytically closed form it claims to exercise; shared recurrence/indexing or long-horizon accumulation defects can therefore survive the proof that was registered to avoid them.

2. **High — The JAX fixture generator never executes the pinned LinOSS implementations.** The script clones and verifies both registered commits (`scripts/gen_jax_fixtures.py:74-87`, `scripts/gen_jax_fixtures.py:148-152`) but neither checkout path is passed to the worker or read afterward. The worker defines its own local `cell` recurrence and runs that with `jax.lax.scan` (`scripts/gen_jax_fixtures.py:32-70`); `test_cell_matches_jax_fixtures` then trusts the archive's parameters and commit-label strings rather than reconstructing their provenance (`tests/test_models.py:268-315`). Thus the claimed agreement with “official JAX implementations” in PLAN and the ledger is false (`PLAN.md:361`, `PLAN.md:536`; `plan/LEDGER.md:17`). The archive currently matches the registered Torch streams, but that read-only audit is not enforced by G2 and cannot turn a hand-written JAX port into the required external oracle.

3. **High — The first binary gate artifact violates the registered cross-model presentation contract.** `tests/fixtures/jax_cells.npz` is now PRESENT and registered as a required artifact (`plan/reviews/phase2/artifacts.txt:2`), which triggers PROTOCOL's binding requirement for a prose description sufficient for kimi content review; hash and size alone are explicitly insufficient (`plan/PROTOCOL.md:19`). The context builder emits only path, byte count, and truncated hash, then declares every npz unrepresentable and “reviewed by sol only” (`tools/run_kimi_review.py:82-100`). There is no description field or sidecar in the manifest. Because the kimi companion is mandatory before the gate commit (`plan/PROTOCOL.md:20`), Phase 2 cannot be honestly accepted through the registered review path until this first-binary-row obligation is implemented.

4. **Medium — The load-bearing Jacobian test samples the training stream, not the registered eval stream.** Test 7 requires the first three eval-stream sequences for each seed/cell (`PLAN.md:364`). `_task_a_config` leaves `seed_data` equal to the experiment seed (`tests/test_models.py:318-327`), and `generate` initializes its streams directly from that value (`src/stencil/data.py:159-177`); the configured `eval_seed_offset = 1_000_000` is never applied (`src/stencil/config.py:55-56`). The test's own docstring calls these “eval-stream” examples while executing training-stream draws (`tests/test_models.py:370-390`). Exact unreachability is structural, but the registered nonzero recurrent Jacobian is input-dependent, so substituting examples weakens the exact fixture/seed contract of the load-bearing proof.

5. **Medium — The governed component map points to Phase 2 files that do not exist.** README says the wire lives in `src/stencil/oscillator.py` and `src/stencil/gates.py`, and repeats `oscillator.py` for the dissipation variants (`README.md:31`, `README.md:39`); PLAN's repository map names the same split (`PLAN.md:148-150`).
