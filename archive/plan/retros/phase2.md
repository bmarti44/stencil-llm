# Retrospective — Phase 2 (models and plumbing proofs), 2026-08-23

Scope: Phase 2 launch through gate(G2) commit `fda006f`, plus the v1.26/v1.27 amendment cycles it triggered. Four coder runs (models, fixes, fixes2, fixes3), 3 sol + 2 kimi phase-review rounds, amendment rounds 30-36, one human adjudication (5). Metrics from `tools/agent_metrics.py`.

## What went well — with evidence

1. **The coder refused to fake a green gate.** Faced with three unpassable registered constants, the phase2-models coder implemented everything, reported G2 red with measurements, and explicitly declined to weaken tests or smuggle normalizations. That report was accurate on all three counts (orchestrator independently reproduced each) and triggered the correct constitutional path: diagnosis → amendment → adversarial review → human ruling on the freeze question (Adjudication 5) → repair with registered precedent. The system's honesty machinery worked under its first real pressure.
2. **The oracle-fraud catch.** Both reviewers independently discovered the JAX "upstream oracle" never executed upstream code — including catching the ORCHESTRATOR'S false ledger claim of a "fourth independent implementation agreement." Two further rounds caught the fix being a dressed-up adapter. Final state: fixtures generated by the genuine pinned pipelines, adapter deleted, consumer test reconstructs all inputs from registered streams, sidecar records hash-verified provenance. Cross-model review caught a self-confirming test that a green gate could never have caught.
3. **Human adjudication stayed rare and narrow.** One ruling in the whole phase, at exactly the registered touchpoint (a gate no code fix could green), producing a narrow registered precedent rather than a blanket exception. The reviewer that blocked the amendment was commended on the record — enforcement against the orchestrator is working as designed.
4. **The devil's-advocate review became registered science.** The human-commissioned usefulness review (results/devils-advocate.md) produced the B3/B4 comparators, the H5 withdrawal contract, and five Appendix F rows — v1.27, landed through six review rounds that repeatedly caught real completeness gaps (dependent enums, run totals, Phase 5 wiring, README map).

## What went poorly — with evidence

1. **The orchestrator shipped a false claim into the ledger** ("upstream JAX agreed") by trusting a green test without reading the generator it certified. Caught by both reviewers, confessed, corrected. Lesson: a test passing is not evidence of WHAT it tested — read the certifying code path before recording a provenance claim (the consumer-semantics lesson, violated in a new costume).
2. **Registered constants were wrong three times over** (fp32 atol, H-trend bound, gate saturation) — all derivable at registration time. The plan-phase lesson "numbers in specs are claims: recompute them" was applied to arithmetic but not to numerics feasibility. Escaped defects: 3, all from the plan phase's registration of Phase 2 constants.
3. **Fix-pass thrash on the oracle** (three coder passes to land one honest fixture generator): rounds 1-2 each closed most findings while introducing a narrower version of the same defect. Cost: ~2 extra hours. The brief for pass 2 said "execute the pinned checkouts" without defining what counts as execution; pass 3's brief specified the exact entry points and the prohibition on adapters, and landed clean. Lesson: when a fix targets a deception-shaped defect, the brief must define the fixed state extensionally (which functions run on which inputs), not intentionally.
4. **Lesson recurrence: 2** — lens rationale omitted again (now mechanized, LENS_RATIONALE); the amend.sh next-command parse format bit the orchestrator once more (round 36 #27's cold-start regression from the round-35 format fix; the class where hand-written ledger entries meet mechanical parsers keeps paying out — the auto-write-ahead closed half of it, the STATE templates remain manual).
